В iOS перед использованием режима «Картинка в картинке» объявите фоновое воспроизведение; macOS фоновый режим не нужен:

```yaml
apple:
  info:
    UIBackgroundModes: [audio]
```

Для видео включите `PictureInPicture`, сохраните `core.Ref` и запускайте или останавливайте режим из элемента управления приложения. Следите за колбэком состояния, чтобы включить этот элемент, когда `Possible` станет true:

```go
ref := &core.Ref{}
state := core.NewSignal(cx, core.PictureInPictureState{})
video := core.Video{
    Source: "asset:clip.mp4", Ref: ref,
    PictureInPicture: true, AutoPictureInPicture: true,
    OnPictureInPicture: state.Set,
}
start := ui.Button{
    Text: "Picture in Picture", OnPress: ref.StartPictureInPicture,
    Disabled: func() bool { return !state.Get().Possible },
}
```

`AutoPictureInPicture` включает автоматический переход в режим, когда приложение iOS уходит в фон; tvOS и macOS эту опцию игнорируют. `Controls` по-прежнему показывает нативные элементы управления воспроизведением; кнопка PiP приложения использует тот же управляемый сеанс для управляемого видео. `OnPictureInPictureRestore` позволяет приложению показать страницу плеера, когда пользователь возвращается. Не размонтируйте видео, пока PiP активен: удаление его области останавливает воспроизведение и PiP.

В Android упакованная activity уже объявляет поддержку PiP. Видео переходит в окно PiP этой activity, остальной интерфейс приложения скрывается, а при возврате сохраняются плеер и позиция. `StopPictureInPicture` разворачивает ту же activity. Кнопки воспроизведения и паузы в окне сообщают `OnPlay` и `OnPause` (с `VideoPauseControls`); `Ref.Seek` использует тот же плеер. Автоматический переход требует явной настройки и подготовленного, воспроизводящегося видео. Запуск всё равно может не удаться из-за текущего состояния системы; обрабатывайте `Error`, даже если `Possible` было true.

Встраивающий Android-хост должен объявить `android:supportsPictureInPicture="true"` и обрабатывать изменения конфигурации `orientation|screenSize|screenLayout|smallestScreenSize`. Передавайте `onPictureInPictureModeChanged` и `onUserLeaveHint` activity в одноимённые методы `NsgoView`; в Android 15+ также передавайте `PictureInPictureUiState.isTransitioningToPip()` в `NsgoView.onPictureInPictureTransition`. Хост или устройство без поддержки сообщает `Supported: false`.

В вебе запускайте режим из нажатия пользователя в браузере, поддерживающем стандартный API PiP для видео. `Supported` также учитывает Permissions Policy страницы, а `Possible` требует загруженных метаданных видео. Собственные элементы управления PiP браузера сообщают то же активное состояние. Остановка, замена или очистка источника, а также удаление видео завершают его сеанс; ожидающий запуск не может снова открыть предыдущий источник. Веб-PiP показывает только видео, без собственного содержимого NSGo, автоматического перехода в фоне и `OnPictureInPictureRestore`. Браузеры без поддержки сообщают `Supported: false`.

В iOS `mobile.PictureInPicture` принимает `Children` с собственной разметкой, по умолчанию 320 × 180 точек. В приложении он не занимает места. Его `Ref` имеет те же методы запуска и остановки, а `OnState`, `OnRestore`, `OnPlay`, `OnPause` и `OnSkip` доставляют действия системы. Привяжите `PausedFunc` и `PositionFunc` к состоянию воспроизведения, которое обновляют эти колбэки; `Duration: 0` описывает прямую трансляцию. Приостановленное приложение сохраняет последний отрисованный кадр.

Поместите `core.Video` в собственное дерево, чтобы совмещать его декодированные кадры с субтитрами или другими наложениями, которые рисует приложение. Запускайте сеанс через внешний `Ref`. Используйте общий сигнал паузы с видео, передавайте в `PositionFunc` собственного сеанса значения из `Video.OnProgress`, а `OnSkip` перенаправляйте в `Ref.Seek` видео. Звук видео воспроизводится через его собственный плеер.

Собственное дерево также отрисовывает текст, представления, изображения и Canvas. WebView, шейдеры Metal и эффекты фона в захваченных кадрах недоступны. Анимированные изображения и нативные переходы слоёв показывают состояние своей модели. Для движения используйте явные анимируемые значения. При проверке в App Store использование, не связанное с видео, может быть отклонено.

`Supported: false` отличает недоступную платформу от поддерживаемого сеанса, который ещё не готов или чей `Error` объясняет сбой. Видео поддерживается в iOS и tvOS, если AVKit сообщает о поддержке PiP устройством, в macOS, Android и веб-браузерах со стандартным API; собственные деревья поддерживаются только в iOS. В iOS и tvOS общий аудиосеанс остаётся в категории воспроизведения, пока PiP включён, в том числе на паузе, и смешивается со звуком других приложений, если `AudioSession` видео равно `AudioSessionMixWithOthers`.

В headless-тестах `nsgotest.PictureInPictureSupport(supported, possible)` задаёт, что предлагает система, в окружении `nsgotest.Environment` для iOS, macOS или Android; `PiPState`, `PiPStarts` и `PiPStops` представления фиксируют сеанс, `app.ReportPictureInPicture` сообщает состояние так, как это сделала бы система, а `app.PictureInPictureControl` отправляет из окна `play`, `pause`, `skip` и `restore`. Окно PiP видео запускает и приостанавливает собственный плеер видео, о чём сообщают `Video.OnPlay` и `Video.OnPause` (с `VideoPauseControls` для паузы); в тестах о них сообщают `app.PlayVideo` и `app.PauseVideo`.

Запустите `go tool nsgo dev -target ios examples/pip` для обоих вариантов или `-target macos` либо `-target android` для PiP видео. Нативные тесты на Mac проверяют вход, выход и повторные команды с нативными элементами управления и без них, а также замену активного управляемого источника. Приёмка на iPhone, включая полноэкранный режим управляемого видео и автоматический переход, пока не выполнена; сейчас у реализации есть нативные тесты делегата и кадров и покрытие headless-тестами приложения.

Для видео в tvOS запустите `go tool nsgo dev -target tvos_simulator examples/pip`; NSGo связывает плеер с нативным сеансом Now Playing. Симулятор tvOS 27 загружает видео с нативными элементами управления и без них, но AVKit сообщает там, что PiP не поддерживается. Реальный вход в PiP, остановку и восстановление ещё предстоит проверить на физическом Apple TV.

Регрессионный тест для веб-цели использует записанный локальный клип и доверенные нажатия кнопок приложения, чтобы проверить реальный сеанс PiP браузера при входе, выходе, замене источника и удалении в Chromium. Другие браузерные движки ещё требуют приёмки.
