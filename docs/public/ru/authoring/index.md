Эти разделы предназначены для авторов компонентов: библиотек элементов управления, дизайн-систем или сложных представлений, которые приложения импортируют как пакет Go. Предполагается, что вы уже знакомы со страницами [Компоненты и состояние](../components.md) и [Стили и темы](../styles.md).

## Компонент

Компонент — это тип с методом `Render`, как и в обычном приложении. Его поля задаёт приложение; всё, что не было указано, получает нулевое значение, поэтому нулевое значение каждого поля должно соответствовать поведению по умолчанию.

```go
package chips

import "github.com/nsgo-dev/nsgo/core"

// Chip is a short label in a pill.
type Chip struct {
	Text string
}

// Render implements core.Node.
func (c Chip) Render(*core.Scope) core.Node {
	return core.View{Class: "self-start rounded-full px-3 py-1", Children: []core.Node{
		core.Text{Content: c.Text, Class: "text-sm"},
	}}
}
```

Приложение использует его как любой элемент: `chips.Chip{Text: "New"}`.

## Поведение и внешний вид

В NSGo каждый элемент управления представлен в двух вариантах. `base` содержит поведение, состояние и поддержку доступности без оформления и принимает стили для каждой части от приложения; `ui` добавляет внешний вид поверх `base`, поэтому логика поведения остаётся в одном месте. Ваша библиотека может следовать такому же разделению:

- **Нестилизованный** компонент отвечает за нажатия, работу с клавиатурой, фокус и озвучивание программами чтения с экрана, открывая стили каждой своей части, как это делает `base.Switch`. Приложения и другие библиотеки сами задают ему внешний вид ([Части и состояния](parts.md)).
- **Стилизованный** компонент оборачивает нестилизованный и только подбирает стили из действующей темы, как это делает `ui.Switch` ([Оформление и темы](looks.md)).

Компонент без самостоятельного поведения, например бейдж, можно сразу делать стилизованным.

## Организация пакета

- Размещайте по одному компоненту в файле, названном в его честь (`chip.go`), вместе с типами, которые использует только он; общие для нескольких компонентов типы выносите в отдельный файл.
- Выделяйте сложный компонент в отдельный пакет, чей API не повторяет имя компонента — например, `dock.Area` в `base/dock`.
- Выносите все тексты, которые произносит или отображает компонент, в каталог `locales/` пакета ([Тексты, тесты и публикация](shipping.md)).
- Не делайте неявных различий по типу устройства: размер или форма, отличающиеся на телефоне и настольном компьютере, должны задаваться полем, которым управляет приложение.
