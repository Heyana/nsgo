## Что озвучивает программа чтения с экрана

Поле `Label` представления — это то, что произносят вспомогательные технологии; `AccessibilityDescription` — дополнительное описание, читаемое после метки; `Hint` — описание действия при активации; `Role` — тип элемента: `core.RoleButton`, `RoleLink`, `RoleHeader`, `RoleImage`, `RoleCheckbox`, `RoleSwitch`, `RoleRadio`, `RoleTab`, `RoleTextField`, `RoleSearchField`, `RoleStatus`, `RoleMenu`, `RoleMenuItem`, `RoleDialog`, `RoleAlertDialog`, `RoleAlert`, `RoleAdjustable`, `RoleProgressBar`, `RoleTable` и остальные роли. По умолчанию `RoleStatus` представляет собой вежливую живую область (`polite live region`), а `RoleSearchField` — текстовое поле, объявляемое как поле поиска. Диалог при открытии озвучивается с его ролью и меткой, а затем с описанием — так же, как заголовок и описание `ui.Dialog`. Текст без явной метки озвучивается своим содержимым. `LabelFunc`, `HintFunc` и `AccessibilityDescriptionFunc` привязывают изменяемый текст доступности к тому же представлению, благодаря чему элементы управления сохраняют фокус и состояние при смене языка. Все базовые элементы, поддерживающие метку, принимают `LabelFunc`, а `View` и `Text` принимают `HintFunc`.

Используйте `TextFunc` для изменяемого текста в `ui.Button`, `ui.Checkbox`, `ui.MenuItem` и `ui.AlertAction` — их имена доступности следуют за этим текстом. Кнопки и флажки также принимают отдельный параметр `LabelFunc`. Ползунки, вкладки, переключатели, индикаторы выполнения и триггеры всплывающих элементов принимают `LabelFunc` для динамического имени доступности. `ui.Option.LabelFunc` задаёт текст варианта во вкладках, выпадающих списках и комбинированных списках. Числовые поля, поля ввода кода, кольцевые индикаторы выполнения и оба варианта спиннеров также принимают `LabelFunc`.

```go
core.View{
	Role:  core.RoleButton,
	Label: "Add to cart",
	Hint:  "Adds the item and opens the cart",
	OnPress: add,
	Children: []core.Node{core.Icon{SVG: lucide.ShoppingCart}},
}
```

`AccessibilityValue` задаёт числовой диапазон или текстовое значение: минимум, максимум и текущее число ползунка либо строку вроде «3 items». `Accessible` объединяет представление в единый элемент доступности, чтобы название и цена карточки зачитывались вместе, а не как два отдельных шага навигации; без метки такое представление зачитывает текст своих потомков. `AccessibilityElementsHidden` скрывает декоративные элементы вроде шеврона или разделителя, а `ImportantForAccessibility` скрывает всё поддерево.

```go
core.View{Accessible: true, Label: "Apples, $1.20 a kilo", Children: []core.Node{
	core.Text{Content: "Apples"},
	core.Text{Content: "$1.20 a kilo"},
}}
```

## Видимые подписи

Передайте элементу `core.Text` или `core.View` ссылку `Ref` целевого элемента управления в поле `LabelFor`. Нажатие на такую подпись переводит фокус на элемент управления и выполняет его действие нажатия, например переключает флажок. Текущий видимый текст подписи становится именем элемента управления без дублирования строки `Label`, а сама подпись следует за его состояниями `Disabled` и `Invalid` для доступности и стилей. При этом подпись не получает роль кнопки и не становится остановкой табуляции.

```go
field := new(core.Ref)
return core.View{Children: []core.Node{
	core.Text{Content: "Email", LabelFor: field},
	base.Input{Ref: field},
}}
```

`LabelledBy: []*core.Ref{label, requirement}` задаёт имя элемента управления из нескольких видимых элементов в указанном порядке, с приоритетом выше `Label`, при этом нажатия на них не перенаправляются. В остальных случаях `Label` имеет приоритет над неявными именами из `LabelFor`, порядок которых соответствует дереву. Обновление текста, перемещение, скрытие, удаление и повторное монтирование обновляют эту связь. Отсутствующие, повторяющиеся, циклические и скрытые ссылки игнорируются; связи действуют только в пределах одной поверхности и области ограничения. Подпись не может активировать элемент управления, находящийся за модальным окном.

Кнопки, флажки, переключатели-радиокнопки, тумблеры, выпадающие списки и числовые поля ввода из пакетов `base` и `ui` передают `Ref` и `LabelledBy` своему элементу управления; ползунки предоставляют `ThumbRef` и `StartThumbRef`. В TSX используйте `labelFor={field()}` и `labelledBy={[label()]}` с сигналами узлов, заполняемыми через `ref={node => field.set(node)}`, чтобы подпись, расположенная перед полем, обновлялась после монтирования этого поля.

## Действия

`AccessibilityActions` перечисляет действия, которые программа чтения с экрана предлагает для элемента: стандартные действия (`core.ActionActivate`, `ActionIncrement`, `ActionDecrement`, `ActionEscape`, `ActionMagicTap`) и собственные действия приложения, каждое со своим `Name` и `Label`. Обработчик `OnAccessibilityAction` получает имя вызванного действия. Используйте `AccessibilityActionsFunc` в `core.View` или `core.Input`, чтобы изменять набор доступных действий или переводить их подписи, пока элемент остаётся смонтированным.

```go
core.View{
	Role: core.RoleAdjustable,
	Label: "Quantity",
	AccessibilityValue: func() core.AccessibilityValue {
		return core.AccessibilityValue{Max: 10, Now: float32(n.Get()), Text: fmt.Sprintf("%d items", n.Get())}
	},
	AccessibilityActions: []core.AccessibilityAction{{Name: core.ActionIncrement}, {Name: core.ActionDecrement}},
	OnAccessibilityAction: func(name string) {
		if name == core.ActionIncrement {
			n.Update(func(v int) int { return v + 1 })
		} else {
			n.Update(func(v int) int { return v - 1 })
		}
	},
	Children: quantityControls,
}
```

`MultiSelectable` помечает таблицу, список или дерево, допускающие выбор более одного элемента. `base.DataTable` устанавливает это свойство при множественном выборе строк; веб, Windows и Linux передают соответствующий флаг доступности.

`Expanded` указывает, раскрыт ли раскрывающийся элемент или кнопка меню; `Busy` — что содержимое загружается; `Invalid` — что приложение отклонило содержимое поля или значение элемента управления (стилизуется через `aria-invalid:`); а `Checked`, `Selected` и `Pressed` сообщают текущее состояние элемента управления. Части элемента управления могут принимать его состояние через `PartStates`, благодаря чему индикатор повторяет состояние флажка, не создавая отдельного шага навигации.

`SelectionItem` помечает представление как элемент выбираемой коллекции независимо от его текущего значения `Selected`. `base.DataTable` устанавливает его на строках или ячейках, когда таблица допускает их выбор, а `base.Tree` — на каждой строке; Windows сохраняет шаблон `SelectionItem`, а веб записывает `aria-selected="true"` или `"false"`. Таблица без выбора оставляет строки без обоих маркеров.

## Живые изменения

`LiveRegion` заставляет программы чтения с экрана объявлять метку представления и текст внутри него по мере их изменения: `core.LiveRegionPolite` дожидается паузы пользователя, а `LiveRegionAssertive` прерывает текущее чтение. `cx.Announce` однократно произносит одно сообщение.

```go
core.Text{ContentFunc: func() string { return fmt.Sprintf("%d items in the basket", count.Get()) },
	LiveRegion: core.LiveRegionPolite}
```

## Фокус и клавиатура

Всплывающие подсказки описывают свой триггер до того, как он получит фокус. `View.Tooltip`, `base.Tooltip` и `ui.Tooltip` используют свой текущий текст как описание доступности элемента управления, если только он не повторяет имя элемента, приложение не задало `AccessibilityDescription` или подсказка не отключена через `Disabled`. Обёртка передаёт это описание своим элементам управления. Сама всплывающая карточка и её дочерние элементы скрыты от программ чтения с экрана и никогда не объявляются как оповещение; поэтому стандартная подсказка `ui.IconButton` не дублирует его метку.

`base.DataTable` открывает свою именованную сетку как остановку фокуса для клавиатуры и средств доступности; слой перехвата указателя скрыт от вспомогательных технологий.

На настольных ОС, в вебе и на Apple TV представления, принимающие нажатия, становятся остановками табуляции наравне с текстовыми полями; `NoFocus` исключает элемент из табуляции, а `Focusable` делает остановкой табуляции представление без обработчика нажатий. `Style.FocusVisible` рисует кольцо фокуса только при переходе фокуса с клавиатуры (`focus-visible:`), `Style.Focus` — при любом фокусе, а `Style.FocusWithin` — когда фокус находится внутри представления; `OnFocus` и `OnBlur` отслеживают эти события (причём `OnBlur` также срабатывает при удалении сфокусированного представления из дерева), а `Ref.Focus()` и `Ref.SetAccessibilityFocus()` перемещают фокус. `core.FocusedRef(cx)` возвращает ссылку на текущее сфокусированное представление, чтобы элемент, открывающийся без триггера (например, панель поиска по клавише), мог вернуть фокус при закрытии. Return и Space нажимают сфокусированное представление, а клавиши со стрелками перемещают фокус по спискам вкладок, группам радиокнопок и меню. Свойство `Tooltip` представления появляется сразу при переходе фокуса с клавиатуры и остаётся видимым, пока фокус не уйдёт или не будет нажата клавиша Escape. Обработчик `OnOpen` всплывающего элемента выполняется после появления его содержимого, поэтому вызов `Focus` внутри него переносит фокус внутрь, как и положено немодальному диалогу; содержимое всплывающей панели следует за её триггером в порядке табуляции, а при закрытии фокус возвращается на триггер.

На Android, iPhone и iPad методы `Ref.Focus()` и поле `AutoFocus` кнопки могут сфокусировать активное нажимаемое представление или представление с `Focusable` для работы с аппаратной клавиатурой. Касание элемента управления такой фокус не переводит. Space и Return активируют сфокусированный нажимаемый элемент после обработки раскладки клавиш, сохраняя модификаторы Control, Alt, Shift и платформенную клавишу на каждом этапе нажатия. Элементы с `NoFocus`, отключённые или скрытые элементы и элементы за модальным окном не могут получить этот фокус. Фокусировка представления не открывает экранную клавиатуру; нативные поля ввода сохраняют своё обычное поведение редактирования. На watchOS и в мини-приложениях путь активации с физической клавиатуры отсутствует.

`cx.Env().ScreenReader()` сообщает, запущена ли программа чтения с экрана; `cx.Env().ReduceMotion()` — запросил ли пользователь уменьшение движения; `cx.Env().IncreaseContrast()` — запросил ли пользователь повышенную контрастность (Increase Contrast в macOS, iOS и watchOS, контрастная тема в Windows, High Contrast в GNOME, настройка контрастности в GTK 4.20 или высококонтрастная тема GTK, настройка контрастности выше стандартной в Android 14, `prefers-contrast: more` или `forced-colors: active` в вебе); `cx.Env().FontScale()` — масштаб текста; а `cx.Env().RTL()` — направление макета. Текст масштабируется согласно размеру шрифта, если не задано `NoFontScaling`, а макет с направлением справа налево зеркалирует свои физические края, если используются логические края.
