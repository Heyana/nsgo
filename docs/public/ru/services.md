## Оповещения и буфер обмена

`cx.ShowAlert` показывает оповещение или лист действий платформы. Его `Actions` возвращаются по индексу, а роль позволяет отрисовать кнопки отмены и деструктивного действия так, как это принято на платформе. На macOS оповещения и окна выбора файлов отображаются как лист (sheet), пока их окно видимо. Если окно скрыто, свёрнуто или находится за пределами экрана, а также в приложении в трее без окна, диалог открывается отдельно. Закрытие окна, запросившего диалог, отменяет его диалоги.

```go
cx.ShowAlert(core.AlertConfig{
	Title:   "Delete the file?",
	Message: "This cannot be undone.",
	Actions: []core.AlertAction{
		{Label: "Cancel", Role: core.AlertCancel},
		{Label: "Delete", Role: core.AlertDestructive},
	},
}, func(index int) {
	if index == 1 {
		remove()
	}
})
```

`SetClipboard` записывает текст, а `SetClipboardImage` — изображение. `ReadClipboard`, `ReadClipboardImage` и `ReadClipboardFiles` отвечают асинхронно, а `HasClipboardText` и `HasClipboardImage` узнают, что содержит буфер обмена, без уведомления о вставке. `core.FileFromURL` открывает URL, которые выдают `ReadClipboardFiles` и `View.OnFileDrop`, как `core.File`: URL вида `file:`, а в вебе — URL вида `blob:`.

На tvOS нет общедоступного буфера обмена. Запись в буфер игнорируется, чтение не возвращает содержимого, а проверки наличия возвращают false.

```go
cx.ReadClipboard(func(text string) { pasted.Set(text) })
cx.SetClipboard("Hello")
```

На macOS и Windows `ReadClipboardItems` выдаёт снимок всех доступных байтовых представлений объёмом до 48 MiB. Каждый элемент содержит упорядоченные значения `ClipboardRepresentation` с нативным `Type` и исходными данными `Data`, включая форматы, обозначающие только наличие, с пустыми данными. `ClipboardFormats` перечисляет нативные имена форматов, не копируя их содержимое. Чтобы восстановить снимок, передайте его в `WriteClipboardItems` вместе с необязательной функцией обратного вызова, которая получает ошибку записи. Пустой срез очищает буфер обмена. Сравнивайте значения `ClipboardChangeCount` на равенство, чтобы обнаружить новое копирование, даже если скопированный текст совпадает с прежним.

macOS сохраняет границы элементов и имена типов буфера обмена. Windows использует один элемент и сохраняет основанные на байтах имена Win32, такие как `CF_HDROP`, и зарегистрированные форматы, такие как `Rich Text Format`. При записи она объединяет элементы с разными форматами и использует нулевой байт для пустого содержимого. Дескрипторы GDI, форматы с отображением владельцем и частные числовые идентификаторы форматов опускаются. На других платформах функции обратного вызова чтения и записи получают `CodeUnavailable`, а функция обратного вызова счётчика получает `-1`.

## Открытие ссылок и файлов

`cx.OpenURL` открывает URL в системном браузере или приложении, а `core.CheckURL` сообщает, что он отклоняет: отсутствие схемы, длину более 16 KiB, пробелы, веб-адрес без хоста, а также `javascript:`, `data:`, `blob:`, `file:`, `about:` и `asset:`.

```go
if err := core.CheckURL(url); err == nil {
	cx.OpenURL(url, func(opened bool) {
		if !opened {
			status.Set("No app opens that link.")
		}
	})
}
```

`cx.OpenFile` открывает имеющийся у приложения файл в приложении, связанном с его типом, а `cx.Share` показывает системный лист «Поделиться» для файлов, текста или того и другого на macOS, iOS, Android, Windows, Linux (через портал рабочего стола или файловый менеджер) и в вебе (`navigator.share`). `core.SharedFile` — это путь на диске (или, для `Share` в вебе и везде, где файл хранится в памяти, его байты `Data`) с именем и типом, которые видит другое приложение. На настольных системах `desktop.RevealFile` показывает файл или папку выделенными в Finder, Проводнике или файловом менеджере, а `desktop.TrashFile` перемещает их в Корзину; он никогда не удаляет окончательно, а отвечает `core.ErrNoTrash` и оставляет элемент на месте, если на томе нет корзины или корзина не сохранит его, например если файл больше, чем вмещает Корзина Windows.

```go
cx.Share(core.ShareOptions{
	Files: []core.SharedFile{{Path: path, Name: "Notes.txt"}},
	Text:  "A note from NSGo",
}, func(shown bool, err error) {})
```

`mobile.OnShared(cx, func(items []mobile.SharedItem) { ... })` получает текст и файлы для [`android.share_types`](building.md#incoming-shares-on-android) или [`apple.share_types`](building.md#incoming-shares-on-ios). Отправленное на Android может запустить приложение; iOS ставит такие данные в очередь в App Group, пока приложение не станет активным или пользователь в следующий раз его не откроет. Ожидающие данные ждут первого обработчика. iOS хранит пакет входящих данных, пока функция обратного вызова не вернёт управление; доставка выполняется как минимум один раз, даже если процесс завершится. Текст приходит в `Text`, а файлы — как доступные для чтения копии в кэше с `Path`, `Name` и `MIME`. Переместите или скопируйте файл в постоянное хранилище, если он должен пережить кэш.

`desktop.LookUp` показывает системную панель словаря для текста, как это делает касание тремя пальцами на macOS, поверх прямоугольной области в представлении: текст и область выделения вместе с `Ref` его представления `Selectable`. `desktop.CanLookUp` сообщает, возможно ли это, — в окне на macOS; в Windows, Linux и вебе такой панели нет. В тестах `nsgotest.App.LookUps` перечисляет показанные панели там, где `nsgotest.Environment` задаёт `CanLookUp`.

```go
var area core.Ref
var selected core.TextSelection
core.View{Ref: &area, Selectable: true, OnTextSelection: func(s core.TextSelection) { selected = s }, Children: subtitles}
// From a menu item or a shortcut:
if desktop.CanLookUp(cx) {
	desktop.LookUp(cx, selected.Text, &area, selected.Bounds)
}
```

`desktop.QuickLook` запрашивает предпросмотр файлов начиная с заданного индекса и обновляет файлы, если вызвать его снова, пока панель открыта. `desktop.CanQuickLook` сообщает о доступности в собственном окне приложения на macOS и Windows, а на Linux — когда сеанс предоставляет запущенную или активируемую службу D-Bus GNOME Sushi. Windows использует зарегистрированный обработчик предпросмотра для типа файла; поддерживаемые форматы зависят от установленных обработчиков или средства предпросмотра. Результат true означает, что запрос был передан платформе, а не что она отобразила файл.

Пробел или Escape закрывают панель. Клавиши со стрелками выбирают файлы из запроса на Windows и в версиях Sushi, которые сообщают о выделении и владельце в X11. В Wayland Linux пока открывает предпросмотр без родительского окна; автоматическое закрытие вместе с владельцем и выбор стрелками недоступны. Средства предпросмотра, специфичные для KDE, и веб не поддерживаются.

```go
if desktop.CanQuickLook(cx) {
	desktop.QuickLook(cx, []string{reportPath, sourcePath}, 0)
}
```

## Нативные значки меню

`desktop.MenuItem.Icon` показывает значок рядом с пунктом в меню приложения, Dock, трея и всплывающих меню на macOS, Windows и Linux. `desktop.MenuIcon` принимает разобранный векторный значок (`SVG`, например `lucide.Folder()`), закодированные байты изображения (`Data`, PNG, JPEG, GIF, WebP или SVG) или локальный, ресурсный либо пиксельный `core.ImageSource` (`Source`). Установка `Template` окрашивает монохромное изображение цветом текста меню с учётом светлого и тёмного оформления (а на macOS — и состояния подсветки); монохромные значки `SVG` по умолчанию считаются шаблонами.

```go
desktop.SetApplicationMenu(cx, []desktop.MenuItem{{
	Label: "File",
	Items: []desktop.MenuItem{
		{Label: "Open Folder…", Icon: desktop.MenuIcon{SVG: lucide.Folder()}, OnSelect: openFolder},
		{Label: "Export", Icon: desktop.MenuIcon{Data: exportPNG, Template: true}, OnSelect: exportFile},
	},
}})
```

Значки загружаются синхронно из локальных источников; удалённые URL и некорректные изображения оставляют пункт без значка. Метки меню, сочетания клавиш и индикаторы флажков и переключателей сохраняют своё нативное поведение.

В тестах `nsgotest.MenuItem.Icon` записывает значок каждого пункта в `app.Menu`, `app.DockMenu` и `app.PopupMenu`.

## Фотографии и файлы

`cx.PickImages` показывает системное окно выбора фотографий и отвечает значениями `core.PickedFile`, у которых приложение читает байты, имя, тип и размер в пикселях. `cx.TakePhoto` показывает камеру там, где она есть на платформе; `cx.Env().CanTakePhoto` сообщает, есть ли она. На macOS, Windows и Linux он показывает предпросмотр камеры сканера с кнопкой «Сделать снимок». `cx.ScanCode` открывает предпросмотр камеры и отвечает первым прочитанным кодом — QR-кодом, если `ScanOptions.Kinds` не запрашивает другие виды, — или nil, если пользователь закрыл его; `cx.Env().CanScanCode` сообщает, есть ли на платформе сканер: на устройствах macOS, iOS и Android с камерой, на компьютерах с Windows, у которых она есть, на рабочих столах Linux с порталом Camera и GStreamer `pipewiresrc`, а также в браузерах с `getUserMedia` и `BarcodeDetector`. macOS показывает лист, если запросившее окно видимо, Windows и Linux — модальное окно поверх окна, а веб — оверлей поверх страницы. Укажите `NSCameraUsageDescription` в `apple.info` для macOS и iOS и `CAMERA` в `android.permissions` для Android. Android, Windows и Linux читают все виды кодов, кроме PDF417. Считайте текст кода недоверенными входными данными.

На tvOS `PickImages` отвечает без изображений, а `TakePhoto` возвращает `core.ErrNoCamera`; NSGo не предоставляет окно выбора Continuity Camera.

В тестах `nsgotest.App.PickImages`, `nsgotest.App.TakePhoto` и `nsgotest.App.ScanCode` получают записи `nsgotest.ImagePick` для выбора и съёмки и записи `nsgotest.CodeScan` для сканирования и отвечают вместо системного интерфейса. Эти хуки работают без интерфейса и на поддерживаемых хостах `nsgo test -target`. `nsgotest.Environment(core.Environment{Camera: true, ScanCode: true})` даёт камеру цели, у которой её нет.

```go
cx.PickImages(core.PickOptions{Limit: 1, MaxDimension: 2048}, func(files []core.PickedFile) {
	if len(files) == 1 {
		avatar.Set(files[0].Data)
	}
})
```

`cx.PickFiles` выбирает файлы любого типа, `cx.PickDirectories` выбирает папки как `fs.FS`, а `cx.SaveFile` сохраняет файл или байты через системный диалог сохранения. Оба окна выбора принимают `Title`, метку кнопки `Button` и начальную папку `Start`, а `PickFilesOptions.TypesName` задаёт название меню типов, чтобы приложение могло показать их на своём языке; это подсказки, которым следуют macOS, Windows и Linux, iOS — только для `Start`, а Android и веб не следуют вовсе. `cx.PickScreenColor` выбирает цвет в любом месте экрана там, где `cx.Env().CanPickScreenColor()` равно true: на macOS, Windows, в Linux с порталом рабочего стола Screenshot и в браузерах с `EyeDropper`.

Задайте в `core.SaveOptions.Start` существующую абсолютную папку, чтобы открыть диалог сохранения в ней на macOS, Windows, Linux и iOS. При пустой или непригодной подсказке, а также на других целях папку выбирает система.

Задайте `core.SaveOptions.Accept`, чтобы проверить выбранное место назначения перед записью. Эта функция выполняется в горутине движка. Возврат ошибки оставляет место назначения нетронутым. На macOS, Windows и во встроенном в процесс окне выбора GTK на Linux диалог показывает причину и позволяет пользователю выбрать другой путь. Отмена после отказа сообщает `saved == false`, отклонённый путь и ошибку. На Android и в портале рабочего стола Linux отказ завершает сохранение с этим результатом. Android позволяет пользователю выбрать папку и передаёт URI дерева с запрошенным именем файла в параметре запроса `name`. Он создаёт документ после одобрения и при успехе сообщает URI нового документа. Платформа отказывается от записи, если проверка не ответит в течение пяти секунд. iOS и HarmonyOS сообщают об ошибке для сохранений, требующих проверки. В вебе нет пути назначения, и используется обычный процесс сохранения.

В тестах без интерфейса `App.PickFiles`, `App.PickDirectories` и `App.SaveFile` получают записи `nsgotest.FilePick`, `nsgotest.DirectoryPick` и `nsgotest.FileSave`. Те же записи находятся в `app.FilePicks`, `app.DirectoryPicks` и `app.Saves`.

### Встроенные ресурсы

Поместите файлы в каталог `resources/` приложения и используйте `cx.ReadAsset("asset:maps/level.bin", done)`, чтобы прочитать их из Go. Функция обратного вызова получает `([]byte, error)` в горутине движка после чтения и отбрасывается, если её владелец исчезает или выполняется снова. Используйте `errors.Is(err, core.ErrAssetNotFound)`, чтобы распознать отсутствующие файлы. Чтение загружает весь файл в память.

## Получение PCM-аудио

Используйте `audio.NewOutput(cx, audio.OutputConfig{SampleRate: 48000, Channels: 2, Render: render})`, чтобы воспроизводить чередующийся PCM в формате Float32, который ваше приложение декодирует или синтезирует. `Start` начинает получение сэмплов, `Pause` останавливает его, а владеющая область видимости закрывает вывод при своём завершении. macOS, iOS, Android, Windows, Linux и веб поддерживают этот поток. Другие цели возвращают `audio.ErrUnsupported`.

`Render` возвращает число заполненных кадров. Он выполняется в аудиопотоке и должен избегать блокировок, выделения памяти и обращений к графу. Неполное заполнение воспроизводит тишину для оставшейся части и увеличивает `Underruns`. `Position` возвращает монотонный счётчик кадров и время хоста на этом кадре. Используйте `Flush`, чтобы отбросить ожидающие кадры, и `Latency`, чтобы узнать задержку буфера. Смена маршрута и прерывания приостанавливают вывод и вызывают `OnInterrupt` в движке. Приложение может возобновить его с помощью `Start`.

## Хранилище

`cx.Storage()` — это хранилище «ключ-значение» приложения, которое хранится на устройстве и общее для всех графов приложения. Чтение синхронное, и чтение внутри вычисления подписывает его на изменения; `SetItem` возвращает `core.StorageFullError` при превышении квоты (`core.StorageQuota`, по умолчанию 5 MiB). Это обычный файл, который может прочитать любая программа пользователя, поэтому храните токены и пароли в [секретах](#secrets).

`cx.Store()` возвращает нижележащее хранилище для хоста, создающего ещё один корень с `core.RootOptions.Storage`, например запускающего плагин в собственной горутине: тогда оба корня разделяют записи приложения и то, что хранится на устройстве. Это всё хранилище целиком, а не раздел, который `cx.ProvideStorage` выдаёт коду, написанному не автором приложения.

Хост, предоставляющий собственный механизм сохранения, вызывает `core.NewStore(backend)` с `core.StorageBackend`: `Load() (map[string]string, error)` загружает данные один раз, а `Write(core.StorageChange)` получает изменения по порядку. Ветвитесь по `change.Op` (`core.StorageSet`, `core.StorageRemove`, `core.StorageClear`) и используйте `change.Key` и `change.Value`. Передайте `nil` для хранилища, которое находится только в памяти.

```go
store := cx.Storage()
if tab, ok := store.GetItem("tab"); ok {
	selected.Set(tab)
}
store.SetItem("tab", "library")
```

`store.Keys()` перечисляет ключи, `RemoveItem` удаляет один из них, а `Clear` очищает хранилище. `cx.DataDir()` и `cx.CacheDir()` выдают папки приложения для файлов, для которых хранилище «ключ-значение» слишком мало; `cx.LogsDir()` выдаёт каталог платформы для файлов журналов, а `Scope.ProvideStorage` выделяет поддереву собственный раздел.

iOS App Clip и его полное приложение разделяют эти расположения данных и хранилища, если настроены `app_clip` и явный `apple.app_group`; их кэши остаются раздельными. Включение группы не переносит существующие данные песочницы. Настройка и подпись описаны в разделе [Хранилище App Clip](building.md#app-clips).

На HarmonyOS файловые операции Go, такие как `os.ReadFile`, `os.WriteFile` и `os.Rename`, работают в этих каталогах и в `os.TempDir()`. Относительные пути начинаются в каталоге файлов. Рекомендательные блокировки файлов и символические ссылки недоступны.

### Папки пользователя

`desktop.UserDir(cx, desktop.DownloadsDir)` возвращает путь к одной из папок пользователя: `DocumentsDir`, `DownloadsDir`, `DesktopDir`, `PicturesDir`, `MusicDir` или `VideosDir`. Функция каждый раз обращается к системе, поэтому учитывает папку, которую пользователь переместил: папки в домашнем каталоге на macOS (`Movies` для видео), известные папки на Windows, включая папки OneDrive, и пользовательские каталоги XDG на Linux. Папка может ещё не существовать. У телефонов, веба и HarmonyOS нет таких папок, доступных приложению по пути, как нет их и на Linux для папки, не указанной в `user-dirs.dirs`: `UserDir` возвращает `core.ErrUserDirUnavailable`, и тогда приложение спрашивает пользователя через `cx.PickDirectories` или `cx.SaveFile`.

```go
dir, err := desktop.UserDir(cx, desktop.DownloadsDir)
if err != nil {
	dir = cx.DataDir()
}
```

Тесты никогда не получают настоящие папки пользователя: каждая из них — пустой каталог внутри временного каталога теста, а `nsgotest.UserDirs(map[core.StandardDir]string{…})` закрепляет их, причём не указанная папка недоступна.

### Отчёты о сбоях

Нативные релизные сборки сохраняют трассировки сбоев Go в `cx.LogsDir()/crashes`. На платформах Apple записываются неперехваченные исключения Objective-C, на Android — неперехваченные исключения Java, а на Windows — исключения SEH, дошедшие до её фильтра верхнего уровня. Получите список ожидающих отчётов при следующем запуске с помощью `cx.CrashReports()`. Каждый отчёт указывает версию, сборку и платформу, которые его создали. Вызовите `Open()`, чтобы прочитать диагностический текст, закройте средство чтения, затем вызовите `Acknowledge()`, чтобы удалить отчёт, когда приложение его обработало. Выполняйте эти файловые операции в горутине.

## Место на диске

`cx.DiskSpace(func(space core.DiskSpace, err error) { … })` асинхронно запрашивает сведения о томе, содержащем `cx.DataDir()`, и вызывает функцию обратного вызова в горутине движка. `Total` — ёмкость, сообщаемая системой, `Available` — объём, который приложение может использовать для операции, запрошенной пользователем, а `Opportunistic` — объём, который можно использовать для кэшей и предварительной загрузки. Все три значения указаны в байтах. `Available` включает место, которое система освобождает по требованию, там, где она сообщает это значение. Платформы с единственным значением свободного места возвращают его в обоих полях. В вебе `Total` — оценка квоты хранилища браузера для источника, а `Available` — её неиспользованная часть. Если служба недоступна, возвращается `core.ErrDiskSpaceUnavailable`.

Сборки для Apple требуют, чтобы `apple.privacy.accessed_apis` в `nsgo.yaml` объявлял `NSPrivacyAccessedAPICategoryDiskSpace`. Объявите `E174.1`, чтобы проверять место перед записью или освобождать файлы при нехватке места с изменением, которое пользователь может заметить. Объявите `85F4.1`, чтобы показывать пользователю доступное место. Приложение должно соблюдать ограничения Apple на использование и передачу этих показаний. Сборка без этой категории возвращает `core.ErrNotDeclared`. [Одобренные Apple причины](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype)

Задайте ответ для теста с помощью `nsgotest.DiskSpace(space, err)`.

## Облачное хранилище

Пакет `cloud` синхронизирует между устройствами небольшие записи «ключ-значение» (`cloud.Get`, `cloud.Set`, `cloud.Delete`, `cloud.Keys`) и более крупные файлы или снимки сохранений (`cloud.ReadFile`, `cloud.WriteFile`, `cloud.DeleteFile`, `cloud.ListFiles`): через iCloud Key-Value Store и контейнеры документов ubiquity на macOS и iOS и через Google Play Games Saved Games на Android.

Каждая операция доставляет свою функцию обратного вызова в горутине движка и пропускает её, если `cx` уже освобождён. `cx.Env().CanUseCloudStorage()` сообщает, доступно ли облачное хранилище; если пользователь не вошёл в систему, отсутствуют entitlements или на платформе нет нативного облачного бэкенда (Windows, Linux и веб), каждый вызов возвращает `cloud.ErrUnavailable` и никогда не отбрасывает записи молча.

```go
if cx.Env().CanUseCloudStorage() {
	cloud.WriteFile(cx, "saves/slot1.sav", saveBytes, func(err error) {
		if err != nil {
			status.Set(err.Error())
		}
	})
}

cloud.WatchChanges(cx, func(ev cloud.ChangeEvent) {
	reload(ev.Keys, ev.Files)
})

cloud.OnConflict(cx, func(c cloud.Conflict) {
	_ = c.Resolve(mergeSaves(c.Local, c.Remote))
})
```

`cloud.WatchChanges` и `cloud.OnConflict` доставляют внешние изменения с нескольких устройств и конфликты версий в горутине движка и автоматически освобождаются, когда освобождается `cx`. Чтение файла с конфликтом возвращает `*cloud.ConflictError` (соответствующий `errors.Is(err, cloud.ErrConflict)`).

Чтобы включить entitlements Apple iCloud в `nsgo build`, добавьте раздел `cloud:` (или `icloud:`) в `nsgo.yaml`:

```yaml
cloud:
  kv_store: true
  containers:
    - iCloud.com.example.myapp
```

Профиль подписи должен предоставлять запрашиваемые возможности iCloud. На macOS iCloud есть только в сборках для Mac App Store (`sign.macos_profile`), поскольку macOS предоставляет его только с профилем обеспечения; сборка Developer ID обходится без него и выдаёт предупреждение. На Android облачному хранилищу нужен SDK Play Games Services v2 в приложении и игрок, выполнивший вход.

В настольных магазинах, таких как Steam, Steam Auto-Cloud синхронизирует `cx.DataDir()` напрямую без какого-либо дополнительного кода — продолжайте записывать туда локальные файлы сохранений, а Steam синхронизирует каталог.

В тестах `nsgotest` выдаёт каждому приложению изолированное облачное хранилище в памяти: переключайте доступность с помощью `nsgotest.CloudAvailable` или `app.SetCloudAvailable`, имитируйте внешние обновления с нескольких устройств с помощью `app.SimulateCloudChange` и проверяйте разрешение конфликтов с помощью `app.SimulateCloudConflict`.

## Секреты

`cx.Secrets()` — это защищённое хранилище приложения для токенов обновления, ключей API и паролей: `Get`, `Set` и `Delete` для строки по учётной записи, которую защищает платформа. Отсутствующая учётная запись читается как `("", false, nil)`, а там, где у платформы нет защищённого хранилища, как в вебе, каждый вызов возвращает `core.ErrSecretsUnavailable`; NSGo никогда не откатывается к обычному хранилищу. Система может заставить вызов ждать, например когда связка ключей запрашивает пользователя, поэтому выполняйте вызовы вне горутины движка и возвращайте результат с помощью `cx.Post`.

```go
secrets := cx.Secrets()
go func() {
	token, ok, err := secrets.Get("refresh-token")
	cx.Post(func() {
		if err == nil && ok {
			login(token)
		}
	})
}()
```

| Платформа | Где хранится секрет |
| --- | --- |
| macOS | Обычный пароль в связке ключей входа: `kSecAttrService` — служба, `kSecAttrAccount` — учётная запись |
| iOS, tvOS, watchOS | Обычный пароль в связке ключей, таким же образом |
| Windows | Обычные учётные данные в Диспетчере учётных данных с целью `service/account`, не более 2560 байт |
| Linux | Элемент Secret Service (GNOME Keyring, KWallet) с атрибутами `service` и `account`; недоступно, если в сеансе такая служба не запущена |
| Android | Шифруется ключом AES из Android Keystore, хранится в закрытых файлах приложения вне резервных копий; при чтении также используются значения, которые `expo-secure-store` зашифровал в свои `SharedPreferences` `SecureStore` |
| Мини-программы WeChat | Хранилище, шифруемое платформой (`wx.setStorage` / `wx.getStorage` с `encrypt: true`, базовая библиотека 2.21.3+); недоступно в более старых базовых библиотеках |
| Веб, другие мини-программы | Недоступно (`core.ErrSecretsUnavailable`): у браузеров нет защищённого ОС клиентского хранилища секретов (храните веб-сеансы в устанавливаемых сервером cookie `HttpOnly`), а у мини-программ QQ, Alipay и Douyin нет шифруемого хранилища |

По умолчанию служба — это идентификатор приложения (`core.App().ID`). Приложение, переходящее с другого фреймворка, сохраняет вход своих пользователей, указывая элементы, которые записал тот фреймворк: `Service`, а на платформах Apple — `AccessGroup` и `Accessible`. На Android задайте `Service` равным `keychainService` из `expo-secure-store` (по умолчанию `"key_v1"`), чтобы читать значения, которые он зашифровал в `SharedPreferences`; запись или удаление очищает перенесённую запись. На iOS `core.SecretAfterFirstUnlock` позволяет фоновой работе читать элемент, пока телефон заблокирован, а доступность `ThisDeviceOnly` не допускает его в резервные копии. На macOS `AccessGroup` перемещает элементы в связку ключей с защитой данных, для чего нужна сборка, подписанная командой, чьё entitlement `keychain-access-groups` содержит эту группу; оно настраивается в `macos.entitlements` в `nsgo.yaml` как для сборок Mac App Store, так и для сборок Developer ID.

```go
s := cx.Secrets()
s.Service = "app:no-auth" // the service an earlier build used
s.Accessible = core.SecretAfterFirstUnlockThisDeviceOnly
err := s.Set("refresh-token", token)
```

`nsgotest` хранит секреты приложения в памяти, в `App.Secrets`, а `nsgotest.Secrets` запускает тест с некоторыми из них, поэтому тест никогда не касается связки ключей машины. Пакет TSX получает доступ к хранилищу через возможность `secrets` под собственной службой.

## Сеть

`cx.Env().Network()` сообщает, есть ли у системы пригодный маршрут (`Online`) и считает ли она этот маршрут лимитным или дорогим (`Expensive`). Привязки следуют за ним, как за любым другим значением окружения. `cx.OnNetworkChange(func(core.Network))` вызывает обработчик в горутине движка при каждом изменении, пока жива его область видимости. Маршрут системы ничего не говорит о том, ответит ли конкретный сервер. Цель, которая не может сообщить о подключении, по умолчанию считается подключённой, а неизвестная стоимость по умолчанию равна false.

Задайте `core.Environment{Network: &core.Network{Online: false}}` через `nsgotest.Environment` или `App.SetEnvironment`, чтобы проверить поведение без сети.

Собственный пакет Go `net/http` выполняет запросы на любой цели с системными настройками TLS и прокси. Сигналы принадлежат горутине движка, поэтому ответ из другой горутины попадает к ним через `cx.Post`.

```go
go func() {
	resp, err := http.Get("https://api.example.com/items")
	if err != nil {
		cx.Post(func() { errText.Set(err.Error()) })
		return
	}
	defer resp.Body.Close()
	var items []Item
	if err := json.NewDecoder(resp.Body).Decode(&items); err != nil {
		cx.Post(func() { errText.Set(err.Error()) })
		return
	}
	cx.Post(func() { list.Set(items) })
}()
```

`cx.Post` выполняет свою функцию в горутине графа, где можно устанавливать сигналы. На Android манифест запрашивает разрешение на доступ в интернет, а загружаемые изображения кэшируются на диске.

`core.NewResource` делает то же самое для значения, загружаемого из источника. Его функция загрузки выполняется в собственной горутине и загружает данные заново, когда источник меняется:

```go
items := core.NewResource(cx, func() (string, bool) { return query.Get(), query.Get() != "" },
	func(ctx context.Context, q string, _ core.ResourceInfo) ([]Item, error) {
		req, err := http.NewRequestWithContext(ctx, http.MethodGet, "https://api.example.com/items?q="+url.QueryEscape(q), nil)
		if err != nil {
			return nil, err
		}
		resp, err := http.DefaultClient.Do(req)
		if err != nil {
			return nil, err
		}
		defer resp.Body.Close()
		var list []Item
		if err := json.NewDecoder(resp.Body).Decode(&list); err != nil {
			return nil, err
		}
		return list, nil
	})
```

`items.Get()`, `items.Err()` и `items.Loading()` — это сигналы, за которыми следуют привязки. Новый запрос отменяет ещё выполняющийся запрос через `ctx`, поэтому запоздавший ответ никогда не заменит более новый. `items.Refetch()` повторяет запрос, сохраняя последний список во время загрузки, а `items.Mutate` сразу устанавливает значение для оптимистичного обновления.

`core.Suspense` показывает запасное содержимое, пока ресурсы, которые читает его содержимое, загружают своё первое значение, поэтому экрану не нужен собственный флаг загрузки:

```go
core.Suspense{
	Content:  func(cx *core.Scope) core.Node { return itemList(cx, items) },
	Fallback: func(*core.Scope) core.Node { return ui.Spinner{Label: "Loading"} },
}
```

Содержимое остаётся смонтированным, но скрытым во время ожидания, поэтому появляется сразу, как только приходят значения. Повторная загрузка оставляет его видимым с последним значением.

### Обнаружение локальных служб

На macOS, iOS, Android, Windows и Linux `cx.AdvertiseService` публикует прослушиваемый порт и атрибуты TXT. `cx.BrowseServices` сообщает о найденных службах с их хостом, портом и атрибутами TXT. `Host` может быть DNS-именем хоста или IP-адресом. Когда служба исчезает, функция обратного вызова снова получает её с установленным `Removed`. Проверяйте поддержку платформой с помощью `cx.Env().CanDiscoverServices()`. Оба вызова возвращают функцию остановки и завершаются, когда освобождается их область видимости. Об ошибке платформы сообщается асинхронно в горутине движка. Linux использует Avahi и сообщает об ошибке, если демон недоступен.

Для Bonjour на платформах Apple объявите типы служб и объясните доступ к локальной сети в `nsgo.yaml`. Система управляет запросом разрешения и запоминает выбор пользователя.

```yaml
apple:
  info:
    NSLocalNetworkUsageDescription: Finds nearby devices to sync with.
    NSBonjourServices:
      - _example._tcp
```

Android использует `NsdManager`. Android 12 и более ранние версии, а также Android 13 до T Extensions 7 требуют `CHANGE_WIFI_MULTICAST_STATE` для обнаружения через Wi-Fi. Автономные сборки объявляют это разрешение. Если вы встраиваете NSGo в хост Android, добавьте его в манифест хоста для таких устройств. Объявляемые значения TXT должны быть корректным UTF-8 на устройствах без API необработанных TXT в Android (API 37 или T Extensions 22). При обзоре необработанные значения TXT сохраняются. Если хост Android нацелен на API 37 или выше, он должен объявлять и запрашивать `ACCESS_LOCAL_NETWORK` на Android 17 и новее.

Используйте `nsgotest.LocalServices`, чтобы предоставить результаты обзора в тесте без интерфейса.

## Сейчас играет

Используйте `cx.SetNowPlaying(core.NowPlaying{...})`, чтобы показывать текущее медиа приложения в Пункте управления и строке меню macOS. Укажите `Title`, `Artist`, `Album` и необязательный `Artwork` как `*core.ImageSource`. Нулевая длительность `Duration` означает прямую трансляцию. Передайте текущую позицию `Position` и скорость воспроизведения `Rate` (ноль на паузе, единица при обычной скорости). Публикуйте снова, когда меняется трек, позиция или скорость. Между вызовами система сама продвигает позицию.

Перечислите поддерживаемые элементы управления воспроизведением в `Commands`, например `core.MediaPlay`, `core.MediaPause`, `core.MediaTogglePlayPause` и `core.MediaSeek`. Обрабатывайте запросы с помощью `cx.OnMediaCommand`. Функция обратного вызова получает вид команды `Kind` и, для перемотки, запрошенную позицию `Position`. Команды получает самый новый действующий обработчик. Вызовите `cx.ClearNowPlaying()`, когда приложение закончило воспроизведение. Пока приложение публикует сведения вручную, управляемые видео на macOS приостанавливают собственную публикацию. Проверяйте поддержку платформой с помощью `cx.Env().CanShowNowPlaying()`.

## Фоновые загрузки

Используйте `cx.Download` и `cx.OnDownloadUpdate` в автономных приложениях iOS и macOS, а также на Android. У встроенных представлений Apple нет хоста передачи. Приложения Android включают `android.background_downloads: true` в `nsgo.yaml`. Начинайте загрузку по действию пользователя, пока приложение видимо. Используйте абсолютный путь назначения с существующим родительским каталогом, в который приложение может писать.

```go
cx.OnDownloadUpdate(func(p core.DownloadProgress) {
    progress.Set(p)
})
task, err := cx.Download(core.DownloadRequest{URL: url}, path, core.DownloadOptions{
    CertificatePEM: serverCertificate,
})
```

Передача использует GET и принимает необязательные заголовки запроса. Она использует обычное хранилище доверенных сертификатов HTTPS, если только `CertificatePEM` не закрепляет конечный сертификат сервера. Закрепление также требует совпадающего имени хоста и действительного сертификата. Используйте конечный URL, поскольку служба требует успешного ответа именно от этого URL.

На платформах Apple самоподписанному сертификату на публичном имени хоста нужно исключение App Transport Security для этого хоста в `apple.info`. Передача всё равно проверяет точное закрепление сертификата, имя хоста и срок действия. Подключению к локальному NAS также нужен `NSLocalNetworkUsageDescription` с объяснением доступа, а для неполных имён хостов или хостов `.local` используется `NSAllowsLocalNetworking`. [Настройки ATS от Apple](https://developer.apple.com/documentation/security/preventing-insecure-network-connections)

```yaml
apple:
  info:
    NSAppTransportSecurity:
      NSExceptionDomains:
        files.example.com:
          NSExceptionAllowsInsecureHTTPLoads: true
```

Приоритетная служба Android продолжает работу после того, как активность уходит с экрана. Она публикует уведомление о ходе выполнения с учётом разрешения Android на уведомления. Ход выполнения измеряется в байтах, а `Total` равен -1, пока размер неизвестен. При успехе файл назначения атомарно заменяется. `task.Pause()` сохраняет частично загруженный файл, `task.Resume()` использует диапазон HTTP, если сервер предоставляет валидатор, а `task.Cancel()` удаляет частично загруженный файл.

iOS использует системный фоновый URLSession, который продолжает передачи, пока приложение приостановлено. Приложение заново подключает свой сеанс при запуске и публикует файлы, прежде чем подтвердить завершение фоновой работы. На macOS передачи выполняются внутри процесса. Платформы Apple используют нативные данные возобновления для приостановленных загрузок и хранят метаданные запроса в закрытом хранилище приложения, пока не будет сохранён окончательный результат. Если сервер не может возобновить передачу, она начинается заново.

Зарегистрируйте `OnDownloadUpdate` снова при запуске приложения, чтобы увидеть активные задачи и сохранённые результаты. Используйте `p.Task.Forget()` после обработки окончательного результата. Android может остановить службу, например когда истекает время её приоритетной передачи. Тогда приложение получает `DownloadInterrupted`. На Windows, Linux, tvOS, watchOS и в вебе `Download` возвращает `ErrDownloadUnavailable`.

## Распознавание речи и жизненный цикл

`cx.StartSpeech` распознаёт речь с помощью системного распознавателя там, где `cx.Env().CanRecognizeSpeech()` сообщает о его наличии (macOS, iOS, Android, Windows и браузеры, предоставляющие `SpeechRecognition` или `webkitSpeechRecognition`), и отвечает расшифровкой по мере её изменения. На платформах Apple объявите `NSMicrophoneUsageDescription` и `NSSpeechRecognitionUsageDescription` в `apple.info`; на Android добавьте `RECORD_AUDIO` в `android.permissions`. В тесте без интерфейса `app.Speech` содержит `nsgotest.SpeechSession`, пока распознавание активно. Используйте `app.HearSpeech` и `app.EndSpeech`, чтобы доставлять результаты.

```go
session, err := cx.StartSpeech(core.SpeechOptions{
	Lang:    "en-US",
	Interim: true,
	OnResult: func(text string, final bool) {
		transcript.Set(text)
	},
})
if err == nil {
	defer session.Stop()
}
```

`cx.Env().Lifecycle()` сообщает, активно ли приложение, неактивно или находится в фоне: на настольных системах — для окна, в котором находится `cx`, так что содержимое свёрнутого окна может приостановиться, пока показывается другое окно, а в собственной области видимости приложения — для всех его окон вместе. `desktop.Minimized(cx)` сообщает, свёрнуто ли это окно, а `desktop.FrontmostApp(cx)` — какое приложение находится на переднем плане рабочего стола, включая само приложение, и находится ли его окно в полноэкранном режиме, как за этим следят настольный питомец или трекер времени; `desktop.CanReadFrontmostApp(cx)` сообщает, отслеживается ли это, — на macOS, Windows, X11 и поддерживаемых композиторах Wayland. `cx.OnQuit` выполняет очистку при завершении приложения, как бы оно ни завершалось, и отводит на свою работу 200 мс. `desktop.OnQuitRequest` может отменить или отложить пункт меню «Выйти» на настольной системе или `desktop.RequestQuit(cx)`. На Windows и Linux он также выполняется после `OnClosing`, когда закрытие окна завершило бы приложение. `desktop.RequestRestart(cx)` опрашивает те же обработчики перед перезапуском; `desktop.Restart(cx)` по-прежнему действует немедленно. Перезапуски средства обновления на Linux и Windows тоже спрашивают, поэтому сохранение может их отменить или отложить. Когда система сообщает о выходе из сеанса, перезагрузке или выключении, `q.Forced()` равно true, и приложение переходит к `OnQuit`. Проверяйте `Forced()`, прежде чем просить пользователя принять решение. `cx.SetAppearance` принудительно включает светлое или тёмное оформление, `cx.SetLocale` выбирает язык, `cx.OnKey` привязывает сочетание клавиш, которое бездействует, пока то, что показывает его владелец, скрыто или находится под диалогом, если только `core.KeyOptions{OverModals: true}` не сохраняет его активным; оно получает свою клавишу раньше меню приложения, если только `YieldsToMenu` не уступает её включённому пункту меню с тем же сочетанием там, где находится фокус (пока фокус у текстового поля или веб-представления, пункт `MenuNotEditing` оставляет клавишу привязке и не отдаёт её последующим пунктам с тем же сочетанием, а меню в Linux не получает клавиш, нажатых без Control, Alt или клавиши с логотипом, поэтому там такая клавиша остаётся у привязки); оно работает в окне, в котором находится `cx`, если только `AllSurfaces` не привязывает его во всех окнах и панелях приложения, включая открытые позже, для сочетания на уровне всего приложения, — и тогда оно бездействует во всех них, пока то, что показывает его владелец, скрыто в окне, где оно привязано; и оно оставляет элементу управления в фокусе клавиши, которые тот использует: кнопке — её Return и пробел, а ползунку, панели вкладок или группе переключателей — их стрелки, если только привязка не сделана с `core.KeyAlways` или `core.KeyNotEditing`; `cx.OnOpenFiles` узнаёт о документах, открытых на macOS, Windows, Linux и iOS. iOS импортирует обычные файлы во временное хранилище, принадлежащее приложению; переместите их в `cx.DataDir()`, чтобы сохранить. На macOS закрытие окна, которое предоставляло меню приложения, восстанавливает меню самого недавнего оставшегося окна или меню по умолчанию, если окон не осталось.

В Wayland отслеживание приложения на переднем плане требует версии 2 или новее протокола wlr foreign-toplevel композитора; другие композиторы сообщают `CanReadFrontmostApp` как false. Его ID — это идентификатор приложения Wayland, имя берётся из записи рабочего стола, если она доступна, а PID равен 0. Упакованные приложения Windows используют свой AUMID вместо пути к frame host. macOS следует состоянию полноэкранного представления AppKit, а не выводит его из размера окна.

Роль редактирования в меню приложения обращается к редактору в фокусе раньше своего запасного варианта `OnSelect`. На macOS «Отменить» и «Повторить» следуют истории этого редактора, а «Вырезать» — его выделению, в том числе пока приложение неактивно; если редактора нет, запасной вариант остаётся включённым.

На iOS передайте в `cx.OnKeyWith` функцию `core.KeyOptions.Title`, чтобы предлагать сочетание в системном меню клавиатуры, пока привязка может сработать. `Group` задаёт название её меню на iPadOS 26 и новее. Эти функции могут читать каталог приложения, чтобы названия сочетаний следовали языку. Используйте `app.KeyCommands()` в тестах, чтобы изучить текущий список.

```go
cx.OnKey("mod+k", func() { palette.Set(true) })
cx.SetLocale("de")
cx.OnQuit(func(ctx context.Context) { saveDraft(ctx) })
```

`cx.Env().DeviceName()` — это имя, которое пользователь дал устройству, а `cx.Env().DeviceModel()` — его аппаратная модель, например `Mac15,7`, `iPhone15,2` или `Google Pixel 8`, чтобы приложение могло различить два сопряжённых устройства. macOS, Android, Windows и Linux выдают оба значения; iOS выдаёт модель, а имя — только приложению с entitlement Apple на имя устройства, назначенное пользователем. watchOS выдаёт свой аппаратный идентификатор, HarmonyOS — своё рыночное название или модель продукта, а мини-программы — марку и модель платформы; эти цели оставляют назначенное пользователем имя пустым. Веб не выдаёт ни того, ни другого. Тесты задают их через `nsgotest.Environment`.

`cx.Env().ThermalState()` сообщает `core.ThermalNominal`, `ThermalFair`, `ThermalSerious` или `ThermalCritical` на платформах Apple и Android API 29 или новее. `cx.Env().LowPowerMode()` сообщает `core.LowPowerOn` или `LowPowerOff` на платформах Apple, Android, Windows и в сеансах Linux с power-profiles-daemon. Там, где система не выдаёт значения, чтения возвращают `ThermalUnknown` и `LowPowerUnknown`. Каждое чтение независимо следует за изменениями, поэтому приложение может подстраивать свою нагрузку во время работы. В тестах задавайте `ThermalState` и `LowPowerMode` в `core.Environment` через `nsgotest.Environment` или `app.SetEnvironment`.

`desktop.CursorPoint(cx, func(p core.Point, available bool) { ... })` читает положение указателя даже за пределами окон приложения на macOS, Windows и X11. Каждый вызов получает одно значение. Точка задаётся в тех же экранных координатах, что и `desktop.Monitors(cx)` и `Window.ShowAt`. В Wayland и на других неподдерживаемых целях, а также если у области видимости нет `core.AccessCursorPoint`, `available` равно false.

`desktop.SetWindowConstraints` ограничивает размер содержимого и управляет изменением размера, сворачиванием и разворачиванием; задайте `WindowOptions.Constraints` при открытии окна или используйте `nsgo.WindowConstraints` для главного окна. Linux применяет нефиксированные максимумы в X11 и убирает запрещённые кнопки сворачивания и разворачивания из нативного заголовка GTK в X11 и Wayland. Wayland пока поддерживает для верхней границы только фиксированные размеры.

`desktop.SetWindowLevel` поднимает окно над остальными, а `desktop.SetWindowWorkspaces(cx, desktop.WindowWorkspacesAll)` или `WindowOptions.Workspaces` держат его на каждом рабочем пространстве, как настольного питомца, HUD или таймер: на macOS — на каждом Space и поверх полноэкранных пространств других приложений, вне переключения по Cmd-`, а на Linux — на каждом виртуальном рабочем столе оконного менеджера X11. Windows и Wayland оставляют его на том пространстве, где оно открылось, а `desktop.CanSetWindowWorkspaces` сообщает, действует ли это: true на macOS и под оконным менеджером X11, поддерживающим `_NET_WM_DESKTOP`. Главное окно попадает на все рабочие пространства, если вызвать `desktop.SetWindowWorkspaces` из его содержимого. В тестах `nsgotest.App.Window` перечисляет запросы, а `nsgotest.Environment` задаёт `CanSetWindowWorkspaces`.

`desktop.RegisterHotKey` привязывает глобальное сочетание клавиш, которое работает, когда на переднем плане любое приложение, — на macOS, на Linux и в приложении Windows, запущенном с `nsgo.Run(App)`. `State` его дескриптора сообщает, приняла ли его система: `HotKeyPending`, пока она не ответит, затем `HotKeyRegistered`, `HotKeyTaken`, если сочетание занято другой регистрацией, или `HotKeyUnsupported` для клавиши или платформы без глобальных сочетаний, чтобы средство записи сочетаний могло попросить другое. На macOS сочетание считается занятым, только если приложение уже удерживает его или другое приложение зарегистрировало его монопольно. В Wayland композитор просит пользователя назначить сочетание: оно регистрируется, когда пользователь это сделал, и считается занятым, если пользователь или композитор его не назначили. В тестах `nsgotest.HotKeyTaken` и `nsgotest.HotKeyUnsupported` заставляют сочетания отвечать именно так.

С `desktop.TitleBarHidden` Windows и Linux предлагают меню приложения как всплывающее меню при нажатии и отпускании одной клавиши Alt или по F10. Alt с первой буквой или цифрой метки верхнего уровня открывает это подменю или выбирает эту команду в письменности метки. Привязки приложения сохраняют свои клавиши; Shift+F10 остаётся клавишей контекстного меню, а другие сочетания с Alt остаются за системой. Escape закрывает всплывающее меню и возвращает фокус клавиатуры.

```go
shortcut := desktop.RegisterHotKey(cx, "alt+space", launcher.Toggle)
warning := core.Text{ContentFunc: func() string {
	if shortcut.State() == desktop.HotKeyTaken {
		return "Another app uses Alt+Space"
	}
	return ""
}}
```

При изменении размера на настольных системах macOS, Windows и Linux ждут новую раскладку до 16 мс перед отрисовкой. Делайте реактивные вычисления и обработчики событий быстрыми, чтобы раскладка укладывалась в этот срок; выполняйте медленный ввод-вывод в горутине и передавайте результаты через `cx.Post`. Занятое приложение продолжает изменять размер и показывает свою раскладку, когда догоняет.

`desktop.SetWindowFrame` перемещает окно, если `WindowFrame.Move` равно true, используя `X` и `Y` в точках от левого верхнего угла главного экрана. Незаданные размеры сохраняют текущие значения. Проверяйте `desktop.CanPlaceWindows`: позиционирование поддерживают macOS, Windows и Linux в X11; обычное окно верхнего уровня Wayland сохраняет позицию, заданную композитором. `desktop.Frame` следует за положением нативного окна на этих настольных системах.

На macOS и Windows `WindowFrame{Animated: true}` плавно переводит видимую панель в новую рамку, включая размер пристыкованной панели. Для скрытых панелей и при уменьшенном движении новая рамка применяется сразу. Обычные окна macOS используют анимацию AppKit.

Задайте в `desktop.WindowOptions.Parent` открытое окно приложения, чтобы оба закрывались, когда закрывается родительское. На настольных системах дочернее окно остаётся над родительским и следует за ним, когда то скрывается или сворачивается; явно скрытое дочернее окно остаётся скрытым, когда родительское возвращается. На macOS оно также центрируется над родительским, если `Frame` не задан, и переходит вслед за ним в полноэкранный режим.

`WindowOptions.NoShadow` и `desktop.SetWindowShadow(cx, false)` также убирают тень у окна Windows со скрытым заголовком, которое само рисует своё оформление; окно с системным заголовком сохраняет рамку и тень, как и окно Linux, которое оформляет его оконный менеджер, — там `NoShadow` убирает лишь тень собственного оформления GTK.

`desktop.SetWindowPointerEvents` пропускает указатель сквозь окно к окнам под ним, любого приложения: `WindowPointerNone` — везде, как это делает HUD, а `WindowPointerPainted` — там, где ни одно представление ничего не рисует и не слушает указатель, как вокруг настольного питомца, который всё же принимает нажатия, перетаскивания и правые щелчки по себе; заголовок, который рисует система, считается пустым местом. `WindowOptions.PointerEvents` и `PanelOptions.PointerEvents` открывают окно в таком режиме. Область `Desktop.WindowDrag` по-прежнему перетаскивает окно внутри нажимаемого предка; более близкий нажимаемый или редактируемый элемент управления сохраняет собственный ввод вместо перетаскивания окна. Окно, которое не принимает указатель, не получает нажатий, поэтому приложение возвращает ему эту возможность из сочетания клавиш, значка в трее или другого окна. Коду, которым владеет `Access`, нужен `core.AccessOverlay`.

```go
desktop.OpenPanel(cx, desktop.PanelOptions{Width: 600, Height: 400, PointerEvents: desktop.WindowPointerPainted}, Pet)
```

На macOS и Windows изображение в окне с режимом painted может задать `Image.HitTestAlpha` (TSX `hitTestAlpha`) значением больше 0 и не больше 1. Например, 0.5 принимает указатель на пикселях изображения, непрозрачных как минимум наполовину. Этот порог также применяется к `OnPress` изображения. Фон или граница представления по-прежнему считаются нарисованными. Ноль использует всё представление изображения, как и изображения на Linux.

В окне macOS с режимом painted `Video.HitTestAlpha` (TSX `hitTestAlpha`) применяет тот же порог к декодированным кадрам видео. Он работает при выключенных `Controls` и непреобразованной видеодорожке, например HEVC с альфа-каналом для настольного питомца. При нуле, недоступном кадре и на других настольных хостах используются границы представления видео.

`desktop.NewTray` может рисовать живой значок с `TrayOptions.View` на macOS и Windows. Windows подгоняет прозрачную отрисовку представления под размер значков области уведомлений и обновляет её, когда представление меняется или изображение заканчивает загрузку; используйте `TrayOptions.OnClick`, `Panel` и `Menu` для его действий. Linux пока показывает значки PNG; отрисовка представления в трее остаётся целью.

`desktop.OpenPanel` открывает панель, которую показывает такое сочетание клавиш или значок в трее: окно без рамки над остальными. Как и `desktop.OpenWindow`, `desktop.NewTray`, `mobile.OpenOverlay`, `audio.NewPlayer`, `audio.LoadSound` и `core.NewHolder`, она принадлежит непосредственно переданному `cx`, а не владельцу выполняющегося обработчика, поэтому передача области видимости приложения из `OnPress` кнопки сохраняет окно, панель или проигрыватель живыми после того, как область видимости этой кнопки исчезнет; реактивные примитивы (`Effect`, `Cleanup`, `AfterFunc`, `OnKey`), напротив, принадлежат выполняющемуся владельцу, которого переключает `cx.Run`. Всплывающая карточка рисует себя на панели с `Transparent`, у которой нет собственного фона, рамки или тени, поэтому видны только скруглённые углы карточки и `BoxShadow`, с местом для тени внутри панели; `FitContent` подгоняет размер панели под содержимое, вплоть до `Width` и `Height`, перед первым показом и при изменении содержимого. `desktop.Transparent` сообщает, не рисует ли панель сейчас ничего своего, как прозрачное окно, тогда как `desktop.CanMakeWindowsTransparent` лишь сообщает, может ли окно быть прозрачным: там, где это false, как на Linux без композитора, задайте содержимому фон.

На macOS панель без `Transparent` использует прямые углы, если любой из размеров меньше 24 точек, и восстанавливает скруглённые углы при обычных размерах.

```go
lookup := desktop.OpenPanel(cx, desktop.PanelOptions{Width: 380, Height: 520, Transparent: true, FitContent: true, HideOnBlur: true}, Card)
desktop.RegisterHotKey(cx, "alt+space", lookup.Toggle)
```

`desktop.NewTray` показывает `TrayOptions.Title` рядом со своим изображением или нарисованным представлением на macOS. Для собственного всплывающего окна прочитайте `tray.ClickBounds()` внутри `OnClick` или `Menu` и передайте доступный прямоугольник в `panel.ShowAt(bounds, core.PlaceBottom)`. Он использует те же экранные точки, что и `Env.Displays`, и включает заголовок. Границы недоступны до первого щелчка, после удаления, на Linux и когда оболочка Windows не может их предоставить. Каждый щелчок заменяет предыдущие границы, поэтому недоступный результат никогда не использует старый прямоугольник. Если задать `TrayOptions.Panel`, вместо этого сохраняется встроенное переключение по щелчку.

`PanelOptions.Dock` удерживает панель по центру вдоль пригодного края дисплея при `Show`, `Focus`, `Toggle` и изменении размера содержимого. Задайте `Edge` как `core.PlaceTop`, `PlaceBottom`, `PlaceLeft` или `PlaceRight`, `Display` — как ID из `Env.Displays` (пусто для основного дисплея), а `Margin` — как расстояние от этого края в точках. Пристыкованная панель не может использовать `ShowAt` или `MoveTo`; `SetWindowFrame` меняет только её размер. Значок в трее показывает её в месте пристыковки, а не под значком.

```go
panel := desktop.OpenPanel(cx, desktop.PanelOptions{
	Width: 320, Height: 80, NoActivate: true,
	Dock: desktop.PanelDock{Edge: core.PlaceBottom, Margin: 12},
}, Candidates)
panel.OnPlacementError(cx, func(err error) { /* offer another presentation */ })
panel.Show()
```

`desktop.CanDockPanels(cx)` сообщает о поддержке пристыковки отдельно от произвольного размещения окон. Её поддерживают macOS, Windows и X11; Wayland нужна необязательная библиотека времени выполнения `libgtk4-layer-shell.so.0` и композитор, реализующий `zwlr_layer_shell_v1`. NSGo загружает эту библиотеку раньше GTK; встраивающий хост, который уже загрузил Wayland, должен предварительно загрузить gtk4-layer-shell до запуска хоста. Отсутствие библиотеки, протокола или выбранного дисплея оставляет панель скрытой и вызывает `OnPlacementError`. Пристыковка в Wayland использует верхний слой, не резервируя рабочую область: `NoActivate` оставляет клавиатуру текущему окну, а панель без него получает монопольный фокус клавиатуры, пока не будет скрыта. Обычные окна Wayland сохраняют привычное размещение композитором.

Средство записи сочетаний позволяет пользователю выбрать такую клавишу. `OnKeyDown` представления `Focusable` получает каждую нажатую клавишу, пока у него фокус, раньше привязок приложения, вместе с удерживаемыми модификаторами, включая модификатор, нажатый в одиночку; возврат `true` не пускает клавишу к привязкам, поэтому запись Command+S не сохраняет файл. `KeyEvent.Shortcut` записывает нажатие так, как его принимают `OnKey` и `RegisterHotKey`, каждый модификатор по имени ("ctrl+shift+k", "alt+space", "shift+meta+k" для Command+Shift+K), и "" для одиночного модификатора. Его `OnKeyUp` получает отпускание каждой из этих клавиш, даже после того как `OnKeyDown` поглотил её или фокус переместился, вместе с ещё удерживаемыми модификаторами. Оба работают на macOS, Windows, Linux, в вебе, где браузер оставляет себе сочетания, которые не отдаёт странице, на Apple TV и в `nsgotest`; Android доставляет события аппаратной клавиатуры представлениям в фокусе асинхронно, поэтому возвращаемое значение их `OnKeyDown` не может поглотить клавишу. iPhone и iPad поддерживают опрос аппаратных клавиш. Сочетание, которое приложение зарегистрировало глобально, получает свою клавишу раньше представления, поэтому средство записи снимает его регистрацию на время записи.

```go
core.View{
	Focusable: func() bool { return true },
	OnKeyDown: func(e core.KeyEvent) bool {
		if s := e.Shortcut(); s != "" {
			shortcut.Set(s)
		}
		return true
	},
	OnKeyUp: func(core.KeyEvent) { recording.Set(false) },
	Children: []core.Node{core.Text{ContentFunc: shortcut.Get}},
}
```

Игра или холст вместо этого опрашивают клавиши. `core.KeysDown(cx)` перечисляет клавиши, удерживаемые в окне, а `core.KeyHeld(cx, "left")` сообщает, удерживается ли конкретная: это отслеживаемые чтения, которые читает и цикл `RequestAnimationFrame`. Первое чтение заставляет платформу с этого момента сообщать о каждой клавише, поэтому уже удерживаемая клавиша остаётся неизвестной, пока её не нажмут снова; клавиши, набранные в поле или веб-представлении или во время составления текста методом ввода, никогда не считаются удерживаемыми, а клавиша, всё ещё удерживаемая в момент потери окном фокуса, в этот момент считается отпущенной. Они работают там же, где `OnKeyUp`, а также на iPhone и iPad с аппаратной клавиатурой.

Для кнопок мыши `View.OnMouseDown` и `View.OnMouseUp` доставляют `core.MouseButtonEvent` для каждой кнопки (`core.MouseButtonLeft`, `core.MouseButtonRight`, `core.MouseButtonMiddle`, `core.MouseButtonBack`, `core.MouseButtonForward`) на macOS, Windows, Linux, в вебе и в `nsgotest`, не делая представление точкой остановки фокуса клавиатуры. `core.MouseButtonsDown(cx)` и `core.MouseButtonHeld(cx, core.MouseButtonRight)` — это отслеживаемые чтения кнопок, удерживаемых в окне, которые автоматически сбрасываются, когда окно теряет фокус.

Для элемента управления, привязанного к физическому положению клавиши, читайте `KeyEvent.Code`, `core.KeyCodesDown(cx)` или `core.KeyCodeHeld(cx, "KeyW")`. Код использует имена `KeyboardEvent.code`: в раскладке AZERTY позиция W из QWERTY имеет `Code: "KeyW"` и `Key: "z"`. `core.KeyCodeLabel(cx, "KeyW")` выдаёт отображаемую метку активной раскладки для подсказки. На iOS, Android, HarmonyOS и в браузерах без карты раскладки используется последнее имя клавиши, сообщённое в этой позиции, а до того, как клавиша будет замечена, возвращается пустая строка. HarmonyOS называет и позицию, и клавишу по `KeyCode` из InputKit, поскольку ArkUI не сообщает скан-код, поэтому там имя клавиши пока не следует раскладке, отличной от QWERTY.

```go
var loop func(time.Time)
loop = func(time.Time) {
	if core.KeyHeld(cx, "left") {
		x.Update(func(x float32) float32 { return x - 4 })
	}
	if core.KeyHeld(cx, "right") {
		x.Update(func(x float32) float32 { return x + 4 })
	}
	cx.RequestAnimationFrame(loop)
}
cx.RequestAnimationFrame(loop)
```

## Поддержание экрана включённым

`cx.KeepAwake("Playing video", core.KeepAwakeOptions{Display: true})` удерживает экран включённым, пока не будет вызвана возвращённая функция освобождения или не будет освобождена текущая область видимости. На Android удержание действует, пока приложение видимо. В вебе оно работает в безопасном контексте с поддержкой Screen Wake Lock, и страница снова запрашивает блокировку, когда становится видимой. Safari может потребовать нажатия или клавиши, прежде чем удовлетворить первый запрос. Удержания только для компьютера на этих двух платформах не действуют.

## Захват указателя

Для игровой камеры или перетаскивания, которое должно продолжаться у края экрана, вызовите `ref.LockPointer()` из нажатия на представление, которое содержит ref. Указатель остаётся на месте и скрыт, а представление получает относительное перемещение в `OnPointerDelta(dx, dy)`. Положительные значения означают движение вправо и вниз.

Вызовите возвращённую функцию, чтобы снять захват. Escape, потеря окном фокуса, а также скрытие или удаление представления тоже снимают его. Проверяйте `cx.Env().CanLockPointer()`, чтобы узнать, поддерживает ли его поверхность. Веб требует жеста пользователя, например нажатия. Linux в Wayland требует композитора, поддерживающего ограничения указателя и относительное перемещение.

## Ограничения звуков

Используйте `audio.SetSoundLimits(cx, audio.SoundLimits{MaxSounds: 200, MaxDuration: 20 * time.Second})` перед загрузкой звуков, чтобы изменить ограничения движка. Также можно задать `MaxEncodedBytes`, `MaxDecodedBytes` и `MaxPlaybacks`. Нулевые поля используют значения по умолчанию: 8 MiB в закодированном виде и 5 секунд на звук, 64 источника, 16 MiB в декодированном виде на все звуки и 32 одновременных воспроизведения на вывод. Существующие звуки остаются загруженными и учитываются в новых ограничениях. Ограниченные области видимости сохраняют ограничения по умолчанию в пределах бюджета движка: звуки `nsgo/audio` подписанного пакета TSX упираются в них независимо от того, что задало приложение на Go, тогда как собственный TSX приложения получает ограничения приложения на Go. SoundPool в Android воспроизводит одновременно не более 32 звуков и декодирует не более 1 MiB каждого, независимо от ограничений.

## Полноэкранный режим

`desktop.SetFullScreen(cx, true, displayID)` заполняет дисплей, названный в `cx.Env().Displays()`, на macOS, Windows и Linux. Опустите ID, чтобы использовать текущий дисплей окна. Неизвестный ID оставляет окно на месте. Повтор того же запроса ни на что не влияет. `desktop.SetFullScreen(cx, false)` выходит из полноэкранного режима и восстанавливает прежнюю рамку окна. В вебе входите в режим из обработчика нажатия. Дисплей выбирает браузер, а `cx.Env().FullScreen()` следует за входом и выходом, включая Esc.

## Дисплеи

`cx.Env().Display()` возвращает текущий `core.DisplayInfo` окна и обновляет привязки, когда окно перемещается на другой дисплей. `cx.Env().Displays()` перечисляет дисплеи, о которых сообщает платформа. `RefreshRate` и `MaxRefreshRate` указаны в Гц, ноль означает недоступную частоту. iOS сообщает максимум панели. HarmonyOS сообщает дисплей окна, его текущую частоту и наибольшую поддерживаемую частоту. Веб сообщает текущий экран и помечает своё измерение по обратным вызовам кадров с помощью `RefreshRateEstimated`. В тестах задавайте `Displays` и `DisplayID` через `nsgotest.Environment`.

## Озвучивание текста

`cx.Speak` читает текст вслух системным голосом для языка там, где `cx.Env().CanSpeak()` сообщает, что платформа умеет говорить: на macOS, iOS, tvOS, Android, Windows, в вебе и в Linux со speech-dispatcher. Одновременно звучит только одно высказывание: другой вызов `Speak` прерывает звучащее, как и `cx.StopSpeaking` и завершение области видимости, которая его произнесла. `done` один раз узнаёт, как оно закончилось: завершилось, было остановлено или не удалось с `core.SpeakError`, например `core.SpeakLanguageUnavailable`, если ни один установленный голос не говорит на этом языке.

```go
cx.Speak("Guten Morgen", core.Voice{Lang: "de-DE", Rate: 0.8}, func(stopped bool, err error) {
	speaking.Set(false)
})
```

`Rate` и `Pitch` принимают значения от 0.5 до 2, где 1 — собственные параметры голоса. `cx.Voices("ja", ...)` перечисляет голоса, установленные для языка, чтобы приложение могло попросить пользователя установить недостающий или дать ему выбрать голос, `ID` которого передаётся в `core.Voice`. Браузеры говорят только после того, как пользователь что-нибудь нажал на странице, а до этого завершаются ошибкой `core.SpeakNotAllowed`. Компоненты Go пакета TSX говорят только при наличии возможности `text_to_speech`.

## Зацикленное аудио

Задайте `audio.Voice.Loop`, чтобы повторять воспроизведение звука до `Stop` или `Close`. Для потоковой музыки задайте `audio.PlayerOptions.LoopStart` и вызовите `SetLoop(true)`. Первый проход включает вступление. Последующие проходы начинаются со смещения. Нулевое смещение повторяет весь трек.

На macOS 14 и iOS 17 или новее конечный трек использует нативную очередь, чтобы подготовить каждое повторение до окончания текущего. Более ранние версии Apple перематывают к началу цикла, когда заканчивается текущий проход, с короткой паузой. На Linux и в вебе зацикленный проигрыватель декодирует трек размером до 32 MiB и длительностью до 5 минут в память — около 23 МБ на минуту — и повторяет его без паузы. На Linux более крупный или длинный трек передаётся потоком через собственный декодер и тоже повторяется без паузы; в вебе он перематывается назад в конце с короткой паузой. На Windows и Android цикл с началом перематывается к нему в конце с короткой паузой. В вебе зацикленный проигрыватель со скоростью, отличной от 1, тоже перематывается назад в конце, поскольку воспроизведение браузера без пауз сдвигало бы высоту тона вместе со скоростью. В вебе зацикленный проигрыватель, как и звук, воспроизводится только после того, как пользователь что-нибудь нажал на странице, а до этого завершается ошибкой `NotAllowed`.

## Биометрия

`cx.BiometricAvailability` сообщает, зарегистрированы ли Face ID, Touch ID или отпечаток пальца на устройстве; Android не сообщает, какой вид зарегистрирован, поэтому там сообщается отпечаток пальца, если он зарегистрирован, а иначе — лицо, если у устройства есть оборудование для распознавания лица. `cx.AuthenticateBiometric` просит систему подтвердить пользователя с указанием причины, которая не должна быть пустой, и сообщает об успехе, неудаче, отмене или недоступности. Он не выбирает за приложение запасной вариант с кодом-паролем.

```go
cx.BiometricAvailability(func(kind core.BiometricKind) {
	if kind != core.BiometricNone {
		cx.AuthenticateBiometric("Confirm deleting this account", func(result core.BiometricResult) {
			if result == core.BiometricSuccess {
				deleteAccount()
			}
		})
	}
})
```

Приложения с Face ID объявляют `NSFaceIDUsageDescription` в `apple.info`; приложения Android перечисляют `USE_BIOMETRIC` в `android.permissions`.

## Вход в систему

`cx.AuthSession` выполняет вход пользователя через поставщика OAuth в системном сеансе аутентификации, а не в веб-представлении: `ASWebAuthenticationSession` на macOS, iOS и watchOS, Custom Tab или браузер на Android, браузер по умолчанию на Windows, Linux и на Mac без схемы, а также всплывающее окно в вебе. В вебе страница перенаправления также отправляет свой обратный вызов через `BroadcastChannel` того же источника, поэтому вход завершается, даже когда `Cross-Origin-Opener-Policy` поставщика отрезает всплывающее окно от страницы. Такое всплывающее окно выглядит для страницы закрытым, поэтому закрытие всплывающего окна после того, как оно показало страницу поставщика, завершает сеанс как отменённый лишь через 5 минут; дайте сеансу кнопку отмены. Протоколом занимается приложение: оно создаёт верификатор PKCE и state, строит URL авторизации для переданного ему перенаправления и проверяет обратный вызов, прежде чем обменять его код. Отмена не является неудачей: `errors.Is(err, core.AuthCancelled)` распознаёт закрытие сеанса пользователем или его завершение возвращённой функцией `cancel`.

```go
verifier, challenge, state := newPKCE() // the app's own
cx.AuthSession(func(redirect string) string {
	q := url.Values{"client_id": {clientID(redirect)}, "redirect_uri": {redirect}, "response_type": {"code"}, "scope": {"openid email"},
		"state": {state}, "code_challenge": {challenge}, "code_challenge_method": {"S256"}}
	return "https://accounts.example.com/authorize?" + q.Encode()
}, core.AuthSessionOptions{Scheme: "com.example.app", Path: "/oauth2redirect", Timeout: 5 * time.Minute}, func(callback string, err error) {
	if errors.Is(err, core.AuthCancelled) {
		return
	}
	if err != nil {
		showError(err)
		return
	}
	u, _ := url.Parse(callback)
	if u.Query().Get("state") == state {
		exchangeCode(u.Query().Get("code"), verifier)
	}
})
```

Перенаправление имеет вид `com.example.app:/oauth2redirect`, если задана схема (Windows, Linux и Android нужна эта схема в `url_schemes` в `nsgo.yaml`, чтобы ОС передала обратный вызов запущенному приложению; системный сеанс macOS, iOS и watchOS перехватывает его без такого объявления), и `http://127.0.0.1:<port>/oauth2redirect` для loopback на настольных системах, поэтому зарегистрируйте оба у поставщика, часто как отдельных клиентов. Оставьте `Scheme` пустым только для loopback или задайте `https` вместе с `Host` для связанного домена приложения, который перехватывают iOS 17.4, macOS 14.4 и watchOS 10.4. watchOS требует схему или связанный домен HTTPS; запасного варианта с loopback там нет, и действующий минимум NSGo watchOS 26 по-прежнему применяется. Закрытая вкладка браузера ничего не сообщает сеансу loopback, поэтому задайте ему `Timeout` или кнопку отмены. `Ephemeral` просит macOS, iOS и watchOS не разделять cookie браузера и запрашивает приватный Custom Tab на Android, если браузер его поддерживает; не рассчитывайте на изоляцию cookie на Android. tvOS и мини-программы пока отвечают `core.AuthUnavailable`. В TSX `AuthSession.start(url, options)` требует возможности `auth_session` и выдаёт сеанс, чей `result` разрешается обратным вызовом или null после отмены.

Android обрабатывает подходящий обратный вызов раньше обычного `OnOpenLinks`, а возврат без обратного вызова завершает сеанс как отменённый. Его обратный вызов должен использовать частную схему, принадлежащую приложению; пустая схема, обратный вызов HTTPS или необъявленная схема возвращают `core.AuthUnavailable`, как и среда выполнения Android, собранная до появления сеансов входа.

Сеанс браузера обрабатывает только подходящую ему ссылку обратного вызова; посторонние и запоздавшие ссылки по-прежнему доходят до `OnOpenLinks`. Запуск ещё одного сеанса браузера для того же URI обратного вызова отменяет предыдущий; разные URI могут ожидать в разных окнах.

Используйте в точности то перенаправление, которое передано функции URL авторизации. Перенаправления loopback в вебе и на настольных системах кодируют пути с Unicode и разрешают сегменты с точками до того, как их получит функция; `Path` для loopback — это декодированный текст, поэтому буквальный `%` тоже экранируется.

Мини-программы вместо этого используют `cx.SignInMiniProgram(core.MiniProgramSignInOptions{}, done)`. Функция обратного вызова получает `core.MiniProgramCredential` с его `Platform` (`MiniProgramWeChat`, `MiniProgramQQ`, `MiniProgramDouyin` или `MiniProgramAlipay`) и непустым краткоживущим `Code`. Отправьте его на свой сервер для обмена кода у хоста; храните секрет приложения там. Это `wx.login`/`qq.login`/`tt.login` или базовая авторизация `auth_base` в Alipay без запроса сведений профиля. Он не открывает URL и не запускает построитель URL OAuth.

`cx.Env().CanSignInMiniProgram()` сообщает о доступности API хоста. Другие цели отвечают `core.MiniProgramSignInUnavailable`; код без `core.AccessMiniProgramSignIn` получает `AccessDenied`. Douyin по умолчанию запрашивает без интерфейса: хост без выполненного входа возвращает `MiniProgramSignInNotSignedIn`, а `MiniProgramSignInOptions{Prompt: true}` разрешает его окно входа в учётную запись хоста. Закрытие этого окна возвращает `MiniProgramSignInCancelled`. Анонимный код устройства никогда не считается пользователем, выполнившим вход. Тесты задают `nsgotest.Environment(core.Environment{MiniProgramSignIn: true})` и `app.MiniProgramSignIn`; `app.MiniProgramSignIns` записывает запросы. TSX не выполняется в мини-программах.

Приложение, чьи веб-представления должны быть авторизованы так же, как пользователь уже авторизован в другом месте, например в собственном браузере, записывает cookie этого входа с помощью `cx.SetWebCookies`, включая HttpOnly, которые сценарии страницы установить не могут, а затем загружает страницы: done выполняется, когда хранилище их содержит. Это постоянное хранилище, общее для всех веб-представлений приложения, поэтому cookie с `Expires` переживают приложение; представления в режиме инкогнито их не видят, кроме как на Android, где одно хранилище на приложение. HarmonyOS, веб, tvOS и watchOS отвечают `Unavailable`.

```go
cx.SetWebCookies([]core.WebCookie{
	{Name: "SID", Value: sid, Domain: ".example.com", Expires: expires, Secure: true, HTTPOnly: true},
}, func(err error) {
	if err == nil {
		page.Set(core.WebSrc("https://www.example.com/"))
	}
})
```

Чтобы удалить один cookie, запишите его снова с тем же именем, доменом и путём и с `Expires` в прошлом; нулевой срок действия создаёт сеансовый cookie. Дождитесь обратного вызова, прежде чем загружать страницу, которая должна увидеть удаление.

В обратную сторону, `cx.WebCookies` перечисляет cookie хранилища, включая HttpOnly и их домен, путь, срок действия и флаги, которые не может прочитать `document.cookie`, независимо от того, показывается ли страница сайта: `core.WebCookieFilter` выбирает те, которые отправил бы запрос к `URL`, или те, что относятся к `Domain` и всем хостам под ним, а нулевой фильтр — все. Приложение, которое обращается к сайту из Go с данными входа пользователя или показывает, где пользователь авторизован, читает их именно так. `cx.ClearWebsiteData` выполняет выход пользователя со всех сайтов: удаляет cookie хранилища, локальное и сеансовое хранилище, IndexedDB, service workers и кэши, а done выполняется, когда всё это удалено. `CookieManager` в Android отвечает только именами и значениями, которые отправил бы URL, поэтому там выдаёт список только фильтр `URL`, заполняя `Domain` его хостом и оставляя остальные поля пустыми, а фильтр `Domain` или нулевой фильтр отвечают `Unavailable`; очистка там оставляет HTTP-кэш. HarmonyOS, веб, tvOS и watchOS отвечают `Unavailable` на оба вызова.

```go
cx.WebCookies(core.WebCookieFilter{Domain: "example.com"}, func(cookies []core.WebCookie, err error) {
	signedIn.Set(err == nil && slices.ContainsFunc(cookies, func(c core.WebCookie) bool { return c.Name == "SID" }))
})
```

## Вход с Apple

`cx.SignInWithApple` показывает системный лист «Вход с Apple» по нажатию собственной кнопки приложения на macOS, iOS и tvOS, где `cx.Env().CanSignInWithApple()` равно true. Он отвечает один раз учётными данными или ошибкой: `core.AppleSignInCancelled`, если пользователь закрыл лист, что не является неудачей, иначе `AppleSignInFailed` или, на других платформах, `AppleSignInUnavailable`. Apple выдаёт адрес электронной почты и имя только при первом входе пользователя в приложение, поэтому сохраните их в этот момент. `Nonce` попадает в запрос в виде своего SHA-256 в шестнадцатеричной записи в нижнем регистре, который содержит утверждение `nonce` токена удостоверения: сервер хеширует nonce, который он выдал приложению, и сравнивает. `cx.AppleCredentialState` сообщает, не отозвал ли пользователь их с тех пор. В тестах без интерфейса `app.AppleSignIn` получает `nsgotest.AppleSignInRequest` и предоставляет учётные данные или ошибку.

```go
nonce := rand.Text() // also sent to the server, which checks the token's claim against its SHA-256
cx.SignInWithApple(core.AppleSignInOptions{FullName: true, Email: true, Nonce: nonce}, func(c core.AppleCredential, err error) {
	switch {
	case errors.Is(err, core.AppleSignInCancelled):
	case err != nil:
		showError(err)
	default:
		signInOnServer(c.IdentityToken, c.AuthorizationCode, nonce, c.GivenName, c.FamilyName, c.Email)
	}
})
cx.AppleCredentialState(savedUser, func(s core.AppleCredentialState, err error) {
	if err == nil && s == core.AppleCredentialRevoked {
		signOut()
	}
})
```

Приложение должно быть подписано с entitlement Sign in with Apple, которое `build` добавляет, когда его запрашивает `nsgo.yaml`; без него лист завершается ошибкой:

```yaml
apple:
  sign_in_with_apple: true  # com.apple.developer.applesignin, in iOS and tvOS packages and Mac App Store builds
```

Xcode регистрирует эту возможность для сборок на устройства из `nsgo dev`; профиль обеспечения в `sign.profile` или `sign.macos_profile` должен происходить от App ID с включённым Sign in with Apple. macOS предоставляет её только с профилем, поэтому образ диска или запуск `nsgo dev` на Mac не могут выполнить вход, как и симулятор, сборки для которого не заявляют entitlements разработчика.

## Встроенные покупки

`cx.Products`, `cx.Purchase` и сопутствующие вызовы продают через App Store на macOS, iOS и tvOS, где `cx.Env().CanPurchase()` равно true, в сборке, чей `nsgo.yaml` запрашивает StoreKit:

```yaml
apple:
  purchases: true  # StoreKit's library, in macOS, iOS and tvOS packages; no entitlement is needed
```

Показывайте цены, которые выдаёт магазин, `DisplayPrice`, и никогда — собственные цены приложения: магазин сам назначает цену для каждой витрины. Покупка отвечает один раз транзакцией или ошибкой: `core.PurchaseCancelled`, если пользователь закрыл лист, `core.PurchasePending`, пока она ожидает одобрения, как при «Попросить купить», а иначе `core.PurchaseFailed` со словами магазина или `PurchasesUnavailable` на других платформах. Отправьте `Signed` транзакции, то есть JWS магазина, на сервер приложения для проверки, выдайте купленное, а затем завершите её; магазин снова передаёт незавершённую транзакцию приложению при каждом запуске.

`cx.ManageSubscriptions` открывает интерфейс управления подписками Apple (системный лист на iOS, страницу подписок App Store на macOS и tvOS). `cx.RequestRefund` начинает запрос возврата средств для транзакции и отвечает `core.RefundSuccess` или `core.RefundCancelled`.

```go
cx.OnPurchaseUpdate(func(t core.Transaction) { // renewals, approved purchases, other devices', refunds, and unfinished ones at launch
	verifyAndDeliver(t.Signed, func() { cx.FinishTransaction(t.ID, nil) })
})
cx.Products([]string{"com.example.pro.monthly"}, func(products []core.Product, err error) {
	if err == nil && len(products) > 0 {
		price.Set(products[0].DisplayPrice)
	}
})
cx.Purchase("com.example.pro.monthly", core.PurchaseOptions{AccountToken: userUUID}, func(t core.Transaction, err error) {
	switch {
	case errors.Is(err, core.PurchaseCancelled):
	case errors.Is(err, core.PurchasePending):
		showWaiting() // its transaction comes through OnPurchaseUpdate
	case err != nil:
		showError(err)
	default:
		verifyAndDeliver(t.Signed, func() { cx.FinishTransaction(t.ID, nil) })
	}
})
```

`FinishTransaction` возвращает `PurchaseNotFound` для уже завершённой транзакции, включая ту, что вернул `CurrentEntitlements`; завершённая нерасходуемая покупка остаётся во владении.

Регистрируйте `OnPurchaseUpdate` при запуске приложения: обновления, пришедшие раньше любого обработчика, ждут первого. `cx.CurrentEntitlements` отвечает, чем пользователь владеет сейчас, чтобы разблокировать это при запуске, а кнопка «Восстановить покупки» вызывает `cx.SyncPurchases`, который может попросить пользователя войти в систему. `AccountToken` — собственный UUID приложения, который содержат транзакция и серверные уведомления App Store. macOS продаёт только в сборке для Mac App Store, а App Clip не продаёт ничего; Android, watchOS, Windows, Linux, веб и мини-программы пока отвечают `PurchasesUnavailable`. Тестируйте покупки с помощью `nsgotest`, чьи `Products`, `PurchaseAnswer`, `UpdatePurchase` и `UnfinishedTransactions` заменяют магазин. `app.PurchaseRequests` записывает операции магазина как значения `nsgotest.PurchaseRequest`. В TSX модулю `Purchases` нужна возможность `purchases`: `purchase` разрешается в `{ status: "purchased", transaction }`, `"pending"` или `"cancelled"`, а `on("update", listener)` получает обновления.

## Ориентация интерфейса

Вызовите `cx.RequestOrientation(core.OrientationLandscape)` в области видимости полноэкранного проигрывателя, чтобы попросить у iOS, Android, HarmonyOS или браузера альбомную ориентацию. Действует последний запрос, чья область видимости жива. Когда эта область видимости завершается, возобновляется предыдущий запрос или приложение возвращается к своей обычной политике ориентации.

На iOS 16 и новее запрос может повернуть интерфейс сразу. В более старых версиях iOS он ограничивает следующий системный поворот. Приоритет имеет `IOS.SupportedOrientations` показанного модального окна. На Android и HarmonyOS сочетание книжных и альбомных направлений, которое система не может представить, сводится к одному разрешённому направлению, предпочтительно к уже показанному. Android может игнорировать запросы ориентации в режимах больших экранов или нескольких окон.

В веб-приложении вызовите `desktop.ToggleFullScreen(cx)` из обработчика нажатия, который открывает область видимости проигрывателя. Браузер переходит в полноэкранный режим по нажатию, а затем NSGo применяет запрос ориентации проигрывателя. Выход из полноэкранного режима снимает блокировку. Консоль браузера сообщает о неподдерживаемых операциях и отказах.

`nsgotest.App.Orientation` записывает последнюю запрошенную маску, а ноль означает обычную политику ориентации.

## Отзывы в магазине

`cx.RequestReview()` запрашивает внутри приложения окно оценки из App Store на macOS и iOS или из Google Play на Android. `cx.Env().CanRequestReview()` сообщает, доступна ли служба. Магазин решает, показывать ли окно и когда, и не сообщает результата. Для проверки окна Apple используйте сборку для разработки. Сборки TestFlight его подавляют.

Автономные пакеты Android включают Play Review SDK, его активность диалога и запрос видимости Play Store; для их сборки не нужны ни Android SDK, ни JDK. Устройство без включённого Play Store сообщает, что служба недоступна. Проверьте выпущенный пакет с помощью [Internal App Sharing](https://developer.android.com/guide/playcore/in-app-review/test).

При встраивании NSGo добавьте `com.google.android.play:review:2.0.2` в хост Gradle. В манифесте хоста добавьте `<package android:name="com.android.vending" />` в `<queries>`, чтобы приложение видело Play Store. Если хост сжимает свой код, сохраните API Play Review и Tasks с помощью правил ниже, поскольку NSGo загружает их по имени.

```proguard
-keep class com.google.android.play.core.review.ReviewManagerFactory { *; }
-keep interface com.google.android.play.core.review.ReviewManager { *; }
-keep class com.google.android.play.core.review.ReviewInfo { *; }
-keep class com.google.android.gms.tasks.Task { *; }
-keep interface com.google.android.gms.tasks.OnCompleteListener { *; }
```

В тестах задайте `CanRequestReview` в `nsgotest.Environment` и проверяйте `nsgotest.App.ReviewRequests`.

## Системные жесты от края экрана

Игра с сенсорными элементами управления у края экрана может вызвать `mobile.DeferSystemGestures`, пока эти элементы активны. Используйте возвращённую функцию, чтобы снять запрос раньше. Он также завершается, когда очищается его область видимости. Запросы из нескольких областей видимости в одном окне объединяются.

```go
release := mobile.DeferSystemGestures(cx, mobile.SystemGestureOptions{
	IOSEdges: mobile.GestureEdgeBottom,
	AndroidRects: []core.Bounds{{
		Origin: core.Point{Y: 120},
		Size:   core.Size{Width: 24, Height: 96},
	}},
})
```

iOS использует физические края экрана. Android 10 и новее используют прямоугольники в точках поверхности, отсчитываемые от левого верхнего угла. Ограничивайте прямоугольники областью вокруг элементов управления, которым они нужны. Android резервирует свой жест «Домой» и ограничивает площадь, которую приложение может исключить из жеста «Назад». `nsgotest.App.SystemGestures` выдаёт тестам текущий объединённый запрос на их главной поверхности. Для другого окна используйте `Surface.SystemGestures()`.

## Оверлеи на Android

`mobile.OpenOverlay` показывает представление приложения поверх других приложений на Android — собственное дерево, которое разделяет сигналы приложения, — а приоритетная служба поддерживает работу приложения, пока оверлей показан. Приложение перечисляет `SYSTEM_ALERT_WINDOW` в `android.permissions`, а пользователь предоставляет это разрешение в системных настройках, которые открывает `mobile.RequestOverlayPermission`; без него оверлей сразу завершается, а `OnEnd` узнаёт причину. Оверлей принимает касания, но оставляет клавиши и касания вокруг себя приложению на переднем плане, если только он не `Focusable` или `Passive`, и перемещается с помощью `desktop.SetWindowFrame` из своего содержимого. Другие платформы оверлеев не открывают.

```go
mobile.RequestOverlayPermission(cx, func(p core.OverlayPermission) {
	if p == mobile.OverlayGranted {
		mobile.OpenOverlay(cx, mobile.OverlayOptions{Width: 200, Height: 80}, Score)
	}
})
```

## Местоположение и движение

`cx.Locate` получает одно определение местоположения, `cx.WatchLocation` передаёт поток определений, а `cx.WatchMotion` передаёт поток показаний акселерометра, гироскопа, магнитометра и объединённых данных о движении устройства. Каждый из них возвращает `*core.SensorStream`, чей `Stop` отменяет его, как и завершение области видимости, которая его запустила; функции обратного вызова выполняются в горутине движка. Разрешения — `core.PermissionLocation`, `PermissionBackgroundLocation` и `PermissionMotion` ([разрешения](permissions.md)): запуск потока никогда не запрашивает разрешение, а поток без своего разрешения завершается ошибкой `core.SensorNotAllowed`.

```go
cx.RequestPermission(core.PermissionLocation, func(s core.PermissionStatus) {
	if !s.Allowed() {
		return
	}
	cx.Locate(core.LocationOptions{}, func(f core.LocationFix, err error) {
		if err == nil {
			showPosition(f.Latitude, f.Longitude, f.Approximate)
		}
	})
})
```

`Locate` ждёт нового определения, по умолчанию 30 секунд (`Timeout`); только `MaxAge` позволяет взять кэшированное, о чём оно сообщает через `Cached` и `Age`. `Approximate` отмечает определение, которое пользователь разрешил только приблизительно; Android обновляет такое определение не чаще чем раз в десять минут, поэтому там задайте для него `MaxAge` в `Locate`. Координаты указаны в WGS 84; у измерения, которого нет у поставщика, `Valid` равно false, а `Altitude` — эллипсоидальная высота, тогда как `MSLAltitude` — высота над средним уровнем моря. Движение использует естественные оси устройства: ускорение в м/с² (+9.81 по z, когда устройство лежит экраном вверх), вращение в рад/с и магнитное поле в мкТл, по умолчанию каждые 20 мс, в пределах от 10 мс до 1 с. Под нагрузкой поток сохраняет самое новое значение для каждого датчика и считает заменённые в `Dropped`.

Потоки продолжаются, пока приложение неактивно, и приостанавливаются в фоне, помечая первое значение после паузы флагом `Gap`; ожидающий `Locate` сохраняет оставшуюся часть своего тайм-аута. `LocationOptions.Background` продолжает поток местоположения в фоне при наличии `PermissionBackgroundLocation`: приложения Apple добавляют фоновый режим `location`, а на Android приоритетная служба показывает уведомление с `NotificationTitle` и `NotificationBody` и поддерживает работу приложения после завершения его активности. Ничто не запускает процесс, который завершила система.

```yaml
apple:
  info:
    NSLocationWhenInUseUsageDescription: Shows where you are on the map.
    NSLocationUsageDescription: Shows where you are on the map.  # macOS
    NSMotionUsageDescription: Counts your reps.
    UIBackgroundModes: [location]                                # background streams
android:
  permissions: [ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION, FOREGROUND_SERVICE, FOREGROUND_SERVICE_LOCATION]
```

iOS и watchOS предоставляют местоположение и движение, macOS — местоположение, tvOS — по одному определению за раз, а Android — и то и другое через собственных поставщиков фреймворка. Linux получает определения и потоки от GeoClue 2 на системной шине, чей агент спрашивает пользователя при первом запросе приложения; поскольку GeoClue нельзя опросить без запроса пользователю, разрешение читается как ещё не запрошенное, пока приложение не запросило его в этом запуске, а фоновое местоположение недоступно. Windows получает их от `Geolocator` из WinRT; разрешение читается как отклонённое, пока определение местоположения для приложения выключено, как предоставленное, когда приложение запросило его в этом запуске и получило разрешение, а иначе как ещё не запрошенное, и фоновое местоположение там тоже недоступно. Безопасный браузер предоставляет определения геолокации, а на мобильных устройствах — показания акселерометра, гироскопа и объединённые данные о движении. В Safari вызывайте `cx.RequestPermission(core.PermissionMotion, done)` из обработчика нажатия. Браузер сообщает, что местоположение недоступно без `navigator.geolocation`, а движение недоступно на настольных системах и для потоков магнитометра. В TSX у `Sensors` есть `permission`, `requestPermission`, `locate`, `watchLocation` и `watchMotion` при возможностях пакета `location`, `backgroundLocation` и `motion`, со временем в миллисекундах.

## Аудио

Пакет `audio` воспроизводит короткие звуки, однократно декодированные в память (`audio.LoadSound`), и длинное потоковое аудио (`audio.NewPlayer`) там, где `cx.Env().CanPlayAudio()` равно true; в остальных случаях вызовы завершаются ошибкой `audio.Unavailable`.

```go
audio.LoadSound(cx, audio.Source{URI: "asset:sounds/click.wav"}, func(click *audio.Sound, err error) {
	if err != nil {
		return
	}
	click.Play(audio.Voice{})                                  // center, full volume, normal rate
	click.Play(audio.Voice{Volume: 0.5, Rate: 1.2, Pan: -0.5}) // overlaps, panned left
})
```

`audio.Voice` задаёт для каждого воспроизведения `Volume` (от 0 до 1, 0 считается как 1), `Rate` (от 0.5 до 2, 0 считается как 1) и `Pan` (от -1 — полностью влево до 1 — полностью вправо, 0 — по центру); значения вне этих диапазонов ограничиваются, а NaN заменяется значением по умолчанию. `Sound.Stop` останавливает все воспроизведения звука, а `Close` освобождает его, как и владеющая им область видимости при освобождении. `Player` поддерживает `Play`, `Preload`, `Pause`, `Seek`, `SetVolume`, `SetRate`, `SetLoop` и `Close`. Сейчас аудио воспроизводят macOS, iOS, Windows, Linux, Android и веб. Бэкенды Apple, Windows и браузеров поддерживают WAV, AAC и MP3. Linux использует кодеки GStreamer, а его потоковый проигрыватель воспроизводит на скорости 1×. Android приостанавливает проигрыватель, когда его представление уходит с экрана, и ограничивает каждый декодированный звук 1 MiB. tvOS, watchOS, HarmonyOS и мини-программы пока сообщают `CanPlayAudio` как false.

Браузеры требуют жеста пользователя для слышимого воспроизведения. Загружайте короткие звуки заранее, а затем вызывайте `Sound.Play` после щелчка, касания или нажатия клавиши. Звук, воспроизведённый до жеста, не слышен. Функция обратного вызова `Play` проигрывателя получает `audio.NotAllowed`, если браузер блокирует воспроизведение. Повторите попытку по жесту пользователя.

`Sound.Play` возвращает `audio.Playback`, который на macOS, iOS, Windows, Linux и в вебе может независимо задавать собственную громкость и скорость или останавливаться. `Ended()` реактивен и становится true, когда это воспроизведение заканчивается, останавливается, вытесняется ограничением голосов или не может начаться. Бэкенды без индивидуального управления возвращают уже завершённый дескриптор.

На iOS собственный аудиодвижок библиотеки, воспроизводящий звук в обход `audio` и `Video`, например `AudioQueue`, удерживает единственный аудиосеанс приложения с помощью `audio.HoldSession(core.AudioSessionPlayback)`, пока воспроизводит, и вызывает возвращённую функцию освобождения, когда останавливается. Он принимает те же уровни, что и `AudioSession` проигрывателя, наряду с видео, проигрывателями и записями приложения, поэтому `AudioSessionPlayback` и `AudioSessionMixWithOthers` продолжают воспроизведение, когда переключатель «Звонок/Бесшумно» установлен в бесшумный режим. На других платформах он ничего не удерживает.

Используйте `audio.Voice{Muted: true}`, чтобы запустить эффект беззвучно, и `playback.SetVolume(0)`, чтобы заглушить активный эффект. Для длинного аудио `audio.NewPlayer` передаёт источник потоком, а `player.SetMuted(true)` заглушает вывод, пока воспроизведение продолжается. Отключение заглушения восстанавливает настроенную громкость проигрывателя. `Voice.Volume` и `Player.SetVolume` используют ноль для полной громкости по умолчанию.

В TSX `nsgo/audio` предоставляет `supported()` и `loadSound(uri)` при возможности пакета `audio`. `loadSound` разрешается звуком, чей `play({ volume, rate, pan, loop, muted })` возвращает воспроизведение с `setVolume`, `setRate`, `stop` и реактивным `ended`; там громкость 0 означает тишину. Отклонённая загрузка отклоняется с `Error`, чей `reason` — имя ошибки аудио, например `quota-exceeded`, а `code` — `ERR_ACCESS_DENIED` без возможности, `ERR_NSH_QUOTA_EXCEEDED` при превышении ограничения и `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM` там, где ничто не воспроизводит аудио. Звук освобождается только вызовом `close()` или когда исчезает его представление; в песочнице каждая загрузка учитывается в `Limits.Sounds` (по умолчанию 256), пока она не завершится ошибкой или её звук не будет закрыт.

## Геймпады

Пакет `gamepad` читает подключённые игровые контроллеры в стандартной раскладке W3C Standard Gamepad (от `ButtonSouth`/`ButtonA` до `ButtonHome`, `AxisLeftX`/`AxisLeftY`/`AxisRightX`/`AxisRightY`). `cx.Env().SupportsGamepads()` сообщает, поддерживает ли цель контроллеры (macOS, iOS, Windows, Linux, Android и браузеры с Gamepad API).

`gamepad.Pads(cx)` — отслеживаемое реактивное чтение, которое перерисовывает области видимости при подключении или отключении контроллеров, не перерисовывая их при изменении кнопок или стиков. Каждый `gamepad.Pad` предоставляет своё семейство `Family` (`FamilyXbox`, `FamilyPlayStation`, `FamilyNintendo` или `FamilyGeneric`, которое также определяет `gamepad.DetectFamily`), USB `VendorID` и `ProductID` там, где платформа о них сообщает, и `CanRumble` для поддержки вибромоторов. Внутри цикла `RequestAnimationFrame` `gamepad.State(cx, id)` возвращает кнопки контроллера (`[0, 1]`, причём `Pad.Pressed` равно true при `>= 0.5`) и оси (`[-1, 1]`, отрицательные значения — влево/вверх, положительные — вправо/вниз), снимаемые один раз за кадр дисплея.

`gamepad.Rumble(cx, id, lowFreq, highFreq, duration)` управляет низкочастотным (тяжёлым/левым) и высокочастотным (лёгким/правым) вибромоторами с интенсивностью, ограниченной `[0, 1]`, заменяя любую текущую вибрацию на этом контроллере и автоматически останавливаясь по истечении `duration`, когда приложение уходит в фон или теряет фокус (`cx.Env().Lifecycle() != core.LifecycleActive`), когда освобождается `cx` или когда контроллер отключается. `gamepad.StopRumble(cx, id)` останавливает вибрацию досрочно; контроллеры с `CanRumble == false` корректно игнорируют вызовы вибрации.

```go
var loop func(time.Time)
loop = func(time.Time) {
	if pad, ok := gamepad.State(cx, 0); ok {
		move(pad.Axes[gamepad.AxisLeftX], pad.Axes[gamepad.AxisLeftY], pad.Pressed(gamepad.ButtonA))
		if hit {
			gamepad.Rumble(cx, pad.ID, 0.8, 0.3, 180*time.Millisecond)
		}
	}
	cx.RequestAnimationFrame(loop)
}
cx.RequestAnimationFrame(loop)
```

Вызовите `gamepad.EnableFocusNavigation(cx)`, чтобы включить навигацию по нативным точкам остановки фокуса с контроллера (крестовина и левый стик перемещают фокус, `ButtonSouth` активирует элемент управления в фокусе, а `ButtonEast` выполняет возврат назад). Активные игровые представления вызывают `gamepad.CaptureInput(cx)`, чтобы приостановить навигацию фокусом, пока они смонтированы. В TSX `nsgo/gamepad` предоставляет `supported()`, `pads()`, `state(id)`, `Button` и `Axis` при возможности пакета `gamepad`.

## Синхронизация аудио по времени

Используйте `audio.Now(cx)` как часы для воспроизведения по времени. Задайте `audio.Voice.StartAt` моментом в будущем, если `audio.CanSchedule(cx)` равно true. Вызовите `audio.OutputLatency(cx, func(latency time.Duration, known bool) { ... })` для активного маршрута вывода. macOS, iOS, Linux и веб поддерживают запуск по времени; на Windows и Android `CanSchedule` равно false, и `StartAt` воспроизводится сразу. Значение `known` в функции обратного вызова сообщает, сообщил ли маршрут задержку; Windows и Android этого не делают.

## Игровые сервисы

Пакет `gameservices` предоставляет независимый от поставщика API для входа игрока, достижений, таблиц лидеров и нативных оверлеев Game Center / Play Games там, где `cx.Env().CanUseGameServices()` равно true. Каждая функция обратного вызова выполняется в горутине движка, поэтому может напрямую устанавливать сигналы, не блокируя кадры.

```go
if cx.Env().CanUseGameServices() {
	gameservices.Authenticate(cx, func(p gameservices.Player, err error) {
		if err == nil && p.Authenticated {
			playerName.Set(p.DisplayName)
			gameservices.ReportAchievement(cx, "first-run", 100, nil)
			gameservices.SubmitScore(cx, "high-scores", 1250, nil)
		}
	})
}
```

`gameservices.ReportAchievement` ограничивает прогресс диапазоном `0..100` (`100` открывает достижение). `gameservices.LoadScores` читает упорядоченные по рангу строки `gameservices.ScoreEntry` для `Global` или `Friends` за `AllTime`, `Week` или `Today`, а `gameservices.ShowAchievements` и `gameservices.ShowLeaderboard` открывают нативные оверлеи платформы. macOS, iOS и tvOS обращаются к GameKit через purego; Android будет обращаться к Play Games Services через хук среды выполнения Java, которого в среде выполнения пока нет, поэтому сейчас он сообщает `CanUseGameServices() == false`; Windows, Linux, веб, watchOS и мини-программы сообщают `CanUseGameServices() == false` и отвечают `gameservices.ErrUnsupported`.

В тестах включите игровые сервисы с помощью `nsgotest.Environment(core.Environment{CanUseGameServices: true})` и управляйте изолированной имитацией каждого приложения с помощью `App.SetGameServicesPlayer`, `App.SetGameServicesFriends`, `App.SeedLeaderboardScores`, `App.SetGameServicesError`, `App.GameServicesAchievements`, `App.GameServicesScores`, `App.GameServicesShownAchievements` и `App.GameServicesShownLeaderboards`.

### Фитнес, регионы и ограниченное по времени движение

`cx.WatchSteps`, `cx.WatchActivity` и `cx.WatchPressure` возвращают потоки, привязанные к области видимости. Запросите `core.PermissionActivityRecognition` перед шагами и активностью, а на платформах Apple — и перед давлением. Apple предоставляет все три через Core Motion; Android предоставляет счётчики шагов и давление и сообщает, что классификация активности недоступна. Подсчёты относятся к окну `Since` значения; возобновлённые окна несут `Gap`. Давление указано в паскалях, с необязательной относительной высотой в метрах. У отсутствующих расстояний, этажей и высоты `Valid` равно false.

`cx.WatchGeofences` принимает `core.GeofenceOptions` с одним–двадцатью различными кругами `GeofenceRegion` (координаты WGS 84 и радиус в метрах). Он сообщает `GeofenceInside`, `GeofenceOutside` или `GeofenceUnknown` для каждого региона. `Background` требует доступа к фоновому местоположению и соответствующих объявлений, а также авторизации Always от Apple; Android также нужен заголовок уведомления. Остановка или освобождение удаляют его регистрации; ни одна подписка не переживает завершения процесса.

`cx.RequestPreciseLocation("route", done)` явно запрашивает авторизацию точного местоположения и отвечает логическим значением, но никогда не позицией. В `apple.info` объявите `NSLocationTemporaryUsageDescriptionDictionary: {route: Explains why this feature needs precision.}`. Android нужны оба разрешения — приблизительное и точное. Ответ false может оставить авторизованным приблизительное местоположение.

`cx.WatchBackgroundMotion(core.BackgroundMotionOptions{Motion: core.MotionOptions{}, Duration: 20 * time.Second, NotificationTitle: "Recording motion"}, sample, failed)` запрашивает ограниченный по времени живой поток. Ему нужны `AccessMotion` и `AccessBackgroundMotion`; пакеты TSX объявляют `motion` и `backgroundMotion`. iOS может прекратить его право на выполнение раньше. Приложения Android задают `android.background_motion: true` и объявляют `FOREGROUND_SERVICE`; неприкреплённая служба останавливается в течение трёх минут, даже если запрошенная длительность больше. Истечение длительности или срока ОС сообщается как `SensorTimedOut`. Остановка или освобождение завершают работу поставщика и право на выполнение; после завершения ничего не записывается. Другие цели сообщают о недоступности.

`Sensors` в TSX повторяет эти шесть методов и использует миллисекунды. Тесты без интерфейса передают данные через `FeedSteps`, `FeedActivity`, `FeedPressure` и `FeedGeofence` и задают `PreciseLocationAnswer` для запросов точности. Физический фитнес, пробуждение по региону и поведение в приостановленном фоне по-прежнему требуют приёмки на устройстве.
