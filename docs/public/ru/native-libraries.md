Пакет Go может поставлять разделяемые библиотеки, которые он загружает через purego, разместив `nsgo-natives.yaml` в каталоге пакета, а начиная с версии 2 — и свои фреймворки для iOS и tvOS. Когда приложение импортирует пакет, NSGo выбирает его объявления для целевой платформы, проверяет файлы и включает их до подписи и создания установщиков. Приложению не нужны дополнительная настройка или команда упаковки.

Сборки настольных приложений и тесты на целевых платформах отключают cgo для кода приложения. Нативный код должен использовать purego и библиотеку, объявленную в `nsgo-natives.yaml`. NSGo отклоняет пакеты приложения с файлами cgo ещё до начала сборки.

## Объявление библиотек

```yaml
version: 2
libraries:
  macos_arm64:
    - name: libexample.dylib
      path: lib/macos-arm64/libexample.dylib
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  macos_x64:
    - name: libexample.dylib
      url: https://downloads.example.org/v1.0/macos-x64/libexample.dylib
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  windows_arm64: []
  windows_x64: []
  linux_arm64: []
  linux_x64: []
  ios:
    - name: Example.framework
      url: https://downloads.example.org/v1.0/ios/Example
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  ios_simulator:
    - name: Example.framework
      path: lib/ios-simulator/Example
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  tvos: []
  tvos_simulator: []
```

Версия 2 поддерживает ключи `macos_arm64`, `macos_x64`, `windows_arm64`, `windows_x64`, `linux_arm64`, `linux_x64`, `ios`, `ios_simulator`, `tvos` и `tvos_simulator`. Версия 1 поддерживает только шесть настольных ключей; файл читается только для ключей своей версии, поэтому сборки для iOS и tvOS ничего не упаковывают из файла версии 1. Объявите каждую целевую платформу, для которой выбирается пакет Go; `[]` явно указывает, что этой платформе не нужна встроенная библиотека. Вместо этого теги сборки Go могут исключить пакет из платформ, которые он не поддерживает. `macos_universal` берёт обе записи macOS, а терминальная целевая платформа — записи своей настольной: `tui_macos_arm64` берёт `macos_arm64`.

У каждой библиотеки есть:

- `name`: имя установленного файла, оканчивающееся на `.dylib` в macOS, `.dll` в Windows или `.so` либо версионированное `.so.*` в Linux. В iOS и tvOS это имя фреймворка `<Name>.framework`, где `Name` состоит из букв ASCII, цифр, `.` и `-` и начинается и заканчивается буквой или цифрой.
- Ровно одно из двух: `path` — файл относительно каталога этого пакета, или `url` — HTTP(S)-адрес самой библиотеки. Версия 2 принимает только адреса https, и загрузка завершается ошибкой, если перенаправление уходит с https. Публикуйте извлечённые библиотеки, а не адреса архивов, а для фреймворка — только его двоичный файл. Адреса не содержат встроенных имён пользователей и паролей.
- `sha256`: SHA-256 исходного файла, обязательный для любого источника. Например, в macOS его выводит `shasum -a 256 lib/macos-arm64/libexample.dylib`.
- `licenses`: непустой список путей к исходным файлам лицензий и уведомлений относительно каталога этого пакета. Эти тексты попадают в `THIRD_PARTY_NOTICES.txt` и доступны через `core.ThirdPartyNotices()` в релизных сборках. Существующая [политика лицензий](building.md#уведомления-о-лицензиях) приложения, включая точные исключения для модулей, применяется к нативным лицензиям независимо.

Локальные пути и символические ссылки не выходят за пределы объявляющего пакета. NSGo отклоняет неизвестные поля, несовпадения контрольных сумм, файлы для другой операционной системы или архитектуры и конфликтующие имена установленных файлов. Два пакета могут совместно использовать одноимённый файл с одинаковой контрольной суммой. Размер файла ограничен 1 ГиБ.

## Упаковка и загрузка

| Целевая платформа | Каталог библиотек |
| --- | --- |
| macOS | `<app>.app/Contents/Frameworks` |
| Windows, Linux и терминальные целевые платформы | Рядом с исполняемым файлом |
| iOS и tvOS | `<app>.app/Frameworks/<Name>.framework/<Name>` |

Пакет загружает свою библиотеку из этого каталога, используя расположение исполняемого файла, а не рабочий каталог. Собирайте зависимости заранее так, чтобы связанные с ними библиотеки загружались из каталога, в котором они поставляются. Объявите каждый необходимый связанный файл и каждое имя файла, которое нужно загрузчику.

NSGo повторно проверяет кэшированные загрузки перед использованием и координирует параллельные сборки через блокировку файла. Кэш содержимого находится в каталоге пользовательского кэша операционной системы, в `nsgo/natives`. Локальные файлы проверяются при копировании.

Универсальный пакет macOS требует одинаковых имён библиотек для обеих архитектур. NSGo объединяет срезы с помощью `lipo`; уже универсальная библиотека издателя может служить для любой из записей. Библиотеки подписываются до приложения, а затем проходят через обычные шаги приложения по созданию образа диска, подписи и нотаризации. Подпись в Windows включает объявленные DLL даже при `build.installers: false`. Установщики Linux включают те же файлы и уведомления, что и каталог исполняемого файла. На Mac терминальные целевые платформы подписывают библиотеки macOS ad hoc; на других системах они включают их в опубликованном виде, универсальную целиком, и отклоняют библиотеку arm64, которая ещё не подписана.

Разработка, `-run` и тесты на целевых платформах используют те же шаги выбора пакетов и копирования — как на настольных системах, так и на iOS и tvOS. Объявления выбираются с учётом целевой платформы сборки, тегов и сгенерированного оверлея Go, включая локальные замены и вендоренные пакеты. Android, HarmonyOS, watchOS, веб и мини-программы ничего не упаковывают из этого файла.

## Фреймворки iOS и tvOS

NSGo проверяет двоичный файл каждого фреймворка и останавливает сборку с указанием причины, если он не является:

- динамической библиотекой Mach-O для arm64, собранной для платформы цели — устройств или симулятора, — как указывает её `LC_BUILD_VERSION`; из универсального файла берётся срез arm64; arm64e отклоняется;
- библиотекой, минимальная версия ОС которой не новее, чем у приложения: `apple.info.MinimumOSVersion`, а без неё iOS 15.0 и tvOS 17.0 ([Сборка и распространение](building.md#nsgoyaml));
- библиотекой с именем установки `@rpath/<Name>.framework/<Name>`;
- библиотекой, которая загружает через `@rpath` только фреймворки, объявленные пакетами приложения для той же цели.

NSGo записывает `Info.plist` фреймворка, в котором `CFBundleIdentifier` — это ID приложения, точка и `Name` в нижнем регистре, вместе с платформой и минимальной версией ОС приложения. Сборки для симулятора подписывают фреймворк ad hoc. Сборка для устройств оставляет его подписи приложения: `sign.profile` подписывает его удостоверением приложения до самого приложения, как это делает Xcode для `nsgo build -run` и `nsgo dev` на устройстве. Фреймворку, который загружает связанные фреймворки, нужен путь поиска `@loader_path/..` или `@executable_path/Frameworks`, чтобы находить их в `Frameworks`, поскольку у исполняемого файла приложения его нет, и ничего другого через `@rpath` он не загружает, если у него нет системного пути поиска вроде `/usr/lib/swift`. Фреймворк, чей идентификатор бандла без учёта регистра уже есть у другого бандла приложения, например `StoreKit.framework` рядом с `NSGoStoreKit.framework` из NSGo, останавливает сборку.

`nsgo build -embed` останавливается с указанием пакета, если приложение связывает пакет, объявляющий фреймворки для iOS: XCFramework для приложения-хоста пока не может их нести.

## Сохранение файлов при вендоринге

Операции вендоринга Go нужны встроенные данные, чтобы сохранить файлы внутри каталога пакета. Пакет может пометить свой манифест и лицензии для включения, не используя их байты во время выполнения:

```go
import "embed"

//go:embed nsgo-natives.yaml licenses/*
var _ embed.FS
```

При использовании `path` включите в эту директиву embed и локальные пути к библиотекам, например `lib/*`. Для загрузок по URL в пакете Go нужны только манифест и файлы лицензий.
