Пакет Go может поставлять разделяемые библиотеки, которые он загружает через purego, разместив `nsgo-natives.yaml` в каталоге пакета. Когда приложение импортирует пакет, NSGo выбирает его объявления для целевой платформы, проверяет файлы и включает их до подписи и создания установщиков. Приложению не нужны дополнительная настройка или команда упаковки.

## Объявление библиотек

```yaml
version: 1
libraries:
  macos_arm64:
    - name: libexample.dylib
      path: lib/macos-arm64/libexample.dylib
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  macos_x64:
    - name: libexample.dylib
      url: https://downloads.example.org/v1.0/macos-x64/libexample.dylib
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  windows_arm64: []
  windows_x64: []
  linux_arm64: []
  linux_x64: []
```

Поддерживаемые ключи: `macos_arm64`, `macos_x64`, `windows_arm64`, `windows_x64`, `linux_arm64` и `linux_x64`. Объявите каждую целевую платформу, для которой выбирается пакет Go; `[]` явно указывает, что этой платформе не нужна встроенная библиотека. Вместо этого теги сборки Go могут исключить пакет из платформ, которые он не поддерживает. `macos_universal` берёт обе записи macOS.

У каждой библиотеки есть:

- `name`: имя установленного файла, оканчивающееся на `.dylib` в macOS, `.dll` в Windows или `.so` либо версионированное `.so.*` в Linux.
- Ровно одно из двух: `path` — файл относительно каталога этого пакета, или `url` — HTTP(S)-адрес самой библиотеки. Публикуйте извлечённые библиотеки, а не адреса архивов. Адреса не содержат встроенных имён пользователей и паролей.
- `sha256`: SHA-256 исходного файла, обязательный для любого источника. Например, в macOS его выводит `shasum -a 256 lib/macos-arm64/libexample.dylib`.
- `licenses`: непустой список путей к исходным файлам лицензий и уведомлений относительно каталога этого пакета. Эти тексты попадают в `THIRD_PARTY_NOTICES.txt` и доступны через `core.ThirdPartyNotices()` в релизных сборках. Существующая [политика лицензий](building.md#уведомления-о-лицензиях) приложения, включая точные исключения для модулей, применяется к нативным лицензиям независимо.

Локальные пути и символические ссылки не выходят за пределы объявляющего пакета. NSGo отклоняет неизвестные поля, несовпадения контрольных сумм, файлы для другой операционной системы или архитектуры и конфликтующие имена установленных файлов. Два пакета могут совместно использовать одноимённый файл с одинаковой контрольной суммой. Размер файла ограничен 1 ГиБ.

## Упаковка и загрузка

| Целевая платформа | Каталог библиотек |
| --- | --- |
| macOS | `<app>.app/Contents/Frameworks` |
| Windows и Linux | Рядом с исполняемым файлом |

Пакет загружает свою библиотеку из этого каталога, используя расположение исполняемого файла, а не рабочий каталог. Собирайте зависимости заранее так, чтобы связанные с ними библиотеки загружались из каталога, в котором они поставляются. Объявите каждый необходимый связанный файл и каждое имя файла, которое нужно загрузчику.

NSGo повторно проверяет кэшированные загрузки перед использованием и координирует параллельные сборки через блокировку файла. Кэш содержимого находится в каталоге пользовательского кэша операционной системы, в `nsgo/natives`. Локальные файлы проверяются при копировании.

Универсальный пакет macOS требует одинаковых имён библиотек для обеих архитектур. NSGo объединяет срезы с помощью `lipo`; уже универсальная библиотека издателя может служить для любой из записей. Библиотеки подписываются до приложения, а затем проходят через обычные шаги приложения по созданию образа диска, подписи и нотаризации. Подпись в Windows включает объявленные DLL даже при `build.installers: false`. Установщики Linux включают те же файлы и уведомления, что и каталог исполняемого файла.

Разработка и тесты нативных настольных целевых платформ используют те же шаги выбора пакетов и копирования. Объявления выбираются с учётом целевой платформы сборки, тегов и сгенерированного оверлея Go, включая локальные замены и вендоренные пакеты. Другие целевые платформы пока не упаковывают библиотеки из этого файла.

## Сохранение файлов при вендоринге

Операции вендоринга Go нужны встроенные данные, чтобы сохранить файлы внутри каталога пакета. Пакет может пометить свой манифест и лицензии для включения, не используя их байты во время выполнения:

```go
import "embed"

//go:embed nsgo-natives.yaml licenses/*
var _ embed.FS
```

При использовании `path` включите в эту директиву embed и локальные пути к библиотекам, например `lib/*`. Для загрузок по URL в пакете Go нужны только манифест и файлы лицензий.
