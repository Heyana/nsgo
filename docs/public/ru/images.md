## Изображение

`core.Image` показывает растровое изображение или SVG: URL, файл, путь `asset:` в ресурсах приложения или байты, которые хранит приложение. Платформа загружает, декодирует и кэширует его вне главного потока, а главный поток отрисовывает результат.

```go
core.Image{
	Source: core.Src("https://example.com/cover.jpg"),
	ResizeMode: core.Cover,
	Style: core.Style{Width: core.Pt(160), Height: core.Pt(100), CornerRadius: 12},
}
```

`core.Cover` заполняет рамку и обрезает то, что выходит за её пределы; `core.Contain` вписывает изображение целиком, `core.Center` сохраняет его естественный размер, а `core.ScaleDown` сохраняет его, если только оно не больше рамки. `BlurRadius` размывает изображение на заданное число точек, `TintColor` перекрашивает его непрозрачные пиксели, а `ObjectPosition` размещает его в рамке.

Масштабированные растровые изображения по умолчанию используют сглаженную выборку. Задайте `Sampling: core.ImageSamplingNearest` в Go или `sampling="nearest"` в TSX, чтобы сохранить чёткие края пиксельной графики и пиксельных буферов. Эту настройку поддерживают платформы Apple, Windows, Linux, Android и веб; HarmonyOS и мини-программы тоже её применяют, хотя их результат пока не проверен на устройствах. Для точных пиксельных краёв в браузере, использующем CSS `pixelated`, масштабируйте до целого числа пикселей устройства на пиксель источника.

`Source` объявляет размер, который использует раскладка: одно измерение выводится из другого, а изображение без размера имеет размер 0 на 0, пока его стиль не задаст размер. `core.ImageSource{Data: data, Size: core.Size{Width: 24, Height: 24}}` показывает байты, встроенные с помощью `go:embed`, а `Size` задаёт собственный размер SVG.

С [`desktop.WindowPointerPainted`](services.md) значение `HitTestAlpha: 0.5` пропускает указатель сквозь пиксели, непрозрачность которых меньше половины, на macOS и Windows. В TSX тот же порог задаётся через `hitTestAlpha`.

## Кадры, которые рисует приложение

`Pixels` показывает `*image.RGBA`, который рисует приложение, — кадры видеоплеера или эмулятора — без какого-либо кодирования, загрузки или декодирования. Записывайте каждый кадр в один и тот же буфер и увеличивайте `Version`: представление показывает его без событий загрузки и без плавного появления, с сохранением альфа-канала, а на macOS, iOS, tvOS, watchOS, Android, Windows и Linux подменяет его на месте без пустого кадра между ними. Без `Size` оно измеряет свои пиксели в точках.

```go
frame := image.NewRGBA(image.Rect(0, 0, 960, 540))
version := core.NewSignal(cx, uint64(0))
var tick func(time.Time)
tick = func(at time.Time) {
	if decoder.WriteDue(at, frame) { // writes the next frame into frame.Pix
		version.Set(version.Get() + 1)
	}
	cx.RequestAnimationFrame(tick)
}
cx.RequestAnimationFrame(tick)

core.Image{ResizeMode: core.Contain, SourceFunc: func() core.ImageSource {
	return core.ImageSource{Pixels: frame, Version: version.Get()}
}}
```

NSGo копирует пиксели при выполнении фиксации, которая несёт новое значение `Version`, поэтому приложение может записать следующий кадр уже из следующего обратного вызова `RequestAnimationFrame`; декодер в собственной горутине пишет во второй буфер и отправляет команду на их обмен. Одна и та же `Version` повторно не отрисовывается. `cx.ImageSize` сразу отвечает для пиксельного источника размером его буфера. `core.Canvas` рисует пиксели с помощью `DrawImage`, копируя их тем же способом, на всех платформах; мини-программам требуется 2D-холст WeChat. `Images` у `core.Shader` принимают пиксели тем же способом, так что шейдер может фильтровать кадр, который пишет приложение, например экран эмулятора, на всех платформах, где отрисовываются шейдеры.

Платформы Apple, Android, Windows, Linux и веб обновляют пиксельные изображения напрямую, а мини-программы WeChat используют 2D-холст. HarmonyOS создаёт `PixelMap` для каждой версии (это проверено на устройстве), и её копии проходят через строковый мост, поэтому большие буферы, перезаписываемые каждый кадр, работают там значительно медленнее 60 кадров/с ([пиксельные буферы](https://github.com/nsgo-dev/nsgo/blob/main/docs/architecture/images.md#pixel-buffers)).

## Снимок представления

Вызовите `cx.Capture(&ref, done)` с `core.Ref` смонтированного представления или `cx.Capture(nil, done)` для текущей поверхности. Обратный вызов получает байты PNG в пиксельном масштабе поверхности или ошибку в горутине движка. Используйте `core.ImageSource{Data: png}`, чтобы показать результат. Чтобы поделиться им, запишите байты в файл `.png` в каталоге кэша приложения и передайте его путь в `core.ShareOptions.Files`. [Отправка файлов](services.md#открытие-ссылок-и-файлов)

Снимок захватывает видимые пиксели поверхности в границах представления. Он доступен на macOS, iOS, tvOS, Windows, Linux, Android и в вебе. Android захватывает окно активности. Снимок в вебе отрисовывает DOM приложения в холст, включая вывод шейдеров NSGo, и опускает встроенные фреймы, изображения, которые не может прочитать, и некоторые эффекты CSS.

## Ресурсы и масштабы

Файлы в `resources/` поставляются вместе с приложением. `core.Src("asset:images/cover.png")` загружает один из них, а `Scales: core.ScalesOf(1, 2, 3)` выбирает `cover.png`, `cover@2x.png` или `cover@3x.png` в зависимости от плотности пикселей экрана.

```go
core.Image{Source: core.ImageSource{
	URI:    "asset:images/cover.png",
	Scales: core.ScalesOf(1, 2, 3),
}}
```

`Placeholder` показывает источник, пока изображение загружается, а `FadeDuration` плавно проявляет загруженное изображение поверх него; 0 позволяет платформе выбрать длительность, а одна наносекунда показывает его сразу. `OnLoadStart`, `OnProgress`, `OnLoad`, `OnError` и `OnLoadEnd` отслеживают загрузку. `cx.ImageSize` читает размер источника в пикселях, не показывая его, `cx.PrefetchImage` загружает источник в кэш, `cx.SetImageCacheLimit` задаёт бюджет памяти в байтах для закодированных изображений (по умолчанию `core.DefaultImageCacheLimit`, 32 МиБ; отрицательные значения приводятся к 0), а `cx.KeepImage` закрепляет атлас или текстуру, защищая их от вытеснения из кэша, пока не будет вызвана возвращённая функция `release` или не будет освобождена его область видимости. Ограничение применяется к каждому кэшу, не учитывая закреплённые элементы, текущие загрузки и текущий проход отрисовки; оно не ограничивает декодированные пиксели, память процесса или кэширование браузера. Ноль отключает хранение незакреплённых изображений. Нативные бэкенды хранят удалённые изображения в собственном дисковом кэше.

## Анимированные и векторные изображения

Анимации GIF и WebP воспроизводятся в представлении, каждый кадр со своей задержкой, и зацикливаются так, как указано в файле. Документы SVG загружаются как изображения и остаются чёткими при любом размере; одноцветный SVG можно перекрасить с помощью `TintColor`.

## Значки

`core.Icon` рисует SVG цветом текста, который он наследует, высотой с размер шрифта, если его стиль не задаёт размер. Его рамка сохраняет соотношение сторон SVG, поэтому квадратная рамка его не растягивает.

```go
core.Icon{SVG: lucide.Search, Style: core.Style{FontSize: 20}, Label: "Search"}
```

В `icons/lucide` есть функция доступа для каждого значка Lucide, названная в стиле PascalCase (`lucide.ArrowUpRight`). Для вспомогательных технологий значок является декорацией, если `Label` не даёт ему имя. `ui.Icon` — то же самое со значениями по умолчанию из `ui`, а `core.SVG` и `core.SVGView` рисуют контуры, которые приложение строит само.

## Оформленное изображение

`ui.Image` — это изображение в скруглённой подложке с заполнителем во время загрузки и бледным значком изображения при ошибке. Оно сохраняет соотношение сторон источника или 3:2, если его нет, если только его стиль не задаёт размер обеих сторон.

```go
ui.Image{
	Source:      core.Src("asset:images/cover.png"),
	Label:       "Cover",
	ResizeMode:  core.Cover,
	AspectRatio: 16.0 / 9.0,
	Placeholder: ui.Skeleton{Style: core.Style{Height: core.Pt(180)}},
}
```
