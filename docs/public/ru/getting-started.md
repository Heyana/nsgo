## Требования

- [Go](https://go.dev/dl/) 1.27.3 или новее.
- Для сборки под iOS, tvOS и watchOS — Mac с Xcode. Все остальные целевые платформы собираются на macOS с одним только Go; для эмулятора Android на x86_64 также нужен Android NDK.
- Для запуска на iPhone — Apple ID в разделе Accounts в Xcode и доверенный iPhone с включённым режимом разработчика (Developer Mode).
- Для запуска на Android — `adb` из пакета platform-tools в Android SDK.
- Для запуска на Windows — только Go, который также собирает пакеты для Windows и веба.
- На Linux — GTK 4.14 или новее, Pango и Cairo. Изображения из сети используют libsoup 3, веб-представления — WebKitGTK 6.0, а звук и видео — плагины GStreamer. В системах с ограничениями пространств имён пользователей в AppArmor [WebKitGTK требуется профиль bubblewrap](debugging.md#веб-представления-на-linux).

## Создание приложения

Создайте модуль, добавьте NSGo и его инструмент, а затем позвольте инструменту написать приложение:

```sh
mkdir hello && cd hello
go mod init example.com/hello
go get github.com/nsgo-dev/nsgo
go get -tool github.com/nsgo-dev/nsgo/cmd/nsgo
go tool nsgo init
```

`go get -tool` один раз добавляет `nsgo` в модуль, поэтому `go tool nsgo` запускает его без какой-либо установки. `init` создаёт:

| Файл | Что это |
| --- | --- |
| `app.go` | Приложение-счётчик: компонент `Root` и `main`, который вызывает `nsgo.Run(Root)` |
| `app_test.go` | Тест, который нажимает кнопку |
| `nsgo.yaml` | Имя, идентификатор, версия и целевые платформы приложения |

`go tool nsgo init -template tsx` вместо этого создаёт приложение на TSX, а `-template mixed` — приложение на Go, точка входа TSX которого использует собственные компоненты на Go.

Добавляйте библиотеки командой `nsgo add <модуль>` вместо `go get`: она показывает, что получат `go.mod` и `go.sum`, прежде чем их записать, и никогда не уводит NSGo проекта с его релизов ([Добавление библиотек](building.md#добавление-библиотек)).

### Шаблоны из модулей Go

Передайте путь модуля шаблона с необязательной версией. Если версия не указана, выбирается последняя версия, которую может найти прокси модулей Go.

```sh
go tool nsgo init -template example.com/my-template@v1.2.0 -module example.com/hello hello
```

Опубликуйте заготовку внутри каталога `template/` модуля. Включите в неё `nsgo.yaml` и `main.go`. Инструмент обрабатывает оба файла, а также любой файл с окончанием `.tmpl`, с помощью `text/template` из Go и удаляет `.tmpl` из имён результирующих файлов. Остальные файлы, включая двоичные ресурсы, он копирует без изменений.

Шаблоны получают `.Name` (отображаемое имя приложения), `.ID` (сгенерированный идентификатор приложения), `.Slug` (имя в нижнем регистре через дефисы) и `.Module` (значение `-module` или slug). Поставляйте `go.mod.tmpl`, чтобы объявить модуль и зависимости создаваемого приложения, поскольку Go исключает вложенные файлы `go.mod` из загрузок модулей. Без него `-module` создаёт тот же минимальный `go.mod`, что и для встроенного шаблона.

## Запуск

```sh
go tool nsgo dev
```

`dev` собирает приложение для этой машины и открывает его. При каждом сохранении он пересобирает и перезапускает приложение, а изменение одного лишь TSX обновляет запущенное приложение на месте. Неудачная сборка показывается поверх приложения с кнопками для копирования ошибки и повторной сборки.

Запустите приложение в другом месте с помощью `-target`:

```sh
go tool nsgo dev -target web                # in the browser
go tool nsgo dev -target ios_simulator      # in the iOS simulator
go tool nsgo dev -target tvos_simulator     # in the Apple TV simulator
go tool nsgo dev -target watchos_simulator  # in the Apple Watch simulator
go tool nsgo dev -target android            # on a connected device or emulator
```

`go tool nsgo doctor` перечисляет все целевые платформы, указывая, собирает ли и запускает ли их эта машина, а для тех, которые она не может, — чего ей не хватает, например Xcode, `adb`, подключённого устройства или GTK.

[Запуск и отладка](debugging.md) описывает устройства, трассировку обновлений, монитор производительности и другие языки.

## С агентом для программирования

Навык (skill) NSGo учит агентов для программирования, таких как Claude Code, Codex и Cursor, тому, как пишется, тестируется и выпускается приложение на NSGo. Добавьте его в каталог приложения или с `-g` — для всех проектов:

```sh
bunx skills add nsgo-dev/nsgo
```

Агенты, которые сами читают документацию, начинают с <https://nsgo.dev/llms.txt>, где перечислены все страницы в формате Markdown по адресу `https://nsgo.dev/docs/<page>.md`; <https://nsgo.dev/llms-full.txt> содержит их все. Агент также может использовать запущенное приложение ([Запуск и отладка](debugging.md#агенты)).
