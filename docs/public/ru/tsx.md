## Приложение на TSX

Приложение на TSX — это пакет Go, который встраивает свои исходники и запускает точку входа:

```go
//go:embed *.tsx nsgo.yaml
var src embed.FS

var Root = compiler.App(src, "App.tsx")

func main() { nsgo.Run(Root) }
```

```tsx
import { mount, signal, Text, View } from "nsgo";

function App() {
  const count = signal(0);
  return (
    <View class="gap-3 p-6" onPress={() => count.update((n) => n + 1)}>
      <Text class="text-lg font-bold">Pressed {count()} times</Text>
    </View>
  );
}

mount(App);
```

`go tool nsgo init -template tsx` создаёт такое приложение, ещё один пример — `examples/tsx`. `nsgo dev` и `nsgo build` компилируют TSX заранее, поэтому пакеты не содержат компилятора; `go run` и `go test` компилируют его при запуске приложения. Node не нужен ни в том, ни в другом случае.

## Компоненты и модули

TSX импортирует примитивы из `nsgo`, компоненты `base` — из `nsgo/base`, игровые контроллеры — из `nsgo/gamepad` (в подписанных пакетах — с возможностью `gamepad`), звуки — из `nsgo/audio` (с возможностью `audio`), а компоненты `ui` — из `nsgo/ui`, если приложение импортирует `tsx/ui`; их показывает `examples/gallery-tsx`.

Для диаграмм Mermaid импортируйте `github.com/nsgo-dev/nsgo/tsx/diagram` ради его побочного эффекта в хосте на Go, вместе с `tsx/textview` или `tsx/ui`. Это добавляет `Diagram` в `nsgo/base`, не подключая разборщик диаграмм к приложениям, которые его не используют. Компонент принимает `source`, `fontSize`, частичную `theme`, `accessibilityLabel` и обычные свойства оформления. Используйте его напрямую или передайте функцию отрисовки в TextView:

```tsx
import { Diagram, TextView } from "nsgo/base";

<TextView markdown={markdown}
  renderDiagram={(code) => <Diagram source={code.code} errorClass="font-mono" />} />
```

То же свойство `renderDiagram` работает в TextView из `nsgo/ui`. Блок кода не на Mermaid сохраняет обычную отрисовку; некорректная диаграмма показывает свой исходник.

Для набора математических формул импортируйте `github.com/nsgo-dev/nsgo/tsx/formula` ради его побочного эффекта в хосте на Go, вместе с `tsx/textview` или `tsx/ui`. Это добавляет `Formula` в `nsgo/base`; приложения, которые не подключают этот пакет, не включают математический движок и шрифт в свой бинарный файл. Компонент принимает `source`, `dialect` (по умолчанию `tex` или `typst`), `display`, `accessibilityLabel` и свойства оформления. Размер шрифта и цвет следуют окружающему тексту. Используйте его напрямую или передайте функцию отрисовки в TextView:

```tsx
import { Formula, TextView } from "nsgo/base";

<TextView markdown={markdown}
  renderMath={(math) => <Formula source={math.tex} display={math.display} />} />
```

То же `renderMath` работает в TextView из `nsgo/ui`. При копировании формулы сохраняют свой TeX. `Renderer` на Go остаётся настройкой хоста.

`UrlScheme.url()` читает отслеживаемый адрес приложения; `UrlScheme.setUrl(url, { history: "push" })` добавляет запись адреса или заменяет её, если параметры не указаны. `UrlScheme.on("change", fn)` отслеживает переходы браузера назад и вперёд и изменения хеша и возвращает функцию отписки. О маршрутизации, проверке того же источника (same-origin) и размещении глубоких ссылок см. [Адреса приложения](addresses.md).

## Go из TSX

Зарегистрируйте код на Go, чтобы TSX мог его импортировать:

```go
tsx.Register("app/native", map[string]core.Node{"Badge": Badge{}})
tsx.RegisterFunctions("app/native", map[string]any{
	"greet": func(name string) string { return "Hello, " + name },
})
```

После этого `import { Badge, greet } from "app/native"` принимает поля `Badge` как свойства и вызывает `greet`. Функции, принимающие `context.Context`, становятся промисами, а `tsx.RegisterClass` превращает типы Go в классы, которые TSX создаёт с помощью `new`.

Необязательное свойство, переданное как `undefined`, использует значение по умолчанию. При регистрации компонента Go с геттером, значение по умолчанию которого отличается от нулевого значения его типа, добавьте параметр вроде `tsx.Default("Max", float64(100))`; то же значение по умолчанию применяется, пока реактивное свойство возвращает undefined, без замены компонента.

Поля данных с документированными значениями по умолчанию в Go тоже можно опускать: `width` и `height` узла `Flow` при отсутствии измеряют его JSX-содержимое, опущенная `width` ребра использует толщину линии по умолчанию, а опущенный `pace` строки квоты оставляет её отметку темпа скрытой.

При регистрации компонентов и классов Go их экспортируемые поля и методы находятся через рефлексию во время работы приложения. Из-за такого поиска компоновщик Go не удаляет экспортируемые методы, которые никто не вызывает, — во всём приложении, а не только в том, что регистрирует TSX, — поэтому подключение `tsx` добавляет около 20 МБ к урезанному (stripped) настольному бинарному файлу, и тем больше, чем больше пакетов подключает приложение.

## Подписанные пакеты

Приложение может запускать загружаемый им TSX — например, заново доставляемые собственные экраны или плагины, — после того как проверит пакет. Объявите в `nsgo.yaml` пакета, к чему может обращаться его код; всё остальное ему запрещено:

```yaml
capabilities:
  network:
    hosts: [api.example.com, "*.cdn.example.com"]
  open_url: true # or { schemes: [https] }
  host: [search, "player.*"] # the app's handlers it may call
  # webview: { hosts: [...], input: true, media: [microphone, camera] }, clipboard, picker, speech, text_to_speech, status_bar, notifications, biometrics, sign_in_with_apple, purchases, secrets, audio, gamepad, auth_session
```

Храните корневой ключ офлайн и заверяйте им ключи выпуска, затем подпишите приложение в этом каталоге. `go tool nsgo keygen` выводит пару ключей и не записывает файлов; запустите его один раз для корневого ключа и по разу для каждого ключа выпуска. Открытые ключи указываются во флагах и в коде приложения; секретные ключи хранятся вне репозитория и передаются инструменту только через `NSGO_ROOT_KEY` и `NSGO_RELEASE_KEY`:

```sh
go tool nsgo keygen # once for the root, once for the release key
NSGO_ROOT_KEY=<root secret> go tool nsgo certify -key <release public> -apps 'com.example.*'
NSGO_RELEASE_KEY=<release secret> go tool nsgo publish -cert release.cert plugin
go tool nsgo verify -root <root public> plugin/dist/Plugin-1.0.0.nsgopkg
```

Приложение доверяет открытому корневому ключу, записанному в его коде, проверяет пакет вне горутины движка и показывает его в `tsx.View` в песочнице рядом с собственными представлениями. Пакет обращается к приложению только через канал хоста, который ему передаёт представление, и хранит собственную часть хранилища и секретов приложения:

```go
trust, err := pkg.OpenTrust(filepath.Join(cx.DataDir(), "trust"))
trust.AddRoot(root)
p, err := trust.Verify(data) // refuses tampered, revoked and older builds
channel := core.NewHost()
channel.Handle("search", func(c *core.HostCall) { c.Resolve(results(c.Data)) })
view := tsx.View{Package: p, Sandbox: tsx.Sandbox{Host: channel}}
core.Catch{Try: view.Render, Fallback: failed}
trust.Accept(p) // once it ran, older builds are refused
```

`Sandbox.Grant` предоставляет пакету меньше, чем он объявляет, `Sandbox.Limits` задаёт другие бюджеты времени и квоты, а `Sandbox.Modules` — функции и компоненты Go сверх собственных возможностей NSGo. Его сочетания клавиш, обработчики «назад» и стеки навигации действуют только пока фокус клавиатуры находится в его представлении, а сам перемещать фокус (`focus()`, `autoFocus`, `Keyboard.dismiss`, `setAccessibilityFocus`) он может, только если фокус уже там или в ответ на нажатие пользователя в нём. Он отображается в собственном представлении, которое занимает пространство, выделенное родителем, не больше, и обрезает его содержимое, включая меню, всплывающие окна и уведомления (toasts); в прокручиваемом представлении поместите его в представление, чтобы он принимал высоту своего содержимого. Его диалог, оповещение, контекстное меню или объявление показываются только таким же образом, а «назад» закрывает его диалог, даже если пакет сам его не удаляет. `View.Export` называет компонент, экспортируемый модулем входа пакета, который показывается вместо корня, монтируемого точкой входа (тогда её `mount` не отрисовывает и не запускает свой компонент), и получает `View.Props` — сериализуемую в JSON карту, копируемую для каждого представления, — поэтому один пакет предоставляет несколько представлений, у каждого из которых своё состояние, с одними и теми же возможностями и ограничениями; отсутствующий экспорт вызывает панику с `tsx.ErrNoViewExport`, а экспорт, не являющийся функцией, — с `tsx.ErrViewExportNotComponent`. Пакет, модуль входа которого экспортирует функции, является плагином функций: `tsx.Load(cx, p, tsx.Sandbox{})` запускает его невидимо и синхронно в горутине вызывающего под `cx`, принадлежащим дереву представлений (без него возвращает `tsx.ErrNoTree`), или возвращает то, что выбросил модуль входа при загрузке, а `Plugin.Call` вызывает эти функции. `go tool nsgo dev -limits` запускает приложение так, как его запустило бы такое представление, а `go tool nsgo revoke` подписывает список отозванных ключей выпуска и пакетов для `Trust.UpdateRevocations`. `examples/plugins` просит пользователя предоставить возможности пакета, устанавливает его и запускает. `Limits.Memory`, по умолчанию 64 МиБ, ограничивает учитываемое нативное хранилище для массивов, строк, буферов и типизированных массивов. Сюда входят копии от `concat`, `flat`, `slice`, расширения массива (spread), конкатенации строк, шаблонов, `replace`, `replaceAll`, `TextEncoder` и `Blob`. `memory=<bytes>` в `-limits` меняет бюджет, а `memory=0` отключает его. Проверки выполняются до выделения памяти. Пакет, превысивший бюджет, останавливается с `ERR_NSH_QUOTA_EXCEEDED` и ресурсом `memory` после того, как Go проверит наличие хранилища, которое можно собрать сборщиком мусора. Обычные объекты, замыкания, стеки, небольшие выделения, а также не учитываемые встроенные функции и API хоста тоже могут выделять память. Браузер использует собственную кучу. Приложение, которое само подписывает пакеты с помощью `pkg.Build` или `go tool nsgo publish -extra <file>` с байтами этого файла, может поместить собственные метаданные в `pkg.Contents.Extra` — например, что плагин добавляет в его меню: они подписываются вместе с пакетом, а `Verify` возвращает их без изменений как `p.Extra`, чтобы приложение их разобрало, поэтому приложение читает их, не запуская код пакета.

Приложение может подписывать собственные JSON-документы, например каталог своих плагинов, с помощью `pkg.SignDocument` и проверять их с помощью `Signed.Open`, используя ключи, которые выводит `nsgo keygen`. Дайте каждому виду документов собственный контекст `app:` с версией, например `app:catalog-v1`: документ никогда не будет принят за документ другого вида, а также за пакет, сертификат или список отзыва. `Open` доверяет ровно тем открытым ключам, которые ему переданы, без сертификата и списка отзыва, и отклоняет поля тела, которых нет в типе, в который выполняется декодирование. Оболочка не содержит ни времени, ни порядкового номера, поэтому более старый документ проходит проверку так же, как более новый: поместите версию или срок действия в тело и проверяйте их.
В нативной песочнице `JSON.stringify`, `JSON.parse` с функцией-ревайвером, `Array.prototype.join`, `toString`, `toLocaleString` и `flat`, а значит и `String()` от массива, выбрасывают перехватываемую `RangeError`, как только уходят глубже 1000 уровней вложенности, считая каждый вызов внутри другого: `toString` массива и вызываемый им `join` считаются каждый отдельно; более глубокие данные привели бы к зависанию вызова или завершению приложения. В вебе используются встроенные функции браузера.

На нативных платформах `DefaultLimits.Stack` равен 1000 кадрам. Задайте `Limits.Stack` или `-limits stack=<frames>`, чтобы выбрать другую глубину, вплоть до 10 000 кадров. Значения Go, равные нулю или меньше, и входные значения выше предела используют 10 000. В вебе используется ограничение стека браузера.

Нативные функции, вызывающие друг друга, учитываются в `Limits.Stack` так же, как вызовы JS: геттер, `toString` или `valueOf`, являющиеся встроенными функциями, регулярное выражение, у которого `exec` — другой его метод, `Reflect.apply` и `Reflect.construct` внутри друг друга, а также цепочки привязанных функций или прокси при превышении предела выбрасывают перехватываемую `RangeError` вместо завершения приложения, а значение плагина, вложенное глубже предела, приводит к сбою вызова, который преобразует его в Go, с `RangeError`. Это обеспечивает форк goja, который требуется NSGo, — `github.com/nsgo-dev/goja`; ваше приложение получает его вместе с NSGo без каких-либо изменений в своём `go.mod`.

На нативных платформах `Limits.Call` ограничивает каждый отрезок выполнения JavaScript, включая обратные вызовы таймеров и продолжения промисов после `await`. Когда отрезок прерывается, ожидающий `Plugin.Call` один раз сообщает `tsx.ErrBudget`, останавливает свои оставшиеся таймеры и игнорирует запоздалые ответы хоста. Независимые вызовы продолжают работать, включая реакции промисов, поставленные в очередь в прерванном отрезке. Вызов, который завершает промис другого вызова, по-прежнему сообщает собственный результат или ошибку. Регулярные выражения с возвратами используют более короткий из бюджетов загрузки и вызова как тайм-аут сопоставления; необработанный тайм-аут также превращается в `tsx.ErrBudget`.

`Limits.CallTotal` добавляет предельный срок по реальному времени для каждого вызова плагина и события представления в песочнице. Он включает время ожидания и распространяется на таймеры, интервалы, кадры, продолжения промисов и ответы хоста вызова даже после того, как вызов завершён. По истечении срока ожидающая работа отбрасывается, а вызов, который ещё ожидает, завершается с `tsx.ErrBudget`. Работа модуля входа ограничена `Limits.Load`, а если `Load` равен нулю — `CallTotal`. Самостоятельные события хоста используют `CallTotal` с момента доставки. Используйте `Plugin.CallWithBudget`, чтобы получить дескриптор предельного срока ожидающего вызова. В `Scope.Post` хоста вызовите `budget.Extend(duration)` до наступления этого срока, чтобы дать больше времени только этому вызову.

`Plugin.Interrupt` останавливает среду выполнения из любой горутины, отбрасывает её ожидающие таймеры и приводит к сбою текущих и последующих вызовов. `Plugin.Stopped()` и `Plugin.Err()` также можно читать из любой горутины. `Err()` возвращает nil, пока среда выполнения работает, и первую причину остановки после того, как она остановлена. Закрытие плагина или освобождение его владельца обычно выполняет его функции очистки и останавливает его с `tsx.ErrPluginClosed`. Задайте `Sandbox.OnStop` при вызове `tsx.Load`, чтобы однократно получить эту причину в горутине движка после того, как ожидающие вызовы завершатся сбоем.

Задайте `Sandbox.OnError` при загрузке плагина функций, чтобы получать неперехваченные сбои таймеров, кадров анимации, `queueMicrotask` и `reportError` вне ожидающего `Plugin.Call`. Обработчик каждого плагина выполняется в горутине движка, поэтому хост может определить, к какому плагину относятся сбои, и вызвать `Plugin.Interrupt`, когда срабатывает его автоматический выключатель (circuit breaker). Прерывания нативных отрезков по бюджету также сообщают `tsx.ErrBudget`, включая задание промиса, вызов которого уже завершён. Обычные ошибки обратных вызовов оставляют плагин работающим. Ошибки загрузки и результатов вызовов по-прежнему возвращаются вызывающим, а представления по-прежнему используют `core.Catch`; без обработчика сохраняется прежнее поведение границ ошибок и отчётов приложения.

Задайте `Sandbox.OnViewRuntime`, чтобы получать `*tsx.ViewRuntime` каждого представления в горутине движка до запуска его модуля входа. Вызовите `Interrupt` из любой горутины, чтобы остановить его работу и оставить на месте последнее отрисованное представление. `Stopped` и `Err` сообщают его конечное состояние, с `tsx.ErrViewClosed` при обычном освобождении. `Sandbox.OnStop` также однократно сообщает конечную причину остановки представления.

`Plugin.JSTime` и `ViewRuntime.JSTime` сообщают время, затраченное во входах в JavaScript нативной среды выполнения, включая текущий вход. Ожидание между входами и время внутри зарегистрированных синхронных функций Go не учитываются. `ViewRuntime.EngineTime` также включает синхронные вызовы Go и собственную работу по реактивности, монтированию, фиксации (commit) и раскладке, в том числе ещё выполняющуюся. Он не включает ожидание между входами в движок, работу, принадлежащую хосту или другому представлению, общий учёт фиксации и нативную отрисовку. Оба счётчика безопасно читать из любой горутины. Ходы JavaScript браузера вне NSGo невозможно ни измерить, ни вытеснить. Там оба счётчика сообщают о недоступности, а `Interrupt` останавливает будущие обратные вызовы NSGo, когда хост снова получает управление.

Веб пока не может изолировать пакет от страницы: его код получил бы доступ к собственной сети, буферу обмена и хранилищу страницы, включая хранилище доверия, в обход своих возможностей. Поэтому там `tsx.View` и `tsx.Load` отклоняют пакет с `tsx.ErrUnisolated`, если вы не зададите `Sandbox.WebUnisolated`, чтобы запустить его с полномочиями страницы, что подходит только для пакетов, которым вы доверили бы полномочия самого приложения.

## Редакторы и тесты

`tsconfig.json`, расширяющий `.nsgo/tsconfig.json`, даёт редакторам типы для TSX; этот файл записывают `go tool nsgo dev` и `go tool nsgo check`. Файлы `*.test.tsx` рядом с приложением, написанные с помощью `nsgo/test`, запускаются вместе с его тестами Go ([Тестирование](testing.md)).
