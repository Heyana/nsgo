## Разрешение

`cx.RequestNotificationPermission` просит пользователя разрешить приложению показывать уведомления (в первый раз — системным запросом) и отвечает значением `core.NotificationPermission`: `NotificationsGranted`, `NotificationsDenied` или `NotificationsUnavailable`, если платформа или сборка уведомлений не показывает. Запрашивайте разрешение в момент, когда пользователь делает что-то, для чего нужны уведомления: iOS и Android спрашивают только один раз, а браузеры отклоняют запрос, который не был вызван действием пользователя. `cx.NotificationPermission` читает ответ, ничего не запрашивая.

```go
cx.RequestNotificationPermission(func(p core.NotificationPermission) {
	if p == core.NotificationsGranted {
		cx.ShowNotification(core.Notification{ID: "chat:42", Title: "Ada", Body: "Lunch?"}, nil)
	}
})
```

## Показ уведомления

`cx.ShowNotification` показывает уведомление, в том числе когда приложение на переднем плане, и заменяет уведомление с тем же `ID`; `Silent` отключает системный звук и вибрацию. Функции `done` передаётся, приняла ли система уведомление (false, если разрешения нет), а для уведомления без ID или заголовка возвращается `core.ErrNotification` без вызова `done`. `cx.CloseNotification` удаляет уведомление с указанным ID.

```go
err := cx.ShowNotification(core.Notification{ID: "sync", Title: "Synced", Body: "12 notes"}, func(shown bool) {})
cx.CloseNotification("sync")
```

`cx.CloseNotifications` удаляет все уведомления, показанные приложением, и отменяет запланированные им. В macOS, iOS, watchOS, Windows и Android это включает уведомления, оставленные предыдущими запусками в Центре уведомлений, Центре поддержки или шторке; в Linux и вебе затрагиваются только уведомления, показанные или запланированные текущим запуском. Вызывайте её, когда приложение выходит на передний план и его окно показывает то, о чём сообщали уведомления:

```go
cx.Effect(func() {
	if cx.Env().Lifecycle() == core.LifecycleActive {
		cx.CloseNotifications()
		cx.SetBadge(0)
	}
})
```

## Планирование уведомления

Уведомление, у которого `At` позже текущего момента, планируется на будущее; повторный вызов `cx.ShowNotification` с тем же `ID` переносит его, а `cx.CloseNotification` отменяет до показа. `Repeat` показывает его каждый день в то же время суток, что и `At`, или каждую неделю ещё и в тот же день недели, начиная со следующего такого момента, в часовом поясе устройства. `cx.Env().CanScheduleNotifications()` сообщает, умеет ли платформа планировать уведомления: приложения macOS, iOS и watchOS в бандле, Android и Windows планируют их нативно, независимо от того, запущено ли приложение (Windows выстраивает ежедневные и еженедельные повторы цепочкой, пока приложение работает, и восстанавливает их при запуске), а Linux и веб (где доступен `Notification`) хранят их, пока работает приложение или страница. В остальных случаях (tvOS, чей центр показывает только счётчики, и мини-программы) `done` получает false.

```go
cx.ShowNotification(core.Notification{ID: "review", Title: "Cards to review", At: due}, nil)
cx.ShowNotification(core.Notification{ID: "habit", Title: "Practice",
	At: time.Date(2026, 1, 1, 9, 0, 0, 0, time.Local), Repeat: core.NotificationDaily}, nil)
```

Android может показать запланированное уведомление на несколько минут позже срока, пока телефон в режиме Doze; приложение, которому нужна точность до минуты, например будильник, указывает в `android.permissions` разрешение `android.permission.SCHEDULE_EXACT_ALARM`, которое пользователь выдаёт в системных настройках начиная с Android 12, или `USE_EXACT_ALARM`, которое Google Play разрешает только будильникам и календарям. Уведомления принудительно остановленного приложения Android ждут его следующего запуска. Чтобы проверить доставку после завершения процесса, дождитесь, пока `ShowNotification` ответит true, а затем завершите процессы приложения без принудительной остановки пакета.

## Нажатия

`cx.OnNotificationPress` вызывает свою функцию с `ID` уведомления, на которое нажал пользователь, пока жив компонент, который её установил, и выводит приложение на передний план. Нажатие, запустившее приложение, достаётся первому зарегистрированному обработчику. Храните в `ID` то, что должно открыться по нажатию (`"chat:42"`), поскольку нажатие может запустить приложение заново. В Windows это работает для приложения, которое установщик добавил в меню «Пуск»; в остальных случаях запуск получает нажатия только пока работает.

```go
cx.OnNotificationPress(func(id string) { openChat(strings.TrimPrefix(id, "chat:")) })
```

Приложение Android, запрашивающее разрешение начиная с Android 13, указывает `android.permission.POST_NOTIFICATIONS` в `android.permissions` файла `nsgo.yaml`.

## Счётчик на значке

`cx.SetBadge` выводит число на значок приложения: в Dock в macOS, на экране «Домой» в iOS (для этого нужно разрешение на уведомления), на кнопке панели задач в Windows, в совместимых с Unity лаунчерах Linux и на значке установленного веб-приложения. Число 0 или меньше убирает счётчик. Приложению macOS не нужно разрешение для счётчика в Dock, пока оно не проверит или не запросит разрешение на уведомления либо не покажет уведомление; с этого момента, в этом и последующих запусках, Dock показывает счётчик, только если пользователь разрешил наклейки приложения в Системных настройках, о чём `cx.RequestNotificationPermission` спрашивает вместе с оповещениями. В лаунчерах без интерфейса счётчиков Linux и в Android числа задать нельзя; лаунчеры Android помечают приложение, у которого есть показанные уведомления.

```go
cx.SetBadge(len(unread.Get()))
```

## Прогресс задачи

`cx.SetTaskProgress` показывает на значке приложения, насколько продвинулась длительная задача: полосой поверх плитки Dock в macOS, на кнопке панели задач в Windows и в совместимых с Unity лаунчерах Linux. Разрешение не требуется, и прогресс показывается рядом со счётчиком. `TaskProgressNormal` показывает `Value` — долю от 0 до 1; `TaskProgressPaused` и `TaskProgressError` окрашивают полосу в Windows и macOS; `TaskProgressIndeterminate` анимируется в Windows и выглядит неподвижной наполовину заполненной полосой в macOS и Linux; нулевое значение `TaskProgress` убирает прогресс. В Windows прогресс показывается на кнопке окна текущей области, а прогресс, заданный там, где у окна нет собственной кнопки, например в области самого приложения или в панели трея, показывается на всех окнах приложения, которые не задают свой. iOS, Android и веб ничего не показывают.

```go
cx.SetTaskProgress(core.TaskProgress{State: core.TaskProgressIndeterminate}) // no fraction yet
cx.SetTaskProgress(core.TaskProgress{State: core.TaskProgressNormal, Value: .43})
cx.SetTaskProgress(core.TaskProgress{}) // done
```
