Пакет `base/dragdrop` связывает источник и цель в одной области `Area` в пределах одного окна. Приложение сохраняет свои представления, стили, выделение и действие, обрабатывающее переданное значение. По умолчанию перетаскивание источника начинается после сдвига на четыре точки, оставляя обычное нажатие без изменений.

```go
import "github.com/nsgo-dev/nsgo/base/dragdrop"

dragdrop.Area{Children: []core.Node{
	dragdrop.Source{
		View: core.View{
			Label: "Film", TestID: "poster",
			Style: core.Style{Width: core.Pt(80), Height: core.Pt(80)},
			Children: []core.Node{core.Text{Content: "Poster"}},
		},
		Data: func() any { return filmID },
		Preview: func(any) core.Node { return core.Text{Content: "Film"} },
	},
	dragdrop.Target{
		View: core.View{
			TestID: "playlist",
			Style: core.Style{Width: core.Pt(160), Height: core.Pt(80)},
			Children: []core.Node{core.Text{Content: "Playlist"}},
		},
		Accept: func(value any) bool { _, ok := value.(string); return ok },
		OnDrop: func(e dragdrop.Event) { addToPlaylist(e.Data.(string)) },
	},
}}
```

Функция `Data` вызывается один раз при начале перетаскивания. Верните срез, чтобы переносить несколько выбранных элементов сразу; скопируйте там изменяемые данные, если они должны оставаться снимком состояния на момент старта. Значение `nil` из `Data` отключает перетаскивание. `Threshold` задаёт необходимое смещение. `Activation: dragdrop.AfterLongPress` сначала ждёт `View.DelayLongPress` (по умолчанию 500 мс), а затем движения; выбирайте этот режим явно там, где обычный свайп должен сначала прокручивать содержимое.

`View` сохраняет все свои обычные свойства, включая обработчики нажатия и параметры доступности. Источник управляет `View.Responder` самостоятельно — не задавайте это поле вручную. Внутри него могут находиться дочерние элементы, например кнопка со своим обычным действием. `Preview` следует за указателем, не перехватывая ввод и не перемонтируя источник; если превью не задано, отображается метка источника. У источника обязательно должна быть метка или превью. Вложенные области работают независимо.

Цели требуется `OnDrop`, чтобы принимать значение. Первой шанс получает самая внутренняя цель; если `Accept` отклоняет значение, его может принять принимающий предок. `OnEnter`, `OnMove` и `OnLeave` позволяют обновлять внешний вид цели. Каждое событие содержит `Data`, `Position` относительно цели и `PagePosition` относительно поверхности окна. Отключение или удаление активной цели сбрасывает её состояние входа; при отпускании проверка принятия выполняется повторно. Цель, перекрытая другим представлением, обрезанная, отключённая или находящаяся под модальным окном, не может принять сброс.

`OnStart` и `OnEnd` описывают жизненный цикл перетаскивания со стороны источника. `OnEnd` получает `Result{Data, Dropped, Target}`. Нажатие Escape, нативная отмена касания, отключение или удаление источника либо отпускание вне принимающей цели завершают сеанс без сброса. Положение цели берётся по последней зафиксированной геометрии; нативные анимации между коммитами не опрашиваются. Этот механизм передаёт значения внутри окна; для системных файлов по-прежнему используется `OnFileDrop`.

Предусмотрите меню, клавиатурную команду или действие доступности, выполняющее ту же операцию. Перетаскивание — это лишь удобный способ её вызвать. В тестах используется `app.DragTo("id:poster", "id:playlist")` или метод `DragTo` выбранной поверхности; в TSX-тестах — `await app.dragTo("id:poster", "id:playlist")`. Оба представления уже должны помещаться в видимую область окна; этот шаг отправляет последовательность касаний через обработчик откликов без искусственной симуляции сброса и без прокрутки во время перетаскивания. См. [Тестирование](testing.md).
