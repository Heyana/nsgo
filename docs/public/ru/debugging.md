## Запуск

```sh
go tool nsgo dev
```

`dev` собирает приложение для текущей машины и открывает его (либо для платформы, указанной в `dev.target` файла `nsgo.yaml`). При каждом сохранении Go-файла команда пересобирает и перезапускает приложение, предварительно выполняя `go mod tidy`, если приложение импортирует пакет, отсутствующий в `go.mod` или `go.sum`; изменение только TSX обновляет запущенное приложение на месте, сохраняя состояние. Выполнение завершается вместе с закрытием приложения.

На macOS и Windows нативная пересборка в dev-режиме заново открывает окно главного представления в его последнем обычном положении и размере в рамках текущей сессии. На Windows также восстанавливается полноэкранный режим. На Linux GTK восстанавливает обычный размер и запрашивает последний полноэкранный режим. Положение окна выбирает оконный менеджер.

Флаг `-target` запускает приложение на другой платформе, а `-device` выбирает iPhone, Apple TV, Apple Watch, симулятор или устройство Android по имени, UDID или серийному номеру:

```sh
go tool nsgo dev -target tui                # terminal cells; diagnostics in .nsgo/tui.log
go tool nsgo dev -target web                # in the browser, at the address it prints, on -port (8080 by default)
go tool nsgo dev -target ios_simulator      # in the iOS simulator
go tool nsgo dev -target ios                # on the connected iPhone, signed by Xcode
go tool nsgo dev -target tvos_simulator     # in the Apple TV simulator
go tool nsgo dev -target watchos_simulator  # in the Apple Watch simulator
go tool nsgo dev -target android            # on a connected device or emulator, over adb
go tool nsgo dev -target miniprogram_wechat # in WeChat DevTools (also _qq, _alipay, _douyin)
```

По умолчанию dev-сервер слушает на всех сетевых интерфейсах. Используйте `-host 127.0.0.1`, чтобы ограничить его loopback-интерфейсом, в том числе когда Android подключается через `adb reverse`, или укажите IP-адрес локального интерфейса для прослушивания только на нём. Для работы dev-функций на физических устройствах Apple используйте адрес, доступный по локальной сети.

`-h` выводит список всех флагов.

## Отладчик Go

Добавьте совместимую с вашей версией Go сборку [Delve](https://github.com/go-delve/delve/blob/master/Documentation/installation/README.md) в `PATH` под именем `dlv`. Запустите нативное десктопное приложение с отладочной информацией и отключённой оптимизацией Go.

```sh
go tool nsgo dev -target native -debug
```

Скопируйте порт из строки Delve `API server listening at`. В VS Code с расширением Go добавьте конфигурацию подключения (attach) и замените `40000` на этот порт.

```json
{
  "name": "Attach to NSGo",
  "type": "go",
  "request": "attach",
  "mode": "remote",
  "debugAdapter": "dlv-dap",
  "host": "127.0.0.1",
  "port": 40000
}
```

В GoLand добавьте конфигурацию запуска **Go Remote** с хостом `127.0.0.1` и тем же портом. Поставьте точку останова в Go-коде приложения, подключитесь и выполните действие, которое до неё дойдёт. После успешной пересборки Go переподключите отладчик к тому же адресу, чтобы он передал точки останова новому процессу. Изменения TSX по-прежнему используют горячую перезагрузку.

`-debug` работает на macOS, Windows и Linux с `-target native`. Используйте dev-сборку для отладки, а `-release` оставьте для замеров релизной сборки.

## Предпросмотр компонентов

Разместите одну или несколько функций `PreviewXxx` рядом с компонентами в импортируемом Go-пакете. Сохраните их в Go-файле, защищённом тегом сборки для предпросмотра.

```go
//go:build nsgopreview

package components

import "github.com/nsgo-dev/nsgo/core"

func PreviewEmpty(cx *core.Scope) core.Node {
    return core.Text{Content: "No items"}
}
```

```sh
go tool nsgo dev -preview ./components
go tool nsgo dev -target web -preview ./components
```

Отметьте фикстуры, которые нужно показать вместе, и выберите локаль, тему, светлое или тёмное оформление, размер области просмотра и направление раскладки. Предпросмотр берёт ближайший файл `nsgo.yaml` приложения, его каталоги переводов, настроенную `theme` и ресурсы. Передайте каталог приложения после флагов, чтобы выбрать другую конфигурацию в том же модуле. В этом случае путь к предпросмотру указывается относительно каталога приложения.

Сохранение файла пересобирает предпросмотр, сохраняя выбранные элементы и настройки отображения. Тег `nsgopreview` исключает фикстуры из обычных релизных сборок. Используйте ту же фикстуру в файле `_test.go` с таким же тегом через `nsgotest.Start(t, PreviewEmpty)` и запустите `GOFLAGS=-tags=nsgopreview go tool nsgo test -target macos ./components`, чтобы сделать нативный скриншот.

После первой установки основного приложения с `-target ios_simulator` пересборка, затрагивающая только Go-код, заменяет установленный исполняемый файл и перезапускает приложение. Редактирование `nsgo.yaml`, упакованных ресурсов или иконки приложения вызывает переустановку.

Используйте `go tool nsgo dev -target android -android-host` для работы над UI под Android с более коротким циклом пересборки Go. Инструмент устанавливает нативную среду выполнения один раз и запускает Go-код на машине разработчика. Каждая пересборка Go переподключается к той же Activity через adb. Изменения упакованных ресурсов, предкомпилированных классов, иконок запуска или `nsgo.yaml` переустанавливают APK среды выполнения. Go-процесс использует ограничения сборки, файлы и сеть хост-машины. `Scope.DiskSpace` сообщает о томе, на котором расположен `DataDir` хоста. Для проверки файлов `_android.go` и поведения Go на самом устройстве используйте обычную команду Android dev.

## Ошибки

Ошибка сборки отображается поверх работающего приложения с кнопками для копирования ошибки и повторной сборки; исправьте файл, и следующее сохранение заменит экран ошибки. Паника компонента при отрисовке показывается так же. Комбинация Command+R в приложении (Control+R вне платформ Apple) в любой момент пересобирает и перезапускает приложение, даже поверх экрана ошибки, если только приложение не перехватывает эту клавишу само через `cx.OnKey` или активный пункт меню приложения; в браузере эта комбинация как обычно перезагружает страницу. Собственный вывод приложения, например `log.Print`, появляется в терминале под строками инструмента.

Перед запуском команда `go tool nsgo check` проверяет приложение с помощью `vet` и выполняет проверку типов TSX; `-target all` проверяет его для каждой целевой платформы, поэтому код за тегами сборки других платформ также проверяется с Mac.

### Логи упакованных приложений Apple

На macOS, iOS, tvOS и watchOS стандартный логгер Go пишет в единый журнал Apple (unified log), включая `log.Print`, диагностику NSGo и вывод консоли TSX. В приложении Console фильтруйте по идентификатору бандла запущенного приложения в поле subsystem и по `nsgo` в поле category. На macOS журнал можно также запросить из терминала:

```sh
log show --last 10m --predicate 'subsystem == "dev.example.hello"'
```

Записи используют стандартный тип лога и сохраняют префиксы предупреждений или ошибок. Их текст публичен, поэтому не выводите в логи учётные данные и другие секреты. Длинные сообщения разбиваются на несколько записей. Во время разработки сохраняется вывод в терминал; собственный writer логов или обработчик `slog` управляет своим выводом самостоятельно.

### Веб-представления на Linux

В Ubuntu 24.04 и новее непривилегированные пространства имён пользователей (user namespaces) могут быть ограничены через AppArmor. Когда bubblewrap не может запустить песочницу WebKitGTK, NSGo записывает ошибку в лог и показывает заглушку. В противном случае некоторые версии WebKitGTK завершаются с `SIGTRAP` при открытии первого веб-представления ([документация Ubuntu AppArmor](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/)).

Используйте профиль AppArmor для bubblewrap из вашего дистрибутива, если он предусмотрен, например `bwrap-userns-restrict`. В противном случае администратор может загрузить профиль, выдающий разрешение `userns` для `/usr/bin/bwrap`, взяв за основу [профиль из Linux CI для NSGo](https://github.com/nsgo-dev/nsgo/blob/main/.github/workflows/test.yml). Профилем управляет администратор, поскольку он распространяется на все приложения, использующие системный bubblewrap.

`WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1` отключает песочницу подпроцессов WebKit. Используйте эту переменную только для локальной разработки с доверенным содержимым.

## DevTools

```sh
go tool nsgo dev -devtools
```

`-devtools` открывает в браузере инструменты разработчика (DevTools), раздаваемые `nsgo dev` для любой целевой платформы, включая приложение на телефоне. Они показывают работающее приложение в реальном времени:

- **Elements**: дерево представлений. Для каждого элемента отображаются создавший его компонент, ссылка на строку в редакторе, селектор для поиска в тестах, классы, границы, вычисленные отступы `margin`, `border` и `padding`, а также заданный стиль. Наведение на строку подсвечивает её отступы и содержимое прямо в приложении, как в DevTools браузера, а кнопка **Pick** позволяет нажать на любое представление в окне, панели, модальном листе или встроенном представлении, чтобы найти его в дереве.
- **State**: сигналы, созданные вашим кодом, сгруппированные по владеющим ими компонентам и вычислениям, с их значениями, значениями мемо и числом читающих их вычислений. Значение, которое не читает ни одно вычисление, ничего не меняет на экране. Строки, булевы значения и числа можно редактировать прямо здесь, чтобы проверить состояние без изменения кода. Значения, созданные самим NSGo, находятся под **NSGo's own**.
- **Profiler**: время каждого коммита, разделённое на ваш код до коммита, сам коммит с раскладкой и применение изменений в главном потоке платформы. Также показаны строки кода, записи в которых вызвали коммит, и открывается список выполненных вычислений, начиная с самых долгих. Второй список показывает вычисления, срабатывавшие чаще всего за последнюю секунду, с указанием строки их создания. Среда выполнения Android применяет пакеты изменений в собственном Java-коде, поэтому для коммитов Android платформенное время не отображается.
- **Recorder**: записывает нажатия, ввод текста, очистку и прокрутку в приложении в виде теста `nsgotest`, готового к копированию в файл `_test.go`. В разделе Elements кнопки **Assert shown** и **Assert text** добавляют проверку выбранного представления. Проверка текста сохраняет строку на том языке, на котором она отображалась в приложении, поэтому записывайте тесты на языке запуска ваших тестов.
- **Highlight updates**: обводит каждое изменённое коммитом представление, как флаг `-highlight`.
- **Layout**: включает и отключает [инспекцию раскладки](#раскладка) на устройстве, как флаг `-layout`.

В TSX-приложениях состояние, вычисления и записи привязываются к соответствующим строкам TSX через source maps бандла и ведут к файлам вашего приложения.

DevTools считывают состояние приложения через сервер `nsgo dev`, который слушает сеть, чтобы к нему могли подключаться телефоны. При каждом запуске генерируется токен, который передаётся после `#` в адресах, выводимых и открываемых `nsgo dev` для DevTools и веб-цели, и сервер отвечает только на запросы с этим токеном — поэтому открывайте DevTools и веб-версию именно по этим адресам. Любой, кому вы передадите такой адрес, сможет менять состояние работающего приложения и добавлять шаги в тест, записываемый в Recorder, поэтому просматривайте записанный тест перед запуском. Другие устройства в вашей сети и сторонние веб-страницы доступа к этому не имеют.

## Обновления

```sh
go tool nsgo dev -highlight
```

`-highlight` на полсекунды обводит контуром каждое представление, изменённое коммитом, чтобы обновление, перерисовывающее больше, чем нужно, сразу было видно на экране во время работы с приложением. Контуры рисуются поверх любого окна, панели, модального окна, листа iOS и встроенного представления (`nsgo.NewView`). DevTools позволяют включать и выключать эту подсветку во время работы приложения.

```sh
go tool nsgo dev -trace
```

`-trace` выводит информацию о каждом коммите запущенного приложения: его номер, длительность и отправленные элементы монтирования, чтобы вы видели, какие представления обновление создало, изменило или удалило. Над элементами указывается причина коммита: строки вашего кода, записывавшие сигналы со времени последнего коммита (от большего числа записей к меньшему), а также количество выполненных привязок, эффектов и мемо.

```text
── commit 12: 40 items, commit 1.65 ms
   after app/market.go:473 ×4, app/market.go:487 ×4, app/market.go:384
   ran 118 bindings, 18 effects, 5 memos
```

Строка, выполняющая запись много раз, или большое число привязок, срабатывающих на одну запись, указывают на места, где стоит сгруппировать записи (`cx.Batch`) или сузить область чтения привязки. `go tool nsgo test -trace` выводит такую же информацию под каждым шагом теста.

## Профили среды выполнения

Снимайте профили активности CPU Go, кучи (heap) или трассировки выполнения работающего приложения с помощью `nsgo dev`. Приложение отправляет снимок dev-серверу, который сохраняет его на машине, запустившей команду.

```sh
go tool nsgo dev -target android -profile cpu -profile-duration 10s
go tool pprof -top .nsgo/profiles/cpu.pprof
```

Снятие CPU-профиля работает также на десктопе, iPhone и симуляторе iOS. На iPhone разрешите доступ к локальной сети при запросе системы. Профиль кучи представляет собой мгновенный снимок и работает также в вебе. Для просмотра событий планировщика и горутин запустите `go tool nsgo dev -profile trace` и откройте `.nsgo/profiles/execution.trace` командой `go tool trace`. Длительность профилирования CPU и трассировки по умолчанию составляет 10 секунд. `-profile-output` задаёт путь к локальному файлу. При предпросмотре компонентов пути по умолчанию и относительные пути отсчитываются от каталога приложения. В режиме dev-запуска сохраняется первый завершённый профиль, после чего приложение продолжает работать.

```sh
go tool nsgo dev -target web -profile heap
go tool pprof -top .nsgo/profiles/heap.pprof
```

Браузерная среда выполнения Go поддерживает профили кучи и трассировки выполнения. Для сэмплирования CPU в браузере используйте вкладку Performance в инструментах разработчика браузера. Указывайте либо `-profile`, либо `-release`. При сборке с `nsgo build` клиент снятия профилей не включается в бинарный файл ([диагностика среды выполнения Go](https://go.dev/doc/diagnostics)).

## Раскладка

```sh
go tool nsgo dev -layout
go tool nsgo dev -layout=bounds,grid=4
```

`-layout` запускает приложение с инспекцией раскладки из DevTools поверх каждого окна, панели, листа iOS и встроенного представления, обводя каждое представление: его границу (`border box`) синим, внутренний край отступов `padding` зелёным, а внешний край отступов `margin` оранжевым — с обрезкой там, где их скрывает область прокрутки или обрезающий контейнер. `grid` рисует сетку с шагом 8 точек, а `grid=N` — с шагом N точек (минимум 4). Указывайте значение после `=`: флаг без значения означает `bounds`.

В нижнем углу выводится панель с размером окна в точках и кнопками включения/отключения рамок, сетки и линейки. На Apple TV и других устройствах только с пультом фокус доходит до кнопок этой панели, поэтому их можно переключать пультом, не выходя из приложения. Когда включена линейка, нажатия выбирают две точки вместо передачи событий в приложение, а на панели показывается расстояние между ними по горизонтали и вертикали; третье нажатие начинает измерение заново. На Apple TV или с клавиатуры стрелки (или свайп по сенсорной панели пульта Siri Remote) двигают перекрестие по экрану, а клавиши Select, Return или Space фиксируют точки, обновляя расстояние в реальном времени до выбора второй точки.

| Клавиша | Действие |
| --- | --- |
| `Cmd+Option+Shift+L`, `Ctrl+Alt+Shift+L` | Показывает или скрывает инспекцию в сборке с `-layout` |
| Стрелки, крестовина пульта / свайп | Сдвигает перекрестие линейки на шаг сетки (по умолчанию 8 pt) |
| `Shift` + стрелки | Сдвигает перекрестие линейки на 1 pt |
| Select, `Return`, `Space` | Выбирает точку под перекрестием во время измерения |
| `Esc`, Назад, Menu | Завершает измерение |

Если ваше приложение само привязывает ту же комбинацию клавиш, приоритет остаётся за приложением. Если клавиши недоступны (например, на телефоне), запустите приложение также с `-devtools` и включайте или выключайте инспекцию кнопкой **Layout** в DevTools; скрывайте её, чтобы нажать на элемент под панелью. Нативные бэкенды и веб считывают матрицы отображения (presentation matrices), поэтому границы, Pick и инспекция учитывают отображаемые трансформации, анимацию и прокрутку; watchOS учитывает своё аффинное рисование. HarmonyOS и мини-программы используют трекер на стороне Go, пока их слои отрисовки не начнут сообщать геометрию. Перерисовка наложений отнимает время на каждом обновлении, поэтому замеряйте скорость без них.

## Производительность

```sh
go tool nsgo dev -fps
go tool nsgo dev -release -fps
```

`-fps` выводит монитор производительности поверх приложения на macOS, iOS, Windows, Linux и Android. Он измеряет частоту кадров и коммиты, а на Android дополнительно показывает время кругового обращения (round-trip) для нативного текста. Dev-сборки содержат dev-клиент; для замеров используйте `-release`, который собирает приложение так же, как `nsgo build`.

## Языки и оформление

```sh
go tool nsgo dev -lang zh-Hans
go tool nsgo dev -lang en-XA   # accented and longer, to find untranslated and cut text
go tool nsgo dev -lang ar-XB   # right to left
```

`-lang` запускает приложение с указанной локалью, включая псевдолокали ([Локализация](localization.md)).

## Агенты

```sh
go tool nsgo dev -automation
go tool nsgo dev -target android -automation
go tool nsgo dev -target web -automation
```

`-automation` позволяет ИИ-агенту или сквозному (end-to-end) тесту управлять запущенным приложением так же, как это делает человек — на macOS, Windows, Linux (`-target native`), Android (`-target android`), в вебе (`-target web`), мини-программах в симуляторах их инструментов разработки (`-target miniprogram_wechat`, `miniprogram_qq`, `miniprogram_alipay` или `miniprogram_douyin`), а также на устройствах и симуляторах Apple (`-target ios`, `tvos`, `watchos`, `ios_simulator`, `tvos_simulator` или `watchos_simulator`): просматривать список окон, получать структуру отображаемого окна, нажимать, вводить текст, отправлять клавиши, прокручивать, перетаскивать, наводить курсор, выбирать пункты меню, отвечать на диалоги, ждать появления элементов и делать скриншоты. Агенты подключаются по протоколу MCP через `go tool nsgo mcp`, который использует процесс `dev -automation`, запущенный для данного каталога, либо запускает его с теми же флагами (например, `-target android`) и останавливает при отключении клиента:

```sh
claude mcp add nsgo -- go tool nsgo mcp
```

Другие клиенты принимают ту же команду — `go` с аргументами `tool nsgo mcp`, запускаемую в каталоге приложения. Представления адресуются селекторами из [тестов](testing.md#тест) или ссылками `view:`, которые выводит снимок состояния (после сохранения файла и перезапуска приложения эти ссылки устаревают).

Агент работает с реальными данными приложения так, как оно запущено через `dev`. Эта возможность включена только в сборках `dev -automation`, и доступ к ней имеют только инструменты на этой машине, обладающие токеном из `.nsgo/automation.yaml`, который доступен для чтения только вам.

### MCP-инструменты, определяемые приложением

Вызовите `automation.Register` из Go-приложения или библиотеки на горутине движка. Например, эта функция передаёт агентам идентификатор текущей отображаемой сцены.

```go
import (
    "context"
    "encoding/json"

    "github.com/nsgo-dev/nsgo/automation"
    "github.com/nsgo-dev/nsgo/core"
)

func registerSceneTool(cx *core.Scope, sceneID *core.Signal[string]) error {
    return automation.Register(cx, automation.Tool{
        Name:        "current_scene",
        Description: "Read the ID of the active scene",
        InputSchema: json.RawMessage(`{"type":"object"}`),
        Handler: func(_ context.Context, _ json.RawMessage) (any, error) {
            return map[string]string{"id": sceneID.Get()}, nil
        },
    })
}
```

Имя должно быть уникальным в графе приложения и отличаться от встроенных имён. `nsgo mcp` включает инструмент в список до тех пор, пока область видимости не будет очищена. Обработчик выполняется на горутине движка, поэтому он может читать и изменять сигналы. Он получает JSON-объект, проверяет нужные аргументы и возвращает значение, сериализуемое в JSON, либо ошибку.

В тесте сохраните область видимости при старте приложения, вызовите `automation.Call(cx, ctx, name, args)` внутри `app.Post`, а затем используйте `app.Settle()` перед проверкой результата или представления. Регистрация активна в `dev -automation` и тестах и ничего не делает в релизных сборках.

## Флаги любой сборки

Любая сборка приложения, включая упакованные релизы, принимает собственные флаги NSGo при запуске — они переопределяют `nsgo.yaml` и код приложения и никогда не попадают во флаги самого приложения:

| Флаг | Действие |
| --- | --- |
| `--nsgo-fps` | Показывает монитор производительности на macOS, iOS, Windows, Linux и Android |
| `--nsgo-lang=zh-Hans` | Запускает приложение в указанной локали, включая псевдолокали |
| `--nsgo-appearance=dark` | Запускает приложение в теме `light`, `dark` или по настройке `system` |
| `--nsgo-os=ios` | Запускает веб-сборку в режиме `macos`, `windows`, `linux`, `ios` или `android`, где `web` соответствует самому себе |

```sh
./Hello --nsgo-fps                                   # Windows and Linux
open Hello.app --args --nsgo-fps                     # macOS
xcrun simctl launch booted dev.example.hello --nsgo-fps
adb shell am start -n dev.example.hello/dev.oneo.nsgo.NsgoActivity --ez nsgo-fps true --es nsgo-lang de
```

В вебе они передаются в строке запроса страницы: `?nsgo-fps&nsgo-lang=de`.

`--nsgo-os` позволяет предварительно посмотреть раскладку для другой платформы прямо в браузере: приложение считывает указанную ОС и её идиому — телефон для iOS и Android и десктоп для остальных, — а `Env.Simulated` возвращает true. В браузере отсутствуют нативные компоненты этой платформы: место системных элементов занимают `NavHeader` и отрисованная панель вкладок, отсутствуют меню приложения, нативное всплывающее меню (`desktop.PopupMenu`) и функции окон, а `mobile.IsAvailable` и `desktop.IsAvailable` равны false. Отрисованные меню вроде `ui.ContextMenu` и `ui.Menu` продолжают работать. Горячие клавиши следуют раскладке клавиатуры посетителя. Остальные сборки игнорируют этот флаг и выводят предупреждение в лог.
