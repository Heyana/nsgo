## Прежде чем начать

Для всего, что крупнее простого исправления, откройте issue или discussion, чтобы согласовать архитектуру до написания кода. Открытые вопросы дизайна перечислены в [ARCHITECTURE.md](https://github.com/nsgo-dev/nsgo/blob/main/ARCHITECTURE.md#open-questions); решения по ним принимаются в первую очередь там.

## Все бэкенды

Исправление или новая возможность в одном бэкенде обычно должны появиться и в остальных. Вносите одинаковые изменения для всех затронутых платформ или фиксируйте то, что пока отсутствует, в [дорожной карте](https://github.com/nsgo-dev/nsgo/blob/main/docs/roadmap.md). Компоненты выглядят и ведут себя одинаково на каждой платформе.

## Проверки

Используйте инструмент `nsgo` вместо `go vet`, `go test` или `go build`:

```sh
go tool nsgo check   # vet every package
go tool nsgo test    # every package's tests
```

Добавьте тест для того, что вы меняете: `nsgotest` — для видимого пользователю поведения, собственные тесты пакета — для остального. Запустите галерею на затронутых платформах ([Настройка окружения для разработки](../contributing.md#the-gallery)).

Форматируйте Go-файлы с помощью `gofmt` из версии Go, указанной в `go.mod`; команда `gofmt -l .` выводит список файлов, требующих форматирования. CI проверяет каждый отслеживаемый Go-файл и падает со списком неотформатированных.

## Pull request

Оформите заголовок в формате Conventional Commits, например `fix(linux): keep the caret after a paste`: при squash-слиянии заголовок становится темой коммита, и проверка не пропустит PR, пока заголовок не соответствует формату. В шаблоне требуется указать затронутые платформы, приложить скриншоты «до» и «после» для любых визуальных изменений и перечислить выполненные проверки.

## Документация и changelog

- Обновите документ, факты в котором изменились: соответствующий раздел в `docs/architecture/` для внутреннего устройства NSGo, страницу в `docs/public/` для описания использования в приложениях и компонентах ([Документация и сайт](docs.md)).
- Поддерживайте эквивалентность `README.md` и `README.zh-CN.md`; всё остальное ведётся на английском языке, а китайские страницы располагаются в `docs/public/zh/`.
- Опишите заметное пользователям изменение одной строкой со ссылкой вида `(#12 by @you)` в отдельном файле в `changelog.d/` под заголовком соответствующего типа, например `### Fixed`, а не напрямую в `CHANGELOG.md`, который заполняется из этих файлов при релизе ([формат](https://github.com/nsgo-dev/nsgo/blob/main/changelog.d/README.md)).
