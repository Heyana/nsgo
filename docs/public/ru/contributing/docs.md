## Страница

Эта документация — файлы Markdown в `docs/public/`, которые удобно читать прямо на GitHub. `en/` и `zh/` зеркально повторяют структуру путей; при отсутствии страницы на китайском языке показывается английская версия с уведомлением. Каждая страница начинается с метаданных front matter:

```yaml
---
title: Testing
description: Test an app the way a user uses it, headless or in a native window.
group: Toolchain
order: 21
---
```

- `group` — группа страницы в боковой панели на языке страницы, а `order` определяет её порядок. Группы следуют пути читателя: учебники, инструменты, компоненты, основные концепции, затем написание компонентов и участие в разработке. Страницы без группы, например введение, идут перед ними.
- Макет отображает заголовок и описание, поэтому основной текст начинается с `##`.

Ссылайтесь между страницами с помощью относительных `.md`-ссылок (`[Тестирование](testing.md#run-on-a-platform)`); сайт преобразует их в свои URL. Каждая страница отвечает на один вопрос; внутреннее устройство NSGo остаётся в `docs/architecture/`.

## Сайт

Сайт в каталоге `website/` собирается с помощью [nsgo-website](https://github.com/nsgo-dev/nsgo-website) — интеграции для Astro, — на основе настроек в `website/site.config.ts`. Для работы требуется [Bun](https://bun.com) 1.4 или новее:

```sh
cd website
bun install
bun run dev    # at http://localhost:4321/
bun run build  # type-check and build, as the deployment does
```

В файле `website/README.md` описано, как сайт собирается и публикуется.

## Для агентов

Сайт также публикует английские страницы для языковых моделей: `/llms.txt` содержит их список, `/llms-full.txt` — полный текст всех страниц, а `/docs/<page>.md` — отдельную страницу с абсолютными ссылками и без разметки блоков кода (`src/lib/llms.ts`). Они обновляются вслед за страницами без отдельного шага.

`skills/nsgo/` — это навык (skill), который агенты устанавливают командой `bunx skills add nsgo-dev/nsgo`: файл `SKILL.md` с правилами для приложений и каталог `references/`, который читается при необходимости для конкретной задачи. Обновляйте его вместе с документацией, когда меняются способы написания приложений, команды инструмента, тестирование или сборка пакетов; оставляйте в нём только то, чему агент обязан следовать, а на остальное давайте ссылки на документацию. Команда `go tool nsgo test -run TestSkills .` проверяет его front matter, ссылки и каждое упоминаемое имя из NSGo.
