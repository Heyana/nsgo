NSGo — это единый Go-модуль. Приложения импортируют его пакеты сверху; бэкенд каждой платформы находится внизу и получает изменения в виде нативных представлений для создания, обновления и удаления.

## Пакеты

| Пакет | Содержимое |
| --- | --- |
| `nsgo` (корень) | `nsgo.Run` и `nsgo.NewView`, выбор бэкенда через теги сборки |
| `core` | API приложения: элементы, стили, классы, темы, сигналы и сервисы; раскладка и подготовка текста |
| `base` | Нестилизованные компоненты, по файлу на каждый, и сложные компоненты в виде пакетов (`base/dock`, `base/editor`) |
| `ui` | Компоненты `base` с оформлением, а также пакеты вроде `ui/chat` |
| `mobile`, `desktop` | Возможности, специфичные только для телефонов или только для десктопов |
| `tsx` | TSX-приложения, их сборщик и компилятор, а также импортируемые ими модули |
| `i18n`, `*/locales` | Каталоги сообщений и сгенерированный из них код |
| `nsgotest` | Тесты, имитирующие действия пользователя — в безголовом режиме или на платформе |
| `internal/engine`, `internal/driver`, `internal/layout` | Горутина движка, протокол монтирования и раскладка |
| `internal/platform/<target>` | Бэкенд: нативные представления, текст и ввод для одной целевой платформы |
| `cmd/nsgo` | Инструмент `nsgo` |
| `examples/` | Галерея и другие примеры приложений |

Пакеты импортируются только сверху вниз; `internal/moduletest/layering_test.go` проверяет граф зависимостей на каждой платформе.

## Проектные документы

[ARCHITECTURE.md](https://github.com/nsgo-dev/nsgo/blob/main/ARCHITECTURE.md) описывает карту пакетов, потоки выполнения и путь от коммита до экрана, а также перечисляет темы в `docs/architecture/`: по одной на каждую подсистему, например раскладку, текст, прокрутку, темы или CLI-инструмент. Прочитайте документ по той части, которую собираетесь менять, перед началом работы; в нём описано, как устроена подсистема и где она отходит от [Native Shell](https://github.com/longbridge/nsh), дизайн которого портирует NSGo.

[AGENTS.md](https://github.com/nsgo-dev/nsgo/blob/main/AGENTS.md) содержит правила, которым должно следовать любое изменение — как от разработчиков, так и от ИИ-агентов. Несколько ключевых правил определяют большинство изменений:

- У каждого API одно место: `core` для элементов и окружения, `base` для логики элементов управления, `ui` для их оформления, `mobile` и `desktop` для конкретного класса устройств.
- У `base` нет визуального оформления; компонент `ui` — это его аналог из `base` с оформлением.
- Ничто не меняется неявно в зависимости от типа устройства: в `core` и `base` нет увеличенных элементов управления на десктопе или уменьшенных на телефонах.
- Нативные представления везде и одинаковы на каждой платформе: то, что одна платформа предоставляет нативно, остальные имитируют.
- Никакого рукописного кода на C и ничего кроме macOS, Xcode и Go для сборки всех целевых платформ, кроме эмулятора Android под x86_64.

Список того, что пока отсутствует на каждой платформе, находится в [дорожной карте](https://github.com/nsgo-dev/nsgo/blob/main/docs/roadmap.md).
