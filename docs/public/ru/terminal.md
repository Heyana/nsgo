`base/terminal` предоставляет сеанс (`Terminal`) и его `View`. Настольные платформы запускают локальные программы; iOS и браузеры используют `Options.Conn` — `io.ReadWriteCloser`, подключённый к удалённой программе. Сеансом владеет приложение, и оно закрывает его по завершении.

```go
t, err := terminal.New(terminal.Options{CursorBlink: true})
if err != nil {
	return core.Text{Content: err.Error()}
}
cx.Cleanup(func() { t.Close() })
return terminal.View{
	Terminal: t, AutoFocus: true,
	MinimumContrast: 4.5, PaddingColor: terminal.PaddingExtend,
	Style: core.Style{FlexGrow: 1},
}
```

`Options.Cursor` выбирает форму курсора по умолчанию: блок, вертикальная черта или подчёркивание. `CursorBlink` включает мигание по умолчанию; при нулевом значении курсор остаётся неподвижным. Программы переопределяют форму и мигание через DECSCUSR или режим DEC 12. Курсор без фокуса полый и не мигает; во время композиции ввода и при уменьшенном движении он тоже не мигает. Миганием управляют часы анимации платформы, без перерисовки текста терминала движком.

`View.Font`, `Theme` и `DarkTheme` задают шрифт и палитру. Сетка сама рисует символы псевдографики и блоков Unicode, а также разделители Powerline U+E0B0–U+E0B7, выравнивая соседние ячейки по пикселям устройства. Остальной текст использует шрифты платформы и их запасные варианты.

`MinimumContrast` повышает контраст обычного текста относительно фактического фона его ячейки, включая инвертированные цвета, бледный текст и выделение. Значения 1–21 используют коэффициент контрастности WCAG; ноль сохраняет цвета. Графика и эмодзи сохраняют свои цвета. При `Transparent` контраст всё равно рассчитывается относительно настроенного фона терминала.

`Padding` оставляет место вокруг сетки, в пунктах. `PaddingColor` выбирает его фон:

| Значение | Поведение |
| --- | --- |
| `PaddingBackground` | Фон терминала, включая изменения через OSC 11 |
| `PaddingExtend` | Фон ближайшей ячейки; на основном экране верхнее и нижнее продление не применяется рядом со строками приглашения, строками Powerline или строками, содержащими ячейку с фоном по умолчанию |
| `PaddingExtendAlways` | Продлевать все края без этих исключений |

TSX-приложения импортируют `tsx/terminal` ради его побочного эффекта — регистрации `Terminal` в `nsgo/base`. Свойства: `cursorBlink`, `minimumContrast` и `paddingColor`; последнее принимает `background`, `extend` и `extend-always`. Свойства внешнего вида можно менять, пока сеанс продолжается.

## В браузере

Приложение встраивает зафиксированный модуль WebAssembly libghostty-vt и использует то же представление терминала и тот же путь ввода. Для сборки приложения не нужны Zig, установка нативной библиотеки или загрузка во время выполнения.

Адаптируйте WebSocket браузера к `io.ReadWriteCloser`: отправляйте двоичные байты и объединяйте или разделяйте входящие сообщения как поток. Аутентификацией, переподключением и любыми сообщениями об изменении размера или управляющими сообщениями владеют приложение и его сервер; NSGo потребляет байты терминала. [Приёмочный тест для браузера](https://github.com/nsgo-dev/nsgo/blob/main/internal/testhost/testdata/terminalweb/socket_js_test.go) показывает полный адаптер потока байтов с обработкой закрытия.

## Действия и масштабирование

`View.Keybinds` переопределяет привязки по умолчанию с помощью `Keybind{Key, Action, Amount}`. Клавиши используют те же имена, что и `Scope.OnKey`, например `mod+=` или `ctrl+shift+c`. Более поздние записи имеют приоритет. Привязки срабатывают, пока ввод этого терминала находится в фокусе и метод ввода не выполняет композицию.

Действия: `CopyToClipboard`, `PasteFromClipboard`, `SelectAll`, `ClearScreen`, `IncreaseFontSize`, `DecreaseFontSize`, `ResetFontSize`, `SetFontSize` и `Ignore`. Действия с окнами и вкладками относятся к раскладке клавиш приложения. `Ignore` поглощает клавишу, не отправляя её программе.

По умолчанию `mod+=` и `mod+shift+=` увеличивают шрифт на один пункт, `mod+-` уменьшает его, а `mod+0` сбрасывает размер до `View.Font.Size` (13, если не задан). `Amount` задаёт шаг увеличения или уменьшения (один при нулевом значении) либо размер для `SetFontSize`. Размеры ограничиваются диапазоном 1–255 пунктов; неконечные значения игнорируются. Масштабирование сохраняет сеанс и внешнее представление, обновляет число строк и столбцов сетки и изменяет размер программы.

```go
ref := &terminal.Ref{}
view := terminal.View{
	Terminal: session, Ref: ref,
	Keybinds: []terminal.Keybind{
		{Key: "ctrl+shift+k", Action: terminal.ClearScreen},
		{Key: "mod+=", Action: terminal.IncreaseFontSize, Amount: 2},
	},
}
```

`Ref.FontSize()` отслеживается для элементов управления, которые его отображают; `Ref.SetFontSize(size)` и `Ref.Perform(action, amount)` выполняются в движке приложения, как и обработчики событий. `Perform` сообщает, доступно ли действие. Несмонтированная ссылка возвращает нулевой размер и отклоняет действия.

## Контекстное меню

Вторичный щелчок открывает нестилизованное `base.ContextMenu` с локализованными пунктами «Копировать», «Вставить», «Выделить всё» и «Очистить». Для копирования требуется выделение. «Очистить» удаляет содержимое выше строки приглашения и недоступно на альтернативном экране. На сенсорных экранах используется представление контекстного меню по долгому нажатию. Стилизуйте поверхность с помощью `MenuClass`/`MenuStyle`, а пункты — с помощью `MenuItemClass`/`MenuItemStyle`.

Задайте `RightClickAction` значение `RightClickPaste`, `RightClickCopy`, `RightClickCopyOrPaste` (скопировать выделение, иначе вставить) или `RightClickIgnore`. Ignore оставляет событие для охватывающего меню приложения; используйте его, когда предоставляете стилизованное `ui.ContextMenu`, вызывающее действия ссылки.

Импортируйте `tsx/terminal`, чтобы зарегистрировать `<Terminal>` в `nsgo/base`. Его реактивные свойства `keybinds` и `rightClickAction` обновляют представление, сохраняя сеанс. Значения действий используют имена Ghostty, например `increase_font_size` и `copy_to_clipboard`; значения для правого щелчка — `context-menu`, `paste`, `copy`, `copy-or-paste` и `ignore`. Свойства стилизации меню используют имена из Go в нижнем camelCase.

## Отчёты о мыши

Программы, включившие отслеживание мыши, получают запрошенные нажатия, отпускания, перетаскивания и наведение, закодированные libghostty-vt в выбранном ими протоколе. Shift обходит перехват щелчков и перетаскивания для выделения. `View.MouseReporting` — необязательная реактивная `func() bool`, при nil равная true; верните false, чтобы сохранить выделение мышью и нативную прокрутку истории, даже когда программа запрашивает перехват. Правый щелчок программы имеет приоритет над охватывающим контекстным меню, пока отчёты включены.

На альтернативном экране, когда включён режим альтернативной прокрутки и отслеживание мыши не запрошено, вертикальная прокрутка колесом превращается в клавиши курсора в соответствии с обычным или прикладным режимом клавиш курсора. `MouseScrollMultiplier{Precision: 1, Discrete: 3}` задаёт число отчётов по умолчанию для сенсорных панелей и колёс; ноль использует эти значения по умолчанию, а положительные значения ограничиваются диапазоном 0,01–10 000. Дробный ввод накапливается, пока не наберётся полный шаг. Обычная история прокрутки сохраняет нативную прокрутку и инерцию платформы.

Импортируйте `tsx/terminal`, чтобы зарегистрировать `<Terminal>` в `nsgo/base`. Его свойство `mouseReporting` по умолчанию равно true; `mouseScrollPrecision` и `mouseScrollDiscrete` задают множители.
