NSGo は1つの Go モジュールです。アプリは上位のパッケージをインポートし、最下層にある各プラットフォームのバックエンドが、作成・更新・削除すべきネイティブビューとして変更内容を受け取ります。

## パッケージ

| パッケージ | 役割 |
| --- | --- |
| `nsgo`（ルート） | `nsgo.Run` と `nsgo.NewView`。ビルドタグによってバックエンドを選択 |
| `core` | アプリ向け API：要素、スタイル、クラス、テーマ、シグナル、サービス、およびレイアウトとテキスト準備 |
| `base` | スタイルなしコンポーネント（1ファイル1コンポーネント）。複雑なものはパッケージ化（`base/dock`、`base/editor`） |
| `ui` | 見た目を持つ `base` コンポーネントと、`ui/chat` などのパッケージ |
| `mobile`, `desktop` | スマートフォン専用またはデスクトップ専用の機能 |
| `tsx` | TSX アプリ、そのバンドラとコンパイラ、およびインポート可能なモジュール |
| `i18n`, `*/locales` | メッセージカタログとそこから生成されるコード |
| `nsgotest` | ユーザーとして操作するテスト（ヘッドレスまたはプラットフォーム上） |
| `internal/engine`, `internal/driver`, `internal/layout` | エンジンゴルーチン、マウントプロトコル、レイアウト |
| `internal/platform/<target>` | バックエンド：特定ターゲット向けのネイティブビュー、テキスト、入力 |
| `cmd/nsgo` | `nsgo` ツール |
| `examples/` | ギャラリーとその他のサンプルアプリ |

パッケージのインポートは下方向のみに限定されています。`internal/moduletest/layering_test.go` が全ターゲットでこの依存グラフを検証します。

## 設計ドキュメント

[ARCHITECTURE.md](https://github.com/nsgo-dev/nsgo/blob/main/ARCHITECTURE.md) にはパッケージ構成、スレッドモデル、コミットから画面描画までの流れがまとめられており、さらに `docs/architecture/` 内の各トピック（レイアウト、テキスト、スクロール、テーマ、ツールなど）が一覧されています。ある部分を変更する前に対応するトピックを読んでください。その部分の仕組みと、NSGo が設計を移植している [Native Shell](https://github.com/longbridge/nsh) からどこを変更したかが記録されています。

[AGENTS.md](https://github.com/nsgo-dev/nsgo/blob/main/AGENTS.md) には、人間とコーディングエージェントの双方がすべての変更で従うべきルールが書かれています。多くの変更に影響する主なルールは次の通りです：

- 各 API には1つの居場所だけを持たせる：要素と環境は `core`、コントロールは `base`、見た目は `ui`、特定デバイス種別向けは `mobile` と `desktop`。
- `base` には見た目を持たせない：`ui` コンポーネントは `base` の実装に見た目を付けたもの。
- デバイスによる暗黙の変更をしない：`core` や `base` でデスクトップならコントロールを大きく、スマートフォンなら小さくするといった挙動を入れない。
- どこでもネイティブビューを使い、すべてのプラットフォームで同じ振る舞いにする：あるプラットフォームにネイティブ機能があるなら、他ではそれを模倣する。
- 手書きの C コードは使わず、x86_64 Android エミュレータ以外の全ターゲットのビルドに macOS・Xcode・Go 以外を必要としない。

プラットフォームごとの未実装項目は[ロードマップ](https://github.com/nsgo-dev/nsgo/blob/main/docs/roadmap.md)にあります。
