UI フレームワークの中での NSGo の立ち位置は、3つの選択から生まれています。アプリは Go（またはその上の TSX）で書き、各プラットフォームは自身のビューで描画し、1つのコードベースでスマートフォン、デスクトップ、Web をカバーするという選択です。他のフレームワークは異なる選択をしており、それぞれの選択にはトレードオフがあります。

## 一覧

| フレームワーク | 言語 | 描画方式 | ターゲット |
| --- | --- | --- | --- |
| NSGo | Go, TSX | 各プラットフォームのビュー | iOS, App Clips, tvOS, watchOS, Android, macOS, Windows, Linux, Web; ミニプログラム（実験的） |
| [NSH](https://nsh.dev) | Rust, TSX | 各プラットフォームのビュー | iOS, Android, macOS, Windows, Linux, Web, GPUI アプリ, ターミナル; コミュニティプラットフォーム経由で HarmonyOS と WeChat ミニプログラム |
| [MyGo](https://github.com/egoist/mygo) | Go, Web ページ | 独自の GPU レンダラ、またはシステム WebView | macOS, Windows, Linux, Web |
| [Fyne](https://fyne.io), [Gio](https://gioui.org) | Go | 独自のレンダラ | デスクトップ, スマートフォン, Web |
| [Wails](https://wails.io) | Go, Web ページ | システム WebView | デスクトップ |
| [Flutter](https://flutter.dev) | Dart | 独自のレンダラ | スマートフォン, デスクトップ, Web |
| [Compose Multiplatform](https://www.jetbrains.com/compose-multiplatform/) | Kotlin | 独自のレンダラ; Android では Compose | スマートフォン, デスクトップ, Web |
| [React Native](https://reactnative.dev) | JavaScript, TSX | 各プラットフォームのビュー | iOS, Android; コミュニティプラットフォーム経由でその他 |
| [.NET MAUI](https://dotnet.microsoft.com/apps/maui) | C# | 各プラットフォームのコントロール | iOS, Android, macOS, Windows |
| [Avalonia](https://avaloniaui.net) | C# | 独自のレンダラ | デスクトップ, スマートフォン, Web |
| [Qt](https://www.qt.io) | C++, QML | 独自のレンダラ | デスクトップ, スマートフォン, 組み込みデバイス |
| [Electron](https://www.electronjs.org), [Tauri](https://tauri.app) | Web ページ; Tauri では Rust | 同梱の Chromium; Tauri ではシステム WebView | デスクトップ; Tauri ではスマートフォン |

## 強み

- **ネイティブビュー。** テキスト、インプットメソッド、選択、スクロール、アクセシビリティ、メニューは各プラットフォーム固有のものを使うため、アプリはユーザーがその環境で期待する通りに動作します。一方、自前で描画するフレームワークはこれらすべてを再実装します。iOS の Liquid Glass のように1つのプラットフォームだけにある表現は、切り捨てるのではなく他のプラットフォームでも同じように模倣します。
- **きめ細かな更新。** コンポーネントは一度だけ実行され、シグナルはそれを読み取る部分だけを更新します。仮想 DOM やフレームごとのビュー関数の差分計算は不要で、アニメーションはプラットフォームのフレームクロック上で動作します。
- **最小のパッケージと最速の起動。** [ベンチマーク](https://nsgo.dev/benchmarks/)では、同じカウンターアプリが macOS、Windows、Linux で約 8 MB にパックされ、MyGo、GPUI、NSH（NSH は 33〜45 MB）より小さくなります。起動も最速で、MyGo や GPUI のような GPU 描画フレームワークより少ないメモリで動作します。
- **Go のみ。** エンジン、レイアウト、バックエンドはすべて Go で書かれており、Go アプリには C も cgo も JavaScript エンジンも不要です。
- **1台の Mac から全プラットフォームへ。** Go と Xcode を入れた Mac が1台あれば、すべてのターゲットをクロスコンパイルできます。NDK、Android SDK、JDK、GTK、Windows ツールチェーンは不要です。
- **1コマンドで全リリースファイルを生成。** `nsgo build` は、署名・公証済みの macOS ディスクイメージ、署名済み Windows インストーラ、deb / Arch パッケージと AppImage、Mac App Store / Microsoft Store / Google Play / Flathub 向けパッケージ、さらに GitHub Releases からインストールするスクリプトを生成します（[ビルドと配布](building.md)）。
- **各プラットフォーム固有のアップデート。** macOS では Sparkle、Windows では WinSparkle が次バージョンをダウンロード・検証・インストールします。Linux と Android ではアプリが更新を検出してリリースページを開き、iOS では App Store が更新します。ストア経由でインストールされたアプリは、そのストアに更新を任せます（[アップデート](building.md#アップデート)）。
- **あらゆるプラットフォームに対応。** スマートフォン、タブレット、TV、ウォッチ、デスクトップ、Web が1つのエンジンと1つの API を共有し、さらに iOS App Clips、iPhone / Mac ウィジェット、そして実験的に WeChat、QQ、Alipay、Douyin のミニプログラムにも対応します。
- **組み込み。** NSGo アプリを既存の iOS、Android、Go デスクトップ、Web アプリ内のビューとして配置し、1画面ずつ段階的に移行できます（[組み込み](embedding.md)）。
- **高速な開発ループ。** Go ファイルを保存するとアプリがリビルド・再起動され、TSX を変更すると実行中のアプリの状態を保ったままその場で更新されます。ビルドエラーや描画中のパニックはアプリ上にオーバーレイ表示されます（[実行とデバッグ](debugging.md)）。
- **どこでも使える共通テスト。** テストはユーザーと同じようにテキストやロールでコントロールを見つけて操作でき、ウィンドウなしで高速に実行することも、各ターゲットの実際のウィンドウ上でプラットフォーム固有の入力を使いながら変更なしで実行し、スクリーンショットを保存することもできます（[テスト](testing.md)）。
- **組み込みのローカライズ。** アプリとそのコンポーネントの文言はカタログで管理され、擬似ロケールによって未翻訳、文字切れ、右横書き（RTL）未対応の箇所を見つけられます（[ローカライズ](localization.md)）。
- **Go で書くシェーダー。** `core.Shader` は Go 構文または WGSL で書かれた GPU シェーダーをすべてのプラットフォームで実行します（[キャンバス](canvas.md#シェーダー)）。
- **必要なときに TSX を使える。** Go コンポーネントと同じエンジン上で、Tailwind クラスを使った TSX で画面を書くこともできます。

## 弱み

- **まだ初期段階。** 0.1.0 は最初のリリースであり、API はまだ安定していません。実行時に配信される TSX のヒープ上限など、不足している機能は[ロードマップ](https://github.com/nsgo-dev/nsgo/blob/main/docs/roadmap.md)に記載されています。
- **小さなエコシステム。** Flutter、React Native、Qt と比べると、サードパーティのコンポーネントやサンプル、オンライン上の回答はまだ少数です。
- **プラットフォームごとの差異。** ネイティブビューを使うためプラットフォーム間で小さな違いが出ることがあり、各環境での確認が必要です。自前で描画するフレームワークはどこでも同じ見た目になります。
- **独自のブリッジ。** Android では Go プログラムが Java ランタイムと並んで動作しパイプ経由で通信します。Linux ではユーザー環境に GTK 4.14 以降が必要です。
- **TSX はインタプリタ実行。** TSX は Go で書かれた JavaScript インタプリタである goja 上で動作するため、React Native や Electron が使うエンジンより低速です。

## NSH

NSGo は NSH の設計を移植したものです。アーキテクチャ、バックエンド、API の名前、そして `base` のスタイルなしコンポーネントは NSH 由来のものです（[ステータス](index.md#ステータス)）。

- **NSGo を選ぶ場合：** Rust や TSX ではなく Go でアプリを書きたい場合、Go と Xcode を入れた Mac から全ターゲットをビルドしたい場合、あるいは NSGo が追加した機能（Go で書く GPU シェーダー、ベクターアイコン、ターミナル、アプリ自身がウィンドウ・パネル・トレイアイコンを開く機能、`ui` のスタイル付きコンポーネント）を使いたい場合。
- **NSH を選ぶ場合：** より成熟したプロジェクト、バイトコードとヒープ上限を備えた QuickJS による TSX 実行、GPUI バックエンド、または 32 ビット Android 対応が必要な場合。

## MyGo

どちらも cgo を使わずに Go で UI を書けますが、MyGo はネイティブ UI 自体を GPU 上に自前描画し、フレームごとにビュー関数から再構築するのに対し、NSGo は変更された部分だけをネイティブビューに渡します。

- **MyGo を選ぶ場合：** すべてのデスクトップで同じ見た目のデスクトップアプリ、Go への型付き呼び出しを備えた Web ページウィンドウ、そしてトレイアイコン、ファイル関連付け、インストーラ、公証、署名付き差分アップデートなどのデスクトップ API と配布機能が必要な場合。
- **NSGo を選ぶ場合：** スマートフォンにも対応したい場合、各プラットフォーム固有のテキスト・入力・アクセシビリティを使いたい場合、またはアプリデータからの再描画ではなくシグナルで状態を保持したい場合。

## その他の Go ツールキット

- **Fyne と Gio** は MyGo と同様にすべてを自前描画し、どちらもスマートフォンと Web に対応しています。Fyne は独自のルックを持つ充実したウィジェット群を提供し、Gio はイミディエイトモードで低レベルかつ柔軟です。どちらもリリース済みバージョンとユーザーがいますが、ネイティブの見た目や操作感ではありません。
- **Wails** はシステム WebView 内に Web フロントエンドを置き、背後に Go を配置します。任意の Web ライブラリが使えますが、インターフェースは Web ページであり、デスクトップ専用です。

## 他言語のフレームワーク

- **Flutter と Compose Multiplatform** はすべてのピクセルを自前で描画します。どのプラットフォームでも見た目が完全に一致し、成熟しており大きなエコシステムを持ちますが、テキスト、スクロール、入力はネイティブではなく再実装されており、Dart や Kotlin を学ぶ必要があります。
- **React Native** はリアクティブなコアがネイティブビューを駆動するという点で NSGo と同じモデルを共有しており、この種のフレームワークでは最大のエコシステムを持ちます。iOS と Android を中心としてアプリロジックを JavaScript で実行するのに対し、NSGo はロジックを Go で実行し、デスクトップと Web も第一級として扱います。
- **.NET MAUI** は C# で各プラットフォームのコントロールをラップしますが、Linux と Web には対応していません。**Avalonia** は WPF に近いモデルで自前描画し、すべてのデスクトップ、スマートフォン、Web で動作します。
- **Qt** は成熟して高速であり組み込みデバイスにも対応しますが、ウィジェットを自前描画し、C++ または QML が必要で、ライセンスは LGPL または商用ライセンスです。
- **Electron と Tauri** は Web ページを表示します。Web のツールとライブラリをフルに活用できますが、その代償としてブラウザ分のメモリ（特に Electron）を消費し、インターフェースは Web ページのような操作感になります。

## 選び方

1つの Go コードベースからスマートフォン、デスクトップ、Web でネイティブに感じられるアプリを作りたい場合で、初期段階のプロジェクトを受け入れられるなら NSGo を選んでください。安定した API で今すぐ出荷しなければならないアプリには、上の表から成熟したフレームワークを選んでください。スマートフォン向けなら Flutter や React Native、デスクトップ専用なら MyGo、Wails、Tauri が適しています。
