以下のページは、コントロールライブラリ、デザインシステム、あるいはアプリが Go パッケージとしてインポートする複雑な単一ビューなどを作成するコンポーネント作者向けです。[コンポーネントと状態](../components.md)および[スタイルとテーマ](../styles.md)を前提としています。

## コンポーネントとは

コンポーネントは、アプリ内と同じく `Render` メソッドを持つ型です。そのフィールドはアプリ側が設定するものであり、アプリが設定しなかった項目はゼロ値になるため、各フィールドのゼロ値が一般的なデフォルトの振る舞いになるように設計すべきです。

```go
package chips

import "github.com/nsgo-dev/nsgo/core"

// Chip is a short label in a pill.
type Chip struct {
	Text string
}

// Render implements core.Node.
func (c Chip) Render(*core.Scope) core.Node {
	return core.View{Class: "self-start rounded-full px-3 py-1", Children: []core.Node{
		core.Text{Content: c.Text, Class: "text-sm"},
	}}
}
```

アプリからは任意の要素と同様に `chips.Chip{Text: "New"}` として使用できます。

## 振る舞いと見た目

NSGo では各コントロールを 2 つの形で用意しています。`base` は見た目を持たずに振る舞い・状態・アクセシビリティを保持し、すべてのスタイルをアプリからパーツごとに受け取ります。`ui` は `base` のコントロールに見た目を適用するため、振る舞いの実装は 1 か所に集約されます。ライブラリでも同じ分割を採用できます。

- **スタイルなし（unstyled）** コンポーネントは、押下、キーボード操作、フォーカス、スクリーンリーダーへの通知を担い、`base.Switch` のように各パーツのスタイルを公開します。アプリや他のライブラリが独自の見た目を与えます（[パーツと状態](parts.md)）。
- **スタイル付き（styled）** コンポーネントはスタイルなしコンポーネントをラップし、`ui.Switch` のように有効なテーマに基づいてスタイルを選択することだけを行います（[見た目とテーマ](looks.md)）。

バッジのように共有するほどの振る舞いを持たないコンポーネントは、スタイル付きコンポーネントのみで作ることもできます。

## パッケージ構成

- 1 つのコンポーネントにつき 1 ファイルとし、そのコンポーネントにちなんだ名前（`chip.go`）を付け、それだけが使う型を同じファイルに置きます。複数のコンポーネントで共有するものは専用ファイルに分けます。
- 複雑なコンポーネントには専用のパッケージを用意し、`base/dock` の `dock.Area` のように API 名からコンポーネント名の重複を省きます。
- コンポーネントが発する文言はパッケージの `locales/` に配置します（[文言・テスト・公開](shipping.md)）。
- デバイスに応じて暗黙的に何かを変えないようにします。スマートフォンとデスクトップで変わるサイズや形式は、アプリが設定するフィールドとして公開します。
