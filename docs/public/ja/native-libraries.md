Go パッケージは、パッケージディレクトリに `nsgo-natives.yaml` を配置することで、purego 経由で読み込む共有ライブラリを同梱して配布できます。アプリがそのパッケージをインポートすると、NSGo はターゲットに応じた宣言を選択し、ファイルを検証して、署名やインストーラー作成の前にそれらを組み込みます。アプリ側に追加の設定やパッケージ化コマンドは不要です。

## ライブラリの宣言

```yaml
version: 1
libraries:
  macos_arm64:
    - name: libexample.dylib
      path: lib/macos-arm64/libexample.dylib
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  macos_x64:
    - name: libexample.dylib
      url: https://downloads.example.org/v1.0/macos-x64/libexample.dylib
      sha256: "<64 hexadecimal digits for this file>"
      licenses: [licenses/LICENSE, licenses/NOTICE]
  windows_arm64: []
  windows_x64: []
  linux_arm64: []
  linux_x64: []
```

サポートされているキーは `macos_arm64`、`macos_x64`、`windows_arm64`、`windows_x64`、`linux_arm64`、`linux_x64` です。Go パッケージが選択されるすべてのターゲットを宣言してください。`[]` はそのターゲットにバンドルされたライブラリが不要であることを明示します。代わりに Go のビルドタグを使って、サポートしていないターゲットからパッケージを除外することもできます。`macos_universal` には 2 つの macOS エントリが使用されます。

各ライブラリには以下の項目があります。

- `name`: インストールされるファイル名。macOS では `.dylib`、Windows では `.dll`、Linux では `.so` またはバージョン付きの `.so.*` で終わる必要があります。
- このパッケージディレクトリからの相対パスである `path`、またはライブラリ自体を指す HTTP(S) URL である `url` のどちらか一方のみを指定します。アーカイブの URL ではなく、展開済みのライブラリを公開してください。URL にはユーザー名やパスワードを埋め込まないでください。
- `sha256`: 元のファイルの SHA-256 ハッシュ値。どちらのソースを指定する場合も必須です。たとえば macOS では `shasum -a 256 lib/macos-arm64/libexample.dylib` で出力できます。
- `licenses`: このパッケージディレクトリからの相対パスで指定する、元のライセンスおよび通知ファイルの空でないパス一覧。これらのテキストは `THIRD_PARTY_NOTICES.txt` に同梱され、リリースビルドの `core.ThirdPartyNotices()` で取得できるようになります。アプリの既存の[ライセンスポリシー](building.md#license-notices)（完全一致によるモジュール例外を含む）は、ネイティブライセンスにも独立して適用されます。

ローカルパスおよびシンボリックリンクは宣言元パッケージの内部に留まる必要があります。NSGo は未知のフィールド、チェックサムの不一致、別の OS やアーキテクチャ向けのファイル、およびインストール名の競合を拒否します。2 つのパッケージが同じチェックサムを持つ同名ファイルを共有することは可能です。1 ファイルあたりのサイズ上限は 1 GiB です。

## パッケージ化と読み込み

| ターゲット | ライブラリディレクトリ |
| --- | --- |
| macOS | `<app>.app/Contents/Frameworks` |
| Windows および Linux | 実行ファイルの隣 |

パッケージはそのディレクトリからライブラリを読み込みます。その際、作業ディレクトリではなく実行ファイルの場所を基準にします。依存関係は、同一ディレクトリ内の関連ライブラリが配布先のディレクトリから読み込まれるようにあらかじめビルドしておいてください。必要な関連ファイルと、ローダーが必要とする各ファイル名をすべて宣言してください。

NSGo はキャッシュされたダウンロードを再利用する前に再度チェックし、ファイルロックによって並行ビルドを調整します。コンテンツキャッシュは OS のユーザーキャッシュディレクトリ配下の `nsgo/natives` に保存されます。ローカルファイルはコピー時に検証されます。

ユニバーサル macOS パッケージでは、両アーキテクチャで同じライブラリ名を指定する必要があります。NSGo は `lipo` でスライスを結合します。配布元がすでにユニバーサル化したライブラリをどちらのエントリに指定することもできます。ライブラリはアプリより先に署名され、その後アプリの通常のディスクイメージ作成、署名、公証手順を通過します。Windows の署名では、`build.installers: false` の場合でも宣言された DLL が署名対象に含まれます。Linux インストーラーには、実行ファイルディレクトリと同じファイルおよび通知が含まれます。

開発時およびネイティブデスクトップターゲットのテストでも、同じパッケージ選択およびコピー手順が使用されます。宣言はローカルの replace や vendoring されたパッケージを含め、ビルドのターゲット、タグ、および生成された Go オーバーレイに基づいて選択されます。他のターゲットでは現在、このファイルからライブラリはパッケージ化されません。

## vendoring 時にファイルを保持する

Go の vendor 操作では、パッケージディレクトリ配下のファイルを保持するために埋め込みデータが必要です。パッケージは実行時にそのバイト列を使用することなく、マニフェストとライセンスを同梱対象としてマークできます。

```go
import "embed"

//go:embed nsgo-natives.yaml licenses/*
var _ embed.FS
```

`path` を使用する場合は、その embed ディレクティブにローカルライブラリのパス（たとえば `lib/*`）も含めてください。URL ダウンロードの場合は、Go パッケージ内にマニフェストとライセンスファイルのみがあれば十分です。
