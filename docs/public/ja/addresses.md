`cx.AppURL()` は、アプリケーションのアドレスを追跡可能な値として読み取ります。Web ではルートの初回描画前からページの初期 URL を参照できるため、リロードや共有リンクから同じビューを選択して表示できます。URL をどのビューにマッピングするかはアプリ側で決定します。

```go
func Root(cx *core.Scope) core.Node {
    return core.View{Children: []core.Node{
        core.Text{ContentFunc: cx.AppURL},
        base.Button{Label: "Open film", OnPress: func(core.PressEvent) {
            if err := cx.SetAppURL("/films/42", core.AppURLOptions{
                History: core.HistoryPush,
            }); err != nil {
                // Show the error in the app's usual way.
            }
        }},
    }}
}
```

`SetAppURL` は、ページリクエストやスタック遷移を行わずに追跡中のアドレスを即座に更新します。デフォルトでは現在のブラウザー履歴エントリを置き換え、`HistoryPush` を指定すると新しい履歴エントリを追加します。同じコミット内でナビゲーションやモーダルのプッシュが行われた場合はそちらのエントリが代わりに使用されるため、1 回の操作で 2 つの「戻る」ステップが作られることはありません。1 回のコミット内で複数回書き込んだ場合は最後のアドレスが採用され、プッシュ要求があれば保持されます。

相対アドレスは現在のアドレス、または明示的な HTML の `<base>` を基準に解決されます。ブラウザーアドレスはページのオリジン内に留まる必要があります。無効なアドレス、空白、制御文字、バックスラッシュ、および 16 KiB を超えるアドレスはアドレスを変更せずにエラーを返します。

`cx.OnAppURLChange(func(change core.AppURLChange) { ... })` は、ブラウザーの履歴移動（戻る・進む）やハッシュ編集を監視します。`change.Reason` は `"back"`、`"forward"`、または `"address"` になります。戻り値の関数を呼ぶと購読を解除でき、スコープの破棄時にもリスナーは削除されます。初期アドレスを取得するには `AppURL` を読み取ります。アプリ自身による書き込みはバインディングを更新しますが、変更通知は発火しません。同じアドレスに留まる履歴移動でも変更通知は送信されません。

ブラウザーの「戻る」操作は、引き続きモーダルを閉じたりナビゲーション画面をポップしたりします。アプリが戻る操作を拒否した場合、既存のエントリとそのアドレスが復元されます。閉じるときのハンドラーで独自の置換アドレスを設定することもできます。プログラムによるポップでは、非同期の履歴移動が完了した後にアドレスが更新され、その移動中に到着した書き込みは完了を待ちます。このプレイヤー自身のエントリを超えてさらに戻ると、前回の読み込みから保持されていたエントリも含め、アプリから離脱します。

`/films/42` のようなパスを使用する場合は、デプロイ先のアプリディレクトリを設定し、アプリケーションルートに対してサーバーが `index.html` を返すように構成してください。

```yaml
web:
  base: /        # /my-app/ when deployed below that directory
```

`web.base` を設定すると HTML の `<base>` が出力され、深いアドレスを直接開いた場合でもスクリプト、スタイル、Wasm、リソースを引き続き読み込めます。設定しない場合は従来の相対アセットパスが維持されるため、クエリやハッシュベースのアドレスではそのまま利用できます。サーバーのフォールバックルールでは、実在するアセットへのリクエストはそのまま配信するようにしてください。厳格な Content Security Policy を設定する場合は、この同一オリジンの base を許可する必要があります（`base-uri 'self'`）。

別ページに埋め込まれたアプリはアドレスを内部で保持し、親ページの履歴には触れません。同一オリジンの iframe は `data-nsgo-history` を指定することで明示的に履歴連携を有効にできます。閉じ込められたサブツリーはアプリケーションアドレスの読み取りや変更を行えません。

他のターゲットでは、`AppURL` はアプリで開かれた最後のリンクまたは `SetAppURL` で保存された値を保持します。設定してもネイティブウィンドウやシステムブラウザーは変更されません。ミニプログラムでもホストのルートを変更せずにこの値を保持します。

TSX でも同じ状態管理を使用できます。

```tsx
import { UrlScheme } from "nsgo";

UrlScheme.url();
UrlScheme.setUrl("/films/42", { history: "push" });
const stop = UrlScheme.on("change", ({ url, reason }) => {
  // Update the app's route from the browser's choice.
});
```
