# Canvas

`core.Canvas` records 2D drawing on the engine and has the platform play it, as NSH's `Canvas` does (`nsh/docs/dev/canvas.md`). Read this before changing `core/canvas.go`, `internal/driver/canvas*.go`, a backend's canvas player or `internal/platform/canvastest`.

## Recording

`Canvas.Draw` runs on the engine when a signal it read, the canvas's size or the available fonts change and records `DrawOp`s into a `Drawing`, which travels in `ItemCanvas` and never changes after. `FontsChanged` schedules every live canvas's recording effect: a drawing can use `TextMetrics` to place shapes without recording text, so replaying its old operations would leave stale geometry. `Icon` and `SVG` record the same way ([icons](icons.md)). The methods follow the web's `CanvasRenderingContext2D`:

- State: `Save` and `Restore`, `Translate`, `Scale`, `Rotate`, `Transform`, `SetTransform` and `ResetTransform`, alpha, and `SetComposite`, Porter-Duff operators and blend modes named as `globalCompositeOperation`.
- Lines and text: widths, caps, joins, `SetMiterLimit`, `SetLineDash` (an odd list repeats, as the web's) and its offset, `SetShadow`, `SetTextAlign` and `SetTextBaseline`.
- Paths: lines, curves, `Arc`, `ArcTo`, `EllipseArc` for rotated ellipses, `RoundRectCorners` for per-corner radii, and `Path` values, which `ParsePath` makes from SVG path data.
- `FillPath`, `StrokePath` and `ClipPath` use a `Path` without touching the current path; `FillEvenOdd` and `ClipEvenOdd` take the even-odd rule.
- Paints: colors, and `CanvasLinear`, `CanvasRadial` and `CanvasConic` gradients.
- Text: `FillText` and `StrokeText` in a `Font`.
- Images and SVGs: `DrawImage` at the natural size, `DrawImageIn` into a rectangle, `DrawImageFrom` from a part of the image, `DrawVertices` through a triangle list and `DrawAtlas` for ordered tiles of one image; `DrawSVG` at the document's intrinsic size and `DrawSVGIn` fitted into a rectangle by its `preserveAspectRatio` (clipping for `slice`), leaving the drawing's state and current path intact, resolving `currentColor` from the drawing's fill color (or black when unset), and laying out `<text>`/`<tspan>` elements with the drawing's `TextEngine` into native `DrawFillText`/`DrawStrokeText` ops so every platform renders SVG text with its own text engine. The corresponding `DrawTintedImage`, `DrawTintedImageIn` and `DrawTintedImageFrom` multiply the source's sRGB and alpha channels by a color before applying the canvas's composition state. The tint can bind to `ArgColor`. The HarmonyOS host draws the PixelMap into an offscreen context, multiplies each byte by the tint over 255 and draws the result. It keeps a copy per image and tint while paints draw it and releases one that two paints in a row did not draw, so a tint that changes, as one bound to `ArgColor` does, costs a pass over the image's pixels on each change. It tints images from bytes or the app's resources; pixel buffers and offscreen images are not drawn there yet.

A canvas has no size of its own unless `Em` gives it one in ems of the font size it inherits, scaled by the user's text size as text is, as `base/formula`'s formulas size themselves: in a text's attachment its baseline, `Em.Descent` ems above its bottom, sits on the line's ([text](text.md)). `EmFunc` and `LabelFunc` follow what they read, laying it out again and naming it anew. `Scope.MeasureText` tracks available-font changes, so a memo or `EmFunc` that uses its measurements updates after a font registration or system font change.

`MeasureEm(width, fontSize)` supplies an em box for a width in points (`Auto` when unbounded) and the resolved, scaled font size. Layout uses its measured height without proportional fitting; baseline placement measures the same box. The recording effect tracks its reads and measures at the final width before `Draw`, with a font signal to invalidate a fixed frame too. It also runs during layout and must not write signals. `base/formula` uses this shared hook for display wrapping; backends receive the ordinary canvas recording.

The recorder resolves what needs the engine, so players stay plain: text alignment and baselines become an offset from the text's metrics, and an `ArcTo` becomes an arc from the current point. A `FillPath`, `StrokePath` or `ClipPath` (`FillRect` and `StrokeRect` among them) begins a path for its `Path` and another after it; the current path it leaves is recorded again, under the transforms it was built in and inside a `Save` and `Restore`, before the next op that builds on it or uses it (`DrawKind.UsesPath`). A run of `FillRect`s after a long line, as a chart's bars after its line, records each rectangle alone. Players keep only a transform, a clip and the paint state.

`Drawing.SetImageSmoothing` records a sampler on each image operation, `DrawAtlas` included, with smooth sampling as the zero value. The recorder saves and restores the sampler alongside drawing state, so a player replaying part of a recording can use the sampler on each operation directly. Core Graphics sets interpolation in the image draw's saved graphics state, Direct2D selects a bitmap interpolation mode, Cairo sets the source pattern's filter, Android passes it through the canvas wire format to `Paint`, HarmonyOS carries it in each image op's JSON and the host, like the web and mini programs, sets the canvas context's `imageSmoothingEnabled`.

`DrawAtlas` records source bounds in image points, one scaled rotation and translation per tile, and optional opacity factors on one operation. It copies its inputs and retains one image source for access checks, density selection and loading. The tile's local origin is its top-left corner. A sprite with transform `t` maps local `(x, y)` to `(t.SCos*x - t.SSin*y + t.TX, t.SSin*x + t.SCos*y + t.TY)`. Each draw retains the clip, composite and shadow, multiplies the saved alpha by its opacity, and leaves the current path intact.

`DrawShader` and `SetShader` record a `ShaderPaint` (`ShaderProgram.Paint`: the program, its lanes, the lanes animated nodes drive, and its images) on the op: `DrawShader` with its rectangle, and every image op under `SetShader`, which `Save` and `Restore` keep as they keep the sampler. The lanes nodes drive become `ArgLane` slots, so a bound uniform redraws through `Animator.CanvasOps` as other bound arguments do, and the core enables a backend's shading only once a drawing shades (`CanvasShaderEnabler`), so apps that never do link none of it. Players draw on the CPU while programs run on the GPU, so `internal/platform/canvasshade` lays out each shaded op as one pass: triangles in the target's pixels under the op's transform, clipped to what the canvas may change, carrying `dst`, `pos` and the color a sprite's alpha, a vertex's color or a tint multiplies the program's by. Metal, Direct3D 11, OpenGL and WebGL 2 render the pass source over into a texture of its bounds, and the player draws it there in device space under the clip, alpha, operator and shadow; Metal and OpenGL read the texture back, while Direct3D shares Direct2D's device and the web draws the WebGL canvas into the 2D one. A pass composites as one image, as a mesh's does. Android's Java player, HarmonyOS, watchOS and mini programs leave `DrawShader` out and draw shaded images plain ([roadmap](../roadmap.md)).

## Queries

A drawing answers without the platform, during `Draw` and after it, so `OnPress` can test the last drawing's shapes:

- `MeasureText` and `TextMetrics` lay text out with the platform's `TextEngine` and report the first line's width, ascent, descent and line height. Trailing white space counts, as in a browser: engines leave it out of a line, so such a text is measured with a mark after it, less the mark. Without an engine, as in some tests, they approximate: 0.6 em a character, 0.8 em up and 0.2 em down.
- `IsPointInPath` and `IsPointInStroke` replay what was recorded for its transform, current path and line style and test the flattened path; `PathContains` and `StrokeContains` test a `Path`. Strokes take joins as round and dashes as solid.
- Bound arguments count as recorded.

## View paints

`FillFromView`, `StrokeFromView`, `LineWidthFromView` and `LineDashFromView` record an operation whose value is the canvas view's SVG paint style ([styles](styles.md)), noted in `Drawing.ViewPaints` with the initial paint where no view sets one. The core resolves the inherited `Fill`, `Stroke`, `StrokeWidth` and `StrokeDash`, with `PaintCurrentColor` the view's text color, and sends `Drawing.Painted`: a change of them sends the drawing again without drawing it again, and no platform knows of them. A canvas that has drawn nothing sends no empty first drawing.

`FillBackgroundFromView(area)` fills the current path with the view's own `Background` and `Gradients`, placed over `area` as over a box of that size, as CSS's `clip-path` shows a box's background: a chart's wash under its line. The recorder leaves a transparent fill the core expands into a fill per paint, the gradients turned into `CanvasGradient`s, and moves the slots after it along. The view is then sent without its background, so it is drawn once, inside the shape; a drawing with nothing to fill yet records the fill over an empty path so the box never shows.

## Animated arguments

`Drawing.Bind(arg, node)` has the platform read argument `arg` (`ArgX` to `ArgColor`) of the last operation from an animated node. The drawing carries the bindings as `DrawSlot`s; the backend registers them with `Animator.BindCanvas` and, when `ChangedCanvases` reports a canvas, plays a copy from `CanvasOps` with the values patched in. The canvas redraws on the frame clock without a commit. Android's Java animator patches the encoded operations in place by their byte offsets.

macOS, iOS, Linux, Windows and the web redraw only what the change covers, as NSH's partial redraws; Android redraws the whole canvas.

- `driver.CanvasDamage` replays the operations last drawn and those drawn now for their geometry, and adds up the bounds of the painting operations that changed or paint with state that did: transform, path, alpha, paint, line, shadow.
- The area, 2 points wider for anti-aliasing and rounded out, is drawn again: Apple invalidates it in the view's content layer (`apple.Damaged`), Windows adds it, where the last frame placed the view, to the next frame's damage (`window.redrawArea`), and the web clears it in the `<canvas>` and plays there. The replay of the whole drawing is clipped to it, so the pixels are a full redraw's, but that Chrome's software rasterizer anti-aliases a path the clip cuts a few levels apart.
- Windows leaves out a source-over paint that cannot change a pixel before it builds its geometry, lays its text out or looks its bitmap up, as NSH's player: at zero alpha, or in a transparent color or gradient with no shadow to show.
- Bounds are conservative: curves by their control points, arcs by their circle, strokes by their reach at miter joins and square caps, shadows by twice their blur, text by 1.5 em a character.
- A changed clip, changed painting under a composite operation other than source-over, an image at its natural size and bounds that are not finite redraw the whole canvas.

What the ops before the first bound one paint is the same whatever the nodes hold: its static part (`driver.SplitCanvas`, NSH's `first_animated`). A backend keeps its pixels and plays only the painting after it over them; the ops before it still set the state, and `CanvasSplit.Skips` leaves out their painting and the path no later op uses.

| Target | Keeps the static part as | How a canvas draws |
| --- | --- | --- |
| macOS | A `CGLayer`, once a drawing of 128 ops or more before its first bound one was painted unchanged 30 times | At once on the main thread, or on Core Animation's threads (`drawsAsynchronously`) while it paints 10 times a second or more and keeps no layer |
| Linux | The pixels a full play left at the split | Into an image surface at the surface's scale, shown as 256-pixel textures: a change draws its area again over the kept pixels, and only the tiles it touches become new textures. A canvas outside a clipping ancestor or the window waits until a layout shows it |
| Windows | A Direct2D command list, played once | From command lists: the static part's and the rest's, played again when a bound node changes, or the whole drawing's. A rest that composites with what came before or clears plays whole |

`internal/platform/canvastest`'s `Split` drawings check that playing over a kept part draws what a full play does, on each of the three.

## Offscreen images

`cx.NewOffscreenImage(size, scale, draw)` records a 2D `Drawing` into a retained `core.OffscreenImage` at logical `size` and backing `scale` (pixels per point; non-positive values take the display pixel ratio or 1). `Source()` returns an `ImageSource` carrying `driver.OffscreenCanvas` (`ID`, `Version`, `Size`, `Scale`, `Drawing`) usable in `Drawing.DrawImage`, `Drawing.DrawImageIn`, `Drawing.DrawImageFrom`, `Drawing.DrawAtlas` and `core.Image`, without loading or firing load events.

The callback runs lazily on first `Source()` call inside `Untracked`, and runs again only after `Invalidate()`, `Resize(size, scale)` (when size or scale changes) or `FontsChanged()`. While clean, repeated `Source()` calls return the same snapshot pointer and `Version`, so later frames pay one `DrawImage` operation per frame with zero re-rendering. `Release()` (also registered on `cx.Cleanup`) emits `ItemReleaseOffscreen` so platforms drop their cached surface.

| Target | Offscreen cache |
| --- | --- |
| macOS, iOS, watchOS | Process-wide mutex-guarded `CGImage` rendered through `CGBitmapContextCreate` with `Play`, keyed by `(ID, Version)` |
| Windows | Per-window GPU `ID2D1Bitmap1` (`d2dBitmapTarget` at `96 * scale` DPI) rendered through `canvasPlayer`, keyed by `(ID, Version, gfxGeneration)` |
| Linux | Per-window Cairo `CAIRO_FORMAT_ARGB32` image surface rendered through `playCanvasOps`, keyed by `(ID, Version)` |
| Web | Per-surface offscreen `<canvas>` rendered through `canvas2d.Player`, keyed by `(ID, Version)`, drawn directly with `drawImage` |
| Android, mini programs | `ItemReleaseOffscreen` filtered cleanly; offscreen rasterization in the Java/mini-program runtimes is not yet implemented |
| `nsgotest` | `App.Offscreen` tracks `Version`, `RenderCount`, `Size`, `Scale`, `Ops` and `Released` per ID |

## Nodes

`Drawing.Node` names a part of the drawing, a chart's bar or a grid's cell, with bounds in the canvas, a role, a label, a test ID and a selected state. A press on one is a press on the canvas at the node's center.

| Target | Nodes are |
| --- | --- |
| macOS | `NSAccessibilityElement`s, the canvas view's accessibility children |
| iOS | `UIAccessibilityElement`s in place of the canvas |
| Web | ARIA elements inside the `<canvas>`, which browsers expose at their bounds and never draw |
| Android | Virtual views of the canvas's `AccessibilityNodeProvider` |
| Windows | UI Automation providers, the canvas element's children |
| Linux | Empty `GtkLabel`s of the node's role at its bounds, which take no pointer |
| `nsgotest` | Views of the model: selectors find them by label, text and test ID, and a press presses the pressable view under their center |

## Players

Each backend plays the operations in order on the main thread; on macOS into a context Core Animation may draw on its own threads ([animated arguments](#animated-arguments)). Images load as image views' do, cached by `ImageSource.Key`; inline byte sources use a content digest, so a collected buffer's address cannot make a cache return an older image when the address is reused. A canvas draws again when one arrives and draws nothing in its place until then. Apple, Windows, Linux, Android, web, mini-program and HarmonyOS canvas caches — and Windows Direct3D, Linux OpenGL and web WebGL shader texture caches — keep at most 64 unkept encoded sources within the byte budget set by `Scope.SetImageCacheLimit` (default 32 MiB), counting failed loads too, and release an evicted entry's native image, COM texture, GL texture, ArkUI `PixelMap` or blob URL. `Scope.KeepImage` pins a source's resolved key (`ItemKeepImage` / `ItemReleaseImage`) so it stays out of count and byte eviction while kept: pins are reference-counted, idempotent to release, released automatically when the owning scope disposes, and on shared caches (`imageload` and Apple's canvas cache) released per surface when a surface closes; once a source's last pin releases, excess unkept entries trim back within bounds. A load under way is never evicted, so loads under way exceed the bound until they finish: cancelling one would leave what waits for it, a canvas or a shader that draws only when its images arrive, without the image, and canvases drawn in passes of their own would cancel each other's loads forever. A pass of drawing (a paint, frame or Core Animation transaction: everything drawn before the main thread next runs posted work) never evicts a source it drew, so one drawing more than 64 keeps them all, rather than loading some again at every pass forever, until later passes draw others. Windows, Linux and Android keep the cache per window or surface and release it on close; Apple's is shared. Android requests bytes from Go on a cache miss, including after eviction; Go keeps sources while their mounted canvases or shaders use them, and a load until Java's cache cancels it or its result is sent. A request's generation rejects a late result. Java recycles evicted bitmaps after any shader frame using them finishes its upload, and cancels its loads and queued decodes when its surface closes.

Pixels draw at once on Apple, Windows and Linux, with a separate cache of up to eight frames. Android keeps the bitmaps of the drawing's current pixel frames and reads them on the first draw ([pixel buffers](images.md#pixel-buffers)).

`DrawVertices` snapshots the vertices in one op and uses the same image source, access check, scale variant and reload path as other image draws. Three `CanvasVertex` values make each triangle. Position is in canvas points, texture coordinates in image points, and the premultiplied vertex colors multiply the texture as they interpolate. The zero color leaves the texture unchanged. Zero-area and nonfinite triangles are ignored. A pair of untinted triangles covering a rectangular crop draws through the ordinary image op. A mesh's bounds participate in damage tracking, and its vertex coordinates change when the app records it again.

Android uses `Canvas.drawVertices` with a bitmap shader. Apple, Linux, Windows, the web and mini programs sample the texture in a shared rasterizer (`canvasmesh`) and hand a single bitmap to the native canvas compositor. The rasterizer sets up each triangle once and splits the rows into 32-row bands that every processor takes in turn, keeping triangle order within each band. Where the context has no rotation or skew, Apple and the `canvas2d` player of the web and mini programs raster on the device's pixel grid and composite without resampling, and Apple writes BGRA as Core Animation's backing stores hold it; Linux and Windows still composite the bitmap over the mesh's bounds. Shared edges belong to one triangle so the join has no seam. `SetImageSmoothing(false)` samples the nearest texel, in the rasterizer and in Android's bitmap shader. Pixel buffers are sampled in place. Offscreen images are sampled from the surface each backend retains, read once per version where the backend keeps it outside Go's memory; Android's canvases and mini programs draw no offscreen images yet, for meshes as for `DrawImage`. The web reads encoded and offscreen texture pixels through the browser's canvas, which requires a same-origin or inline image, and mini programs read encoded ones through theirs. The HarmonyOS host clips each triangle and draws the image through the affine transform that maps its texture coordinates onto it. It plays each triangle's average vertex alpha and no color tint, as ArkUI's 2D context has no per-vertex color, and like its `DrawImage` it draws encoded images only, not pixel buffers or offscreen images. Each image and mesh op carries its sampling, which the host sets as `imageSmoothingEnabled`. To hide seams, the encoder marks the edges two triangles with opaque vertices share, and the host moves only those edges out by half a device pixel, measured through the context's current transform, when the drawing's alpha is also 1; the mesh's outline keeps to its texture coordinates, and translucent triangles are not drawn twice over a strip, though texture alpha along a grown edge still is. A triangle whose texture coordinates meet at one point fills with that texel; one whose coordinates lie on a line has its middle corner moved a quarter of an image pixel off the line, so the transform inverts.

| Target | Plays into | Composites | Shadows | Conic gradients | Stroked text |
| --- | --- | --- | --- | --- | --- |
| macOS, iOS | Core Graphics | Blend modes; operators that clear outside the shape draw in a transparency layer | Core Graphics's | `CGContextDrawConicGradient` from macOS 14 and iOS 17, wedges before | CoreText in the stroke drawing mode |
| Web | A 2D `<canvas>` | `globalCompositeOperation` | The canvas's, scaled to its pixels | `createConicGradient` | `strokeText` |
| Windows | Direct2D, through an offscreen bitmap when the drawing composites or clears | Direct2D's composite and blend effects | A command list through the shadow effect | A bitmap brush of the sweep | DirectWrite outlines, through a text renderer written in Go |
| Linux | Cairo | Cairo's operators | An alpha mask blurred with a box blur | A mesh pattern | Pango's layout path |
| Android | `android.graphics.Canvas` | `BlendMode`, or Porter-Duff modes before Android 10, in a layer for operators that clear outside the shape | The paint's shadow layer | `SweepGradient` | The paint's stroke style |

A call into the platform can cost more than the op it plays draws ([performance](performance.md#keeping-frames-cheap)). Apple's player calls the Core Graphics functions of pointers and integers through `purego.SyscallN` (`registerSyscall`), adds a `MoveTo` and the `LineTo`s after it in one `CGContextAddLines`, makes each color once a drawing, tracks whether the path is empty and asks Core Graphics only after shapes that may add nothing, and copies the path that a fill, stroke or clip keeps only when a later op uses it.

An atlas resolves its image once. Apple caches cropped tiles within the source's lifetime and shares one Core Graphics coordinate flip across axis-aligned sprites. Windows uses a Direct2D sprite batch for axis-aligned, pixel-aligned placements that fit its sampling rules. Linux changes the source matrix of a shared Cairo pattern. Android can draw compatible placements as a textured mesh, with bitmap draws for placements that need the ordinary player's edge and compositing rules. The web and mini-program player passes a packed sprite list to JavaScript where the host allows generated functions. Its fallback calls the same 2D drawing methods through `syscall/js`. HarmonyOS sends the image once with the sprites packed nine numbers each in one JSON op to a host whose `deviceJSON` reports `CanvasAtlas`, and the host's player, the committed prebuilt host included, draws them as the web's player does, on ArkUI's 2D context. A host built before the packed op, such as an app's previously generated host, does not report it and gets each sprite expanded into a save, its transform, its alpha, the image and a restore.

`internal/platform/canvastest` holds sample drawings, one for each group of features, and the pixels they must produce; the Apple, Windows and Linux players check them in their tests. Cache tests on Apple, Windows, Linux and Android exercise 1,000 distinct sources, eviction, reloading and loads under way; on Apple and Linux, canvases drawn in passes of their own load 88 slow images together; Android also runs its real pipe, decoder and player on the emulator. The web is checked by screenshots of the gallery's Canvas page.

The web replays canvases at the screen's pixel ratio multiplied by the enclosing scroll zooms and style transforms, with raster zoom clamped to 1–4 as on Apple (`driver.RasterStep`). Scroll zooms and animated or transitioned style transforms keep CSS scaling cheap while moving and replay 120 ms after the last step (or after a CSS transition completes); static style transforms replay immediately. A canvas whose full zoomed bitmap would pass 4096 × 4096 pixels or a side of 16384 draws only its visible sub-rectangle (plus overscan) positioned inside the view and re-slices as scrolling or panning moves outside the painted tile, keeping large canvases sharp within the budget; a rotated or unclipped canvas past the budget stays bounded. New drawings and moved content take their current ancestry's scale, read from `data-nsgo-zoom`; a zoom replays the recording without rerunning `Draw`. Once the replay's bitmap matches the screen size under axis-aligned transforms, a zoomed canvas uses `image-rendering: pixelated` so Chrome's nested scale compositing does not grey sharp edges; moving zooms, rotations/skews and capped or fractional sizes keep smooth sampling. Android redraws texts and canvases in 0.5× steps up to 4× (`RasterScale.step`) within the same bitmap budget, Linux rasterizes Cairo canvas surfaces at the stepped cumulative scale (`canvasRasterScale`), and Windows scales offscreen mixing bitmaps (`offscreenScale`) while vector command lists draw directly at the world transform.

A canvas's `ResolutionScale` reaches the platform on its drawing (`driver.Drawing.Resolution` and `Upscale`, read through `ResolutionScale` and `Smooth`), so a new factor or sampling resends the same ops without running `Draw`. Each backend multiplies the raster scale it already computes by the factor and stretches the smaller raster to the canvas's box: Apple lowers the content layer's `contentsScale` and sets its magnification filter, the web the `<canvas>`'s backing size under its `image-rendering`, Android its backing bitmap's scale and the paint's filtering, Windows plays into a bitmap of the canvas's own drawn with linear or nearest interpolation, Linux rasterizes the Cairo surface lower and appends it as one texture scaled with GSK's filter, watchOS draws into a `CGLayer` stretched with the context's interpolation, and mini programs size their offscreen canvas lower, copying it up without smoothing for nearest. Hit tests stay in points. HarmonyOS's ArkTS host plays at the screen's density ([roadmap](../roadmap.md)). `canvastest.Resolution` is the shared sample, a checkerboard whose squares each take one backing pixel at 0.5.

## Where NSGo departs from NSH

| NSH | NSGo | Why |
| --- | --- | --- |
| Any number or color may be an animated value, bound where it is passed | `Bind` binds the last operation's argument | Go has no union of a number and a node; one method keeps every drawing call plain |
| Nodes reach only GPUI's accessibility and the headless driver | Nodes reach each backend's accessibility, except Windows' and Linux's | NSGo has no GPUI backend; native accessibility is where screen readers look |
| `font` is a CSS shorthand string | A `Font` value | Styles are Go values |
