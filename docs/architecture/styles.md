# Styles

How a `Style` becomes what each backend draws: the corners, borders, outlines, shadows, gradients, filters, masks, blend modes, 3D transforms and keyframes past React Native's view styles, and the positions, sizes and directions layout takes from it. Read this before changing `core/style.go`, `internal/driver`'s `ViewStyle` or a backend's drawing of a view.

## Resolving

Styles follow NSH's `styles.md` with Go values in place of CSS strings: constructors (`LinearGradient`, `Blur`, `Ring`, `DropShadow`) build what apps write, and every zero value is unset. `Zero`, the smallest float32 above 0, is a length that is set, as `Transparent` is a color: it merges as any length, and `restyle` turns it to 0 in a view's committed style, so layout and backends never see it.

- `Merge` replaces a field the later style sets, `Transform` by CSS's properties: translate, rotate, scale and perspective each replace their own, and the transform property's functions, `Transform`'s or the list `Transforms`, replace each other; a slice replaces only when it is not nil, so an empty one clears. State styles merge in NSH's order, after the `GroupStyle` of the nearest ancestor whose `Group` matches its `Name` (the nearest group when empty). A group reports hovers, and presses only when it has a press handler; its state changes restyle the views that follow it. `Active`, groups and peers never add press events to a plain view, since NSGo's event mask also decides press targets and keyboard stops; use a press handler for an active style, or `Focusable` to opt into keyboard focus.
- A state's `Background` without `Gradients` drops the gradients, as an animated background does, so press feedback shows over a gradient fill.
- `CurrentColor` in a color other than `Color` is the text color the view has, its own or inherited, else its subtree's `Palette.Text`; a `-current` class with an alpha (`bg-current/50`) keeps it until the view knows the color it inherits. `ParseColor` reads `currentColor`, and a `color-mix()` of it as a mark for `driver.ResolveCurrent`: a color of no alpha holding an index into a table of mixes, so every color field carries one as it is. A shadow or a drop shadow without a color is `CurrentColor`, as in CSS, and a gradient's stops resolve before it is painted. An outline or a border without a color takes it too, as CSS's do; `Transparent` is a color that draws nothing but is set, which a border needs to draw none.
- The states are NSH's, in its order: checked, indeterminate, selected, focus-within, hover, focus, focus visible (`FocusVisible`, `focus-visible:`), active, the `aria-*` states of the accessibility state (busy, checked, expanded, pressed, selected, so an open popup's trigger keeps its look while hovered), `Data` by name (the `data-*` attributes `PartStates.Data` shows), and disabled, which NSH orders before `aria-*` for classes and over all for style props: NSGo's state styles hold both, so disabled is last. `View.ShowsExpanded` shows a trigger's expanded state to the view the app gave it, as `Popover` and `Menu` do, where NSH sets the state on the app's view itself.
- `NumberOfLines`, `TextOverflow`, `PointerEvents` and `ObjectFit` are style keys over the element's `MaxLines`, `EllipsizeMode`, `PointerEvents` and `ResizeMode`, which Go keeps; TSX has the keys alone, as NSH 0.4.0 does. `PointerEventsNone` inherits as CSS's `none`: once a style names `PointerEvents`, a commit after a change walks the tree (`updatePointerEvents`) and mounts `box-none` where a view inside takes the pointer again, `none` at the top of what it blocks and nothing below. `PointerEventsOn` is `auto` written out, where 0 is unset.
- While a view is disabled, its own state styles but `Disabled` wait, as NSH's do; its classes' variants (`checked:`, `hover:`) still apply, and the platform keeps reporting the states the styles wait for.
- `Fill`, `Stroke`, `StrokeWidth` and `StrokeDash` are SVG's paint properties, inherited as CSS inherits them: views draw nothing with them, and canvases paint with them where a drawing takes its view's paint ([canvas](canvas.md#view-paints)). A `Paint` is unset (zero), `PaintNone`, `PaintCurrentColor` or `PaintColor(c)`; dashes that are empty but not nil, or add up to 0, are solid.
- Text fields inherit as CSS does, now with `WhiteSpace`, `UserSelect`, `WritingDirection` and `LayoutDirection`. `LineHeight`, `LineHeightMultiple` and `LineHeightEm` are one group: the nearest node that sets any wins, a multiple follows each text's font, and em becomes a length where it is set; `LetterSpacing` and `LetterSpacingEm` are another.
- `viewStyle` resolves what depends on the frame, so a resize sends it again: percentages of `Transform`, `Transforms` and `TransformOrigin`, and each `Gradient` as a `GradientPaint`. A paint's geometry is in fractions of the box, its stops placed as CSS places them, repeats laid out, and pairs sampled in their `ColorSpace` (Oklab unless set) until blending in sRGB stays within an 8-bit step. Platforms draw paints without knowing CSS.
- `frameTransform` lowers `Transforms`, CSS's list in the app's order: a list in the order of `Transform`'s fields, alone, goes in them, which transitions move one by one and Android has; any other goes in `Transform.Then`, a matrix after the fields, which a transition mixes entry by entry, so large turns are not arcs. `ParseTransform` reads CSS's `transform` for it, and `translate`, `rotate` and `scale` are `Transform`'s fields.
- `Effects` travel behind a pointer the core keeps while they compare equal, so `ViewStyle` stays comparable and unchanged effects send nothing.

## Classes

`Class` on `View`, `Text`, `Span`, `Scroll`, `Input`, `Image`, `Overlay` and `Canvas`, and on every part of `base`'s components ([components](components.md)), takes Tailwind CSS classes, a port of NSH's `tailwind` module and `core/classes.rs` (`core/tailwind*.go`, `core/classes.go`). Utilities and variants mean what they mean in Tailwind CSS 4, on its default theme and palette, which a theme's `Tailwind` extends ([themes](themes.md#tailwind)); one with no native meaning, or a value Tailwind's grammar or CSS refuses (`p-.5`, `w-[100]` without a unit, `p-[-4px]`), is unknown and logged once. NSH's class tests run ported (`tailwind_nsh_test.go`).

- Parsed classes and grid track lists are cached per engine in two generations of at most 1024 entries each, as text measurements are; tools that parse without an engine retain no entries. Rules are ordered as Tailwind orders them: plain utilities first in the string's order, then variants by Tailwind's variant order, then important ones (`!p-4`, `p-4!`). NSH bounds its engine's cache too; NSGo uses its text cache's two-generation eviction instead of an LRU.
- A node resolves its rules for its environment: `dark:` follows `Scope.Dark`, breakpoints and `portrait:` the window, `rtl:`, `motion-reduce:`, `contrast-more:`, `pointer-fine:`, `pointer-coarse:` and `ios:`, `android:` and `web:` theirs. `pointer-fine:` and `pointer-coarse:` follow `Env.Pointer` (the browser's CSS `pointer` media query on the web, else derived from `Idiom`: fine on desktops and Macs, coarse on phones, tablets and watches, and neither on TVs), chosen by the app's classes rather than implicitly by `core`. A node whose rules read any of them follows them in a render effect, so only those nodes resolve again.
- State variants become the style's state styles (`hover:` its `Hover`, `group-hover/item:` a `GroupStyle` named `item`); `group` and `group/item` name the view's `Group`. `first:`, `last:`, `odd:`, `even:` and `only:` follow the node's place among its parent's native children. Child-order and spacing changes queue a refresh per changed parent before resolve, through transparent regions. A positional child takes its place from that walk; a child a relational selector also matches reads its place when matched, as the selectors do. NSH tracks parents with positional children; NSGo batches the changes instead, so no child, plain or positional, searches its siblings on each insertion, and moving the last positional child away leaves no dependency to maintain.
- `peer` and `peer/name` mark sibling state sources; `peer-checked:`, `peer-disabled:`, `peer-enabled:`, the other state variants and boolean `peer-data-<name>:` match any preceding sibling with the exact marker name, through transparent regions but never into descendants. Multiple peer variants each require a matching sibling. State, marker and child-order changes queue one refresh per parent before resolve, including conditional child spacing. This extends NSH, which has no peers, so sibling labels and field parts can follow controls without duplicated state bindings. A marker requests hover and focus events, and press events only when it already takes presses, so marking a plain view never makes it a Tab stop or, on the web, a press target that takes text selection from its contents; `peer-active:` therefore follows only pressable markers. Arbitrary peer selectors remain unknown.
- Relational variants (`has-[>svg]:px-3`, `has-checked:opacity-50`, `[&_svg]:size-4`) match the engine's native element tree, with regions transparent; `svg` means `Icon`/`SVGView`, not every canvas. Unlike NSH, NSGo implements these in shared core (`classselector.go`, `classrelations.go`), so backend implementation views never affect matching. Variant stages keep their own conditions: `hover:[&_svg]` reads the ancestor's hover, `[&_svg]:hover` the icon's. Conditions, class/attribute/pseudo-class specificity and type specificity precede variant rank; inline styles still win, important rules last, and state backgrounds keep hiding gradients. State event masks retain selector dependencies after matching: the view with the classes and the views a selector may reach report the hover and focus states the selectors read, and presses only when they already take them, as `Active`, groups and peer markers do, so a selector never makes a plain view a Tab stop or a web press target. Peer variants still apply on selector targets. A refresh finds a node's sources through an index of their scopes, walking its ancestors rather than every source in the app.
- Selectors support lists, descendant/child/adjacent/general sibling combinators, classes, `data-*` presence/equality from `PartStates.Data` (`part=icon`), roles and the supported boolean accessibility states (`aria-checked=mixed` included). Types are `view`/`div`, `text`/`span` (text nodes, not inline spans), `scroll`, `input`, `textarea`, `image`/`img`, `canvas`, `svg`, `video`, `webview` and `native`. Pseudo-classes are the existing state variants, `enabled`, first/last/only-child, nth-child (positive integer, odd or even), `:is`, `:where`, `:not` and `:has`. An arbitrary selector has one top-level `&` per alternative; omitted `&` means the element itself. Unsupported syntax, nested explicit anchors, escapes, pseudo-elements and at-rules are unknown. Parsing is bounded to 2048 characters and eight nested functions.
- Relation sources queue only intersecting matching scopes after structure, props, state, class or environment changes; a commit coalesces them before layout, removing stale styles and spacing as nodes move or sources disappear. Descendant rules stay within their source, sibling rules include its parent and ancestor rules include its root. Related targets follow the environment even without classes of their own.
- `View.ClassFunc`'s and `Text.ClassFunc`'s classes follow `Class`'s, again when what it reads changes, so a part's state classes come and go without a new node.
- A span's classes go under its `Style` and what its `StyleFunc` returns, and `Text.SpansFunc`'s spans take them too. Spans and `Screen.HeaderClass` have no sibling context: `peer-*` variants there are ignored and logged once per class and context while the graph caches the diagnostic; the same cached classes still apply normally on a view.
- Classes merge under `Style`, their state styles merging with the style's rather than replaced by them, and important ones over it. `space-x-*` and `space-y-*` give a view's children but the last the margin on that side, under their own.
- Shadows and rings, filters, gradients (`bg-linear-to-*` with `from-*`, `via-*`, `to-*`), outlines and `tracking-*` are composed once a style's rules are applied, as Tailwind composes its CSS variables, so their order in the string does not matter: inset shadows, inset rings, the ring offset's band, the ring, then the shadow's layers; a color (`shadow-red-500/50`, `drop-shadow-*`, `inset-shadow-*`, `text-shadow-*`) replaces each layer's, alpha too, and a size's modifier (`shadow-xl/20`) is the layers' alpha. An outline style alone is CSS's medium width, 3 points; `outline-none` removes the outline. `leading-*` wins over a text size's own line height. Arbitrary shadows, drop shadows and gradients (`bg-[linear-gradient(...)]`) read as CSS does, their rems the theme's. A state's background hides the view's gradient, unless the state has a gradient of its own.
- `-current` colors (`border-current`, `bg-current/50`) are the view's text color once its classes apply, wherever they are; borders, outlines, rings and decorations without a color are the text's as well.
- Layout swaps left and right right to left, so physical classes (`pl-*`, `mr-*`, `left-*`, `rounded-l-*`, `text-left`) set the other side then and follow the direction, and logical ones (`ps-*`, `start-*`, `rounded-s-*`) stay put.
- `p-[env(safe-area-inset-bottom)]` and `m-[calc(4px+env(keyboard-inset-height))]` set `PaddingEnv` and `MarginEnv` on their physical sides. `object-*` places an image or a video (`ObjectPosition`) and fits it (`ObjectFit`).
- `core.ParseBoxShadows`, `ParseGradients`, `ParseFilters` and `ParseObjectPosition` read CSS's values, a port of NSH's `css.rs`, which arbitrary classes and TSX's style objects share; `ParseColor` reads hex, `rgb()`, `hsl()`, `oklab()`, `oklch()`, `color-mix()` and names.
- `normal-nums`, `small-caps` and the figure classes (`tabular-nums`, ...) each turn their features on and those they exclude off in the node's `FontVariant`, as CSS's `font-variant-numeric` and `font-variant-caps` do.
- `line-clamp-*`, `truncate`, `text-ellipsis`, `pointer-events-*` and `object-*`'s fits set `NumberOfLines`, `TextOverflow`, `PointerEvents` and `ObjectFit`, so they take variants and the inline style wins over them.
- `aria-busy:`, `aria-checked:`, `aria-expanded:`, `aria-pressed:` and `aria-selected:`, `focus-within:`, and `data-<name>:` (Tailwind's boolean form, lower case letters, digits and dashes) are state variants like the others, with their `group-*` forms; `aria-current:` and `data-[state=open]:` are unknown, as in NSH.
- A color the palette lacks names a `Palette` role in kebab case (`bg-accent`, `text-text-muted/70`), or a color a theme named (`bg-muted-foreground`, a shadcn/ui token), or either as a variable (`bg-(--brand)`), read from the node's theme in the appearance it shows. `caret-*` is the selection's color, which the caret takes.
- `bg-transparent` is a color of alpha 0 that is not the zero `Color`, so it sets the field.

## Layout

- `Static` is Taffy's static position: an absolute view inside is placed in its nearest positioned ancestor, and `syncFrames` takes the static ancestors' offsets off its frame. `Fixed` hoists the view into its host (the root view or its modal) as an overlay without an anchor is, placed by its insets; it returns to its parent when it stops being fixed.
- `Sticky` lays out as relative with no insets; `pinRange` sends its nearest scroll view an `ItemStickyCells` range for `Top` (`Left` across), or `Bottom` (`Right`) when the start inset is auto. Travel stays within the parent's content box; end-pinned views stay after short content. Unlike NSH's start-only ranges, a range whose `End` is below `Start` has negative travel toward the content's start, shared by the native backends; the web uses native bottom/right stickiness in a track ending at the normal frame. Sticky views draw above siblings of the same `ZIndex`; `nativeChildren` orders children by both, stably.
- `MinContent`, `MaxContent` and `FitContent` are Taffy's sizing keywords. A flex item's cross size in one is measured before its flex basis, as browsers do, so a column's min-content box wraps its text before its height is taken. A text's min-content width is its widest word, measured alone (`breakWords`). `WhiteSpaceNoWrap` measures and lays text out unwrapped, wider than its box.
- A text reports no baseline, so `AlignBaseline` aligns its box's bottom. A grid takes a baseline-aligned item's baseline from its max-content layout, where Taffy takes it from its min-content one: a text wrapped at its narrowest would align its row by its last line.
- TSX's style keys are physical as CSS's are: `PhysicalEdges` holds `marginLeft`, `paddingRight`, `left` and their kind on their sides right to left, where Go's fields and the `start` and `end` keys, applied after them, follow the direction. Its `flex` is CSS's shorthand, `display: "flex"` a row unless a direction says otherwise (`RowByDefault`, under classes too), and `minWidth: "auto"` CSS's automatic minimum (`AutoMinimum`), an unset minimum being 0 as in Yoga.
- `LayoutDirection` sets the direction per subtree during resolve. Left and right of insets, margins, paddings, borders and corners swap right to left, as React Native's do, so they are its start and end: NSGo has no separate start and end fields. `PhysicalBorders` marks the sides of a border that keep their names right to left, as TSX's `borderLeftWidth` and its kin do in NSH 0.4.0, each winning its side (`mirrored`); `TextAlignLeft` and `TextAlignRight` do the same for text, by its direction. `TextStyle.RTL` gives text engines the base direction, which `TextAlignStart` follows; `WritingAuto` takes it from the first strong letter.
- `PaddingEnv` and `MarginEnv` are NSH's `env()` terms: `EnvSafeArea` adds the inset of the root view the node renders in on that edge (`Insets`: the surface's safe area, a modal's, a screen's below its header, or a `ui.TabShell` section's above a drawn tab bar, which `ProvideInsets` gives it; a screen starts from its place's insets, not the surface's), and `EnvKeyboard` the software keyboard's height. `bindStyle` reads the values a style's terms need inside its binding, tracked, so only nodes with terms follow them; `restyle` adds them over the merged padding and margin, a padding with a term staying at least 0. A keyboard move leads the commit with a `LayoutKeyboard` layout animation. Right to left, a term takes the inset of the edge it swaps to. `MarginPercent` and `PaddingPercent` mark the sides whose values are percentages of the containing block's width. A class that names a physical side (`ml-4`) resolves against the node's own direction, its ancestors' `LayoutDirection` over the app's. NSH lets any of its variables stand on any edge; NSGo's take their own edge's, which is what content keeps clear of, and replace `SafeAreaView` and `KeyboardAvoidingView`, which NSH 0.3.0 removed as well.

## Drawing

Each backend draws `ViewStyle` with its own primitives; `driver` holds what they share: `RoundedRect` and `EllipticRect` (circular, or continuous corners with Figma's 60% smoothing), `Corners.Fit`, `ColorMatrix` and `SplitFilters`, `Transform.Matrix` (whose `RotateZ` turns after `RotateX` and `RotateY`, as Tailwind's `rotate-z-*`, where `Rotate` is CSS's `rotate` before them) and `ChildPerspective`, `MixStyles` for transitions and `KeyframeAnimation.Cycle`.

- A rounded view with a fill and one solid border, either of them opaque, takes `ViewStyle.Rim`: the fill stops under the border, which draws what it shows over the fill, so an edge pixel a curve covers partly never takes the fill's color. Apple, Windows, Linux and Android draw it, and Apple fades the fill layer through a background transition and fits a backdrop blur the same way (`apple.FitBackdrop`); browsers avoid the bleed themselves. A see-through fill under a see-through border, a gradient, dashes and sides that differ keep CSS's layering, as a border must let what is under it show or a gradient has no color to mix.
- On macOS and iOS the tint above a blur, color-filtered backdrop or material (macOS's tint view, iOS's `UIVisualEffectView` content view or `CABackdropLayer` tint view layer) follows background transitions through `apple.BackdropTint` and `apple.StyleLayer`, retargeting from its presentation color with the transition's delay and easing. Animated backgrounds update it each frame and take over an active tint transition; frames changing other properties leave that transition running. On iOS the outer view's layer stays clear and excludes background transitions while a tinted backdrop is active so the backdrop is neither obscured nor double-tinted, handing the tint's displayed color back to the outer layer if the backdrop leaves during a background transition.
- On macOS and iOS, per-side border rings go in the backdrop's top layer (the glass's own, the tint over a `CABackdropLayer` or macOS material, UIKit's content view) as it is made and after each restyle (`apple.MoveBorders`), so they draw above the blur, material or glass and below the view's children, as CSS's borders do.
- `BlendPlusDarker` is a linear burn: Core Animation's `plusD` on iOS, `CILinearBurnBlendMode` on macOS, Direct2D's linear burn, and CSS's `plus-darker`; GTK and Android have none and blend normally, as GTK does `plus-lighter`. Android rotates a view in its plane once, so `RotateZ` joins `Rotate` there, exact unless the view tilts, and `Transform.Then` reaches it as one translation, rotation and scale (`Transform.InPlane`), without its shear or depth. Android's pivot has no depth, so `TransformOriginZ` moves nothing there; the other backends compose it into the matrix (`ViewStyle.Matrix`). Android's `Elevation` casts the system's shadow where the style casts none.
- On the web, Liquid Glass (`glass.go`) mounts a whole-app `<canvas content="drawable">` stage only while an eligible glass view exists and the browser exposes HTML-in-Canvas (`content="drawable"`, `requestPaint`, `drawElementImage`) and WebGL 2. `s.root.el` sits inside the stage as `drawable`, with each eligible glass view and any following overlay sibling above it kept as flat depth-1 `drawable` layers in DOM paint order; each layer composites its visible descendant `<canvas>` elements (icons, charts, pixel images, shaders) after `drawElementImage` so Chrome's HTML-in-Canvas canvas omissions never drop them and the stage never recurses into itself. Views under blend-mode, mask, translucent backdrop-filter or nested-glass ancestors (where Chrome hangs on nested `drawable` layers), views with non-upright transforms, and browsers without HTML-in-Canvas fall back to CSS `backdrop-filter` blur, tint and inset rim; removing the last eligible glass view tears the stage down and restores `s.root.el` directly under its host.
- A view's own outer shadows and outline stay outside its `Overflow` clip, as CSS keeps them: Windows and Linux draw them before pushing the clip and the outline after popping it, and the web's `overflow` never clips an element's own `box-shadow` or `outline`. Core Animation's `masksToBounds` and masks clip a layer's own shadow and sublayers with its children, so an Apple view that clips and draws them (`apple.NeedsClipHolder`) clips elsewhere and leaves its own layer unclipped: a view, text, canvas or shader moves its children and content layers, and an input, web, video or native view its hosted editor, web view, player or component, into a holder view clipped to its corners, a shape mask where they differ in radius (`apple.ClipHolder`), which an effect's container reuses; a scroll view clips its viewport holder, and an image clips its image layer, with a shape mask for differing radii. A macOS scroll mask follows the container's committed bounds and divides its radii by the content zoom to keep viewport corners in points. An iOS holder follows both the viewport's frame and bounds origin, so UIKit still scrolls, zooms and hit-tests the children in content coordinates. AppKit masks a view's layer as `clipsToBounds` answers whenever its frame changes, so such a view answers false and its holder true. A holder is hit as its view where no child is, so pointer events such as box-none read the view's own, and it takes the view's `ChildPerspective` whether it clips or not, an effect's container as well, which the view's sublayer transform would give only the flat holder: it keeps following the view's style and size once the shadow it clipped for goes away. The holder joins the same window before content moves into it, preserving an editor's first responder and selection; web and video holders change without reopening their page or player. Replaced editors and newly created native components join the current holder. An image's layer clips every corner and updates its shape mask after resizing; a tint mask stays on the picture inside it. Android draws `Box`'s outer shadows before clipping the view's body to its rounded path and its outline after restoring the ancestor's clip; its render node stays unclipped, since `setClipToOutline` would cut off its own decoration.
